# 現行製品仕様書（MVP）v1.0
作成：2026-11-12／**設計のみ・未実装**。本書を初期MVPの製品要求の基準とし、歴史的検討は [PROJECT_CONCEPT.md](../PROJECT_CONCEPT.md) に残す。相違があるときは本書と最新の決定記録を優先し、変更時は他仕様も更新する。

## 1. 目的と利用者
- 目的：空き家の建物条件と所有者の希望から**6つの活用候補の確認状況**を整理し、地域データがあれば根拠を示しながら**次に確かめること**を提案する。
- 主な利用者：空き家の活用を考え始めた所有者・管理者。架空物件でも試せる。
- 成功体験：何を入力するか分かる→候補ごとの違いと不足情報を理解する→次に何を確認するかを説明できる。
- 判定しない：実際に利用可能か、建物の安全性、法令適合、営業許認可、経済性、地区全体の需要人数、客観的な最適順位。

## 2. 対象用途
| ID | 用途 |
| --- | --- |
| housing | 住宅・移住 |
| community | 地域交流 |
| study | 学習支援・子どもの居場所 |
| meal | 子ども食堂・地域食堂 |
| work | コワーキング・創業 |
| shop | 小規模店舗・カフェ |

すべてに**同じ品質の基本3条件判定・理由・不明/不足の表示・次の確認質問・専門家確認**を用意する。用途固有の法令注意は異なる。

## 3. ユーザーフロー
Home → 建物情報（3ステップ）→ Results（6用途の確認状況）→ 用途詳細「地域との接点」／2用途比較／入力修正。
- 地区は任意で手動選択。博労・川原を実証候補、戸出を比較候補とする。
- 概略ピンは任意。地区境界GISが未確認ならピンから地区を自動確定しない。
- 建物は部屋数、基本設備（台所・トイレ・浴室・電気・通信）、その他任意条件。設備はpresent/absent/unknown、未入力はunknown。
- 所有者希望は方向（住まい→housing、地域→community/study/meal、事業→work/shop）または具体的用途を選べる。詳細な用途選択を明示的に確定した場合はそれを優先。未定も可。除外用途は常に主候補から外す。
- 用途ごとに希望A分類＋基本確認B分類を表示。**数値スコア・客観ランキングはない**。結果の順は希望グループ→用途ID固定順。
- 基本項目の確認状態は、必要十分条件でも法令上の判断でもない。

## 4. 中核機能 Must
| ID | 要求 | 受入基準 |
| --- | --- | --- |
| P01 | Homeの価値説明と限界 | 「活用候補の整理」であり実現可能性判定ではないと伝わる |
| P02 | 3段階フォーム・戻る | 不明入力でも進行、戻っても入力が失われない |
| P03 | 希望／未定／除外 | 希望と除外の衝突を説明、主候補に除外を入れない |
| P04 | 6用途の判定 | 全用途で正規化した設備3値を分類、理由を列挙 |
| P05 | 用途一覧と詳細 | 一致・不足・不明、専門家確認、確認質問を閲覧できる |
| P06 | 2用途比較 | 同じ情報項目で並べ、優劣の架空スコアを付けない |
| P07 | 地域情報の透明性 | 実／参考／未調査／架空、収録済み／未収録／エラーを区別 |
| P08 | 次の質問 | 地域データなしでも用途固有の標準質問。質問の理由を表示 |
| P09 | 安全なデータ扱い | 氏名・正確住所・自動GPSの収集なし。入力・選択ピン・診断結果をサーバーへ保存しない |
| P10 | 基本品質 | 型・決定規則・入力・スマホ・キーボード・エラー・比較の受入テスト |

## 5. 後から足すもの Should / Later
**Should（出典・権利・品質が確認できた場合のみ）**
- 匿名化した実アンケート集計による、根拠別「次に確かめる質問」の分岐。
- 公式施設データの公開範囲での500m/1km**直線距離**表示、地図・施設一覧。
- ユーザーと専門家へのレビューを経た文言改善。
**Later（今回作らない）**
- 実物件登録、ユーザーアカウント、所有者と利用希望者のマッチング、課金、法令適合や利益の自動計算、AI APIによる自由生成の用途推薦。

## 6. 技術・公開・プライバシー
- 想定：React + TypeScript + Vite + Tailwind、静的な公開可能JSON、ブラウザー内の純粋な判定処理。初期にDB、Supabase、バックエンド認証は不要。
- Vercel第一候補。ただしHobbyとチームのGitデプロイ制約を実アカウントで確認し、共同開発に合わなければCloudflare Pages。
- localStorage/IndexedDBへの自動永続保存はしない。ホストのアクセスログ、地図タイルの外部通信は存在しうるため公開前に事実を確認する。
- 公開施設のライセンス・出典・更新日を明示。住民アンケートの個票・識別可能な少人数集計を公開しない。
- 実調査未実施なら「未調査」。架空デモは一目で「架空データ」と分かる。

## 7. 作品の価値と説明
> **「空き家の特徴と地域の声をつなぎ、活用の可能性と次の確認事項を見つける。」**
ただし地域の実データがなければ、地域の実情を反映済みとは主張しない。現MVPは候補整理と根拠別の確認質問であり、地域ニーズを使った順位変更は実装しない。

## 8. 外部依存と着手の条件
- 未検証：6用途の3基本項目の実務的な妥当性、地区境界GIS、公共施設CSVの全件分析、住民/所有者/専門家の評価、Vercel実チームでの動作。
- 未決定：最終チーム人数・担当と作業可能時間、調査責任者・承認・保存期間・協力先。
- **アプリの実装・デプロイ・アンケート配布・外部連絡は未実施。明示の着手指示があるまで行わない。**
