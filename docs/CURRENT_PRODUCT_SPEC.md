# 現行製品仕様書 v2.0：地域で始めたい活動の場所と準備を整理する
更新：2026-11-12／**設計のみ・未実装**。v1はGit履歴とPROJECT_CONCEPT.mdの第1〜52章に保存。**本書が現行MVPの製品要求です。**

## 1. 中心価値と利用者
**利用者**：富山県、とくに高岡市周辺で、やりたい活動の内容は決まっているが、適切な場所や準備の進め方が分からない個人・学生団体・地域団体・小さな事業チーム。**空き家所有者は初期の主ユーザーではない**。

**ユーザーが得ること**：「活動に必要な場所・運営条件が整理でき、既存施設・空き家・その他会場を比較し、次に取る具体的な行動を一つ以上選べる」。

**未検証の課題仮説**：場所の選び方や調達の手順が活動開始を妨げている。場所より資金・人員が主な障壁なら、この価値仮説は見直す。

## 2. 今回扱う活動
| activityId | 活動例 | 具体的な確認が必要なこと |
| --- | --- | --- |
| community | 地域交流・イベント | 人数、時間帯、運営主体 |
| study | 学習支援・子どもの居場所 | 参加対象、見守り・責任者、時間帯 |
| meal | 子ども食堂・食事交流 | 調理/配食、衛生、運営主体 |
| work | 仕事・創業・作業スペース | 通信、稼働時間、運営・費用 |
| shop | 販売・店舗・カフェ・マルシェ | 販売方法、飲食の有無、許認可・費用 |
| other | その他の地域活動 | 必要な人数・設備等を基本質問で整理 |

**旧6用途の「住宅・移住」は、活動を始めたい人向けのMVPでは対象外。** 活動以外の住宅用途や所有者向け診断は将来別フローとして再検討する。カテゴリは用途の推奨順位ではない。

## 3. 基本体験
Home「どんな活動を始めたい？」→活動内容の入力（2〜3ステップ）→活動条件の要約→**場所の選択肢3種類を検討**→次に確かめることと行動の提示→確認事項の見直し。

**場所タイプ**：
- existing_public：地域交流センター・公民館等の既存の公共/地域施設。
- vacant_house：所有者の同意、建物・費用・法令等の検討が必要な空き家の転用。
- other_venue：民間貸会場、既存団体の拠点などその他の会場。

場所タイプの比較は**タイプ別の検討材料**であり、個別の物件の空き状況・利用可能性を調べたものではない。具体的な場所の検索・予約・所有者紹介はしない。

## 4. 入力項目
- 必須：活動カテゴリ1つ（otherを含む）。どんな活動かの短文は任意。
- 追加：希望地区（任意、手動）、参加人数（不明可）、単発/定期/未定、希望時間帯（複数可/不明）、必要設備（調理、電気、通信、机・椅子等の任意選択）、運営主体の有無（いる／まだ探している／不明）、費用感（任意・不明）。
- 入力の不足を「不適合」と変換しない。個人名・実在の所有者・正確な住所・GPSを要求しない。
- 事業、飲食、子どもが参加する活動では、状況に応じて専門家・運営上の留意事項を**別表示**。

## 5. 必須機能（Must）
| ID | 機能 | 完成条件 |
| --- | --- | --- |
| P01 | 活動から始めるホーム | 利用目的・非保証を説明できる |
| P02 | 活動の条件入力 | 活動種類が選べ、ほかの条件が不明でも進める |
| P03 | 活動条件の要約 | 参加者・時間・設備・運営状況の未確認点が分かる |
| P04 | 3場所タイプの比較 | 既存施設・空き家・その他を並列に扱い、架空スコアや推奨順位を付けない |
| P05 | 次の具体的な行動 | 各場所タイプで確認事項、最初の行動、確認方法、根拠、注意が見られる |
| P06 | 既存施設を検討する入口 | 空き家の利用を強制せず、既存施設の利用条件も調べられる |
| P07 | 未調査・根拠の状態区分 | 公式出典/参考/未調査/デモを混同しない |
| P08 | 安全・プライバシー | 利用許可・法令適合・収益・所有者の協力を断定せず、入力をサーバー保存しない |
| P09 | 基本品質 | キーボード、スマホ、空欄・異常系、比較・戻るの受入条件 |

## 6. Should / Later
**Should（出典・内容の検証後）**：高岡市の公共施設の実在情報・利用案内への公式リンク、地域の利用障壁の匿名集計と「次の確認事項」への反映、地図（公開データの座標・ライセンスが確認できた場合）。
**Later**：実際の空き家物件データ、空き家所有者・学生団体のマッチング、予約・問い合わせ、アカウント・案件保存、資金や法令適合の自動評価、所有者向け6用途診断。

## 7. 絶対に断定しないこと
- 「この空き家が借りられる」「この施設が空いている」「飲食営業できる」「子どもを安全に預かれる」「この場所が最適」「実際に地域の需要がある」。
- 調査前の地域課題、施設の利用条件、団体の活動意思・協力を既成事実としない。
- 公開施設の存在を、予約可能性や利用者の受入れに直結させない。

## 8. 技術方針（設計）
React + TypeScript + Vite + Tailwind、バージョン付きの定型ルールと公開可能な静的データ、ブラウザー内で行動案を決める。ログイン・DB・外部AI APIは初期MVPで必須ではない。Vercel/Cloudflareの共同開発運用は実アカウントで要検証。GPSの自動取得・個人情報の公開保存はしない。外部地図通信などは採用時に確認。

## 9. 未解決の事業性・需要の検証
活動希望者が、既存検索・公共施設情報・自治体窓口や汎用AIでは解決できない問題を抱えているか、実際の過去行動を聞いて確認する。施設CSV本体の監査と運営者への聞き取りは未実施。**設計が整っていることは需要を証明しない。**
