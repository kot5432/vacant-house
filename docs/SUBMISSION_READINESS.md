# 作品部門・応募前チェックリスト（設計上の準備）
更新：2026-11-12。これは既存設計と過去に確認した募集条件の整理であり、**応募直前に必ず公式の最新要項を確認する**。提出・動画・実装は未実施。

## 企画を一言で
**空き家の建物条件と所有者の希望から6種類の活用候補を整理し、地域の声や既存施設の根拠を示して、次に確認することを提案するWebアプリ。**

## 伝えるべき3つの独自の工夫
1. **希望・設備・地域情報の分離**：希望しているから適法、施設が少ないから需要大、とは決めつけない。
2. **説明可能な質問分岐**：実調査の内容によって「既存施設の利用時間」「運営主体の確保」「利用頻度」などの確認事項が変わる。
3. **足りない情報も可視化**：不明設備、未調査の地区、施設の未収録を隠さず提示する。

## 審査に誤解させない説明
- 「推薦スコア」「もっとも適した用途」「市全体の需要量」「安全・営業許可・収益」は算出していない。
- 実調査が未実施なら**地域ニーズ未調査**。デモは**架空データ**と表示し、利用者・協力団体の実績を作らない。
- AIを使用した場合、**どの作業に使い人がどこを設計・検証したか**を説明する。
- 競合作品との違いは仮説であり、ユーザー試験がない限り優位性を断定しない。

## 動画案（10分以内、現行案は9分30秒目標）
1. 課題（0:00〜1:00）：空き家の活用を考え始める人が、用途ごとの確認事項を整理しにくい。
2. 提案（1:00〜2:00）：建物・希望・地域根拠から活用候補と次の質問を提示。
3. デモ（2:00〜5:00）：架空の交流スペースの建物条件を入力、6用途の確認状況、比較、詳細。
4. 差分デモ（5:00〜6:30）：同じ建物のまま、地域ニーズの証拠を「利用時間の障壁」「担い手不足」「未調査」で切り替え、**確認質問だけが変わる**ことを説明。
5. 技術（6:30〜7:40）：ルールが説明可能・同じ入力は同じ結果、データの版・出典・未確認を管理。
6. 現実の検証（7:40〜8:40）：実施した調査のみ紹介。未実施なら「今後の検証課題」と表記。
7. 限界と展望（8:40〜9:30）：許認可・収益判断はしない、所有者と活動者の連携は将来案、AI使用範囲を明記。
※実装・確認できた画面だけを撮影して説明する。未完成機能を実装済みのように見せない。
