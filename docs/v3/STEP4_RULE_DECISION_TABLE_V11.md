> **状態：設計提案・実装前。** [RULE_ENGINE_CONTRACT_V1.md](RULE_ENGINE_CONTRACT_V1.md) を補完し、曖昧な条件をテスト化する。既存の4領域とP01-P12、基本6問、保存方式B、U02下書き非保存Aは確定前提。**P05の一般安全P2・子ども参加P1、同順位ID順、物理会場なしのP08一般確認P2はADR-003で正式採用**。その他の優先細則は設計案。**物理会場なしの限定支援B案はADR-002で正式採用**。旧空き家関連の診断/物件データは使用しない。

## 1. ルール評価の順序（提案）

1. `EventInput` のランタイム検証。入力形式のエラーと本人による「未定」を区別する。
2. 施設固有の適用スコープ判定（地域・会場候補/確定・本人選択施設カテゴリ・出典版）。
3. `applicability`（該当／非該当／要情報）判定。本人の「対象外」をこの段階で使わない。
4. P1/P2/P3候補の判定（**優先度は作業順の提案であって法定期限ではない**）。
5. 本人の進捗・完了履歴・新条件による再確認と合成し、未解決候補を計算する。
6. 優先する1件と他のP1全件、4領域の全体像を生成する。

## 2. 判定表の具体案

| タスク | 基本優先 | 昇格を検討する条件 | 検証する否定例 |
|---|---|---|---|

| P02 参加対象・人数 | P3 | audience=undecided→P2。人数未回答は「未確認」の説明にとどめ、即P2と決めつけない | 未回答人数を0扱いしない |

## 3. 未確認・未定・対象外・再確認の区別

| 状態 | 意味 | ランキング |
|---|---|---|
| `applicable=no` | 入力条件からその準備が今回不要と判断された | 候補外。過去の進捗は保持 |
| `applicable=needs_information` | 情報不足で適用要否を判断できない | 確認事項として表示。自動不要としない |
| `progress=not_started` | 本人が未着手を選んだ | 対象なら未解決 |
| `progress=in_progress` | 取りかかっている | 対象なら未解決 |
| `progress=completed, needsRecheck=false` | 本人が完了を表明 | 通常の未解決候補から外す |
| `progress=completed, needsRecheck=true` | 前提変更で再確認要 | **未解決候補に含める** |
| `progress=not_applicable` | 本人が不要と判断 | 通常の未解決候補から外すが重要な公式条件の案内は非表示にしない |
| `progress=not_applicable, needsRecheck=true` | 不要の判断の前提変更 | 再確認の未解決候補に含める |

## 4. 再確認の付与条件（推奨）

- 「関連フィールドが変わった」だけでは付けない。**以前の作業で確認した前提が変わり、その判断の有効性が失われ得る場合**に付与する。
- audience: P05見守り、P02定員、P11連絡。成人のみ→未成年を含むに変化したら既存の完了判断を再確認候補。
- venueStatus / venueCategory: P07選定、P08施設条件、P09設備。単に同一施設のメモ文言を修正した場合は不要。
- region: P08の施設固有情報の適用解除。以前の公式根拠は現在の案内から消す。
- schedule: P03開催条件、P06進行、P12開催前確認。実際の期限がわからない限り日数閾値を置かない。
- equipment: P09利用環境。無関係のP01完了を解除しない。
- 再確認解除は本人が明示して新しい条件を確認したときのみ。「詳細画面を開いた」だけでは解除しない。
- データ保存は条件と進捗とrecheckReasonCodesを同一イベントの整合単位で保存する。

## 5. 同順位の整理

**ADR-003で正式採用：P1→P2→P3、同じ優先区分内はタスクIDの数値昇順（P01→P12）。** 旧「P08→P05→P07…」という特別順は不採用。

- いずれもP1候補なら代表は1件でも、**ほかのP1も同じ優先領域に見せる**。
- 期限に基づく並べ替えは、信頼できる出典に明示期限があるときのみ検討。一般のイベント開催日から勝手に計算しない。
- **同優先区分の固定ID順は正式採用済み。** 表示順と本人にとっての最適性は別であり、使いやすさは今後利用者検証する。

## 6. 物理会場なし・オンライン（B案正式採用）

**2026-11-15正式採用：** [ADR-002](ADR_002_NO_PHYSICAL_VENUE_SCOPE.md)のB案。`no_physical_venue`はオンライン開催と断定しない。P07（建物会場探し）、P08（建物の予約／館内施設の申請）、P09（館内設備）の**施設専用の子項目**のみ非該当にする。親タスクP07〜P09は`applicable=needs_information`として開催形式・場所の利用条件・必要な環境の一般確認を残す。**屋外・公園・道路等の条件やオンライン固有手続きを自動判定しない**。該当施設の旧公式根拠は現在のプランから除去し、完了歴と要再確認を分離する。基本6問は増やさない。
