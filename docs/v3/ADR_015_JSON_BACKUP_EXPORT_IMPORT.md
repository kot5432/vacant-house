# ADR-015｜MVPにJSONバックアップのエクスポート・インポート両方を追加（A案正式採用）

決定：2026-11-15。ユーザーがA案を明示採用。現行の初めて単発・小規模地域イベントを主催する人向け準備支援Webアプリのみ対象。旧空き家・所有者・物件・マッチングは移行・復元対象にしない。**設計のみ、実装・試験・デプロイ未実施**。

## 1. 正式に採用するMVP範囲
- 本人が同一ブラウザのIndexedDBに保存した**イベント入力と本人の進捗・再確認情報を、ローカルJSONファイルとしてエクスポート**できる。
- 本人が以前書き出した**対応形式のJSONをインポートし、イベントと進捗を復元**できる。
- アカウント、サーバーDB、端末間の自動同期、共有・クラウドバックアップ、PDF/印刷、参加者名簿の収集は追加しない。ファイルの転送・保管は本人が行う。
- 共通P01〜P12タスク定義、公式出典カタログ、生成済み優先度などの**再計算可能な配信データは書き出さない**。復元時はそのアプリ版のルール・公式出典で再評価し、本人の既存進捗を勝手に「確認済み」と再認定しない。
- **ローカル書き出しはデータ消失のリスクを減らすための選択肢であり、ダウンロード先での保管・復元成功は保証しない**。機微な情報を本人が任意欄に記載した可能性があるため、ファイルは私的に保管するよう説明する。

## 2. データ形式の安全な契約（方向性を採用、細部は未承認）
- ルートには`formatId`（現行プロダクト専用）・`exportSchemaVersion`・`exportedAt`・`sourceBuildId`・`eventCount`・`events`を保持する案。イベントには`eventSchemaVersion`、`eventId`、`revision`、入力、`progressByTask`、必要な保存メタデータを含める。
- **書出し対象は保存成功済みのイベントだけ**。未完成U02入力、未保存U04ドラフト、保存中・保存失敗のU03変更を「バックアップ済み」と誤って含めない。
- エクスポートは一貫した保存済みスナップショットを読み、書き出し失敗・途中キャンセルで成功と表示しない。OSがファイルを保存した場所までアプリが保証したと誤表示しない。
- インポートは**ローカルでのみ解析**。ファイルサイズ・UTF-8／JSON形式・ルート識別子・既知の版・イベントID・重複ID・必須6問・人数・メモ字数・タスクID・進捗enum・現在の対応スキーマを検証する。未知の旧空き家JSON、未知schema、破損・異常に大きいファイルを勝手に取り込まない。
- **プレビュー・件数・衝突件数・データの取り扱いを示し、本人の明示確定前にDBへ書き込まない**。既存のイベントを黙って上書き・削除せず、失敗時に既存データを保護。複数タブ競合／容量不足／途中失敗時にも「復元成功」と表示しない。
- **衝突時の扱い・一括追加の原子性・ID再採番方法・インポートできる旧版の範囲は、後続の正式判断が必要**。これらは本ADRで決定済みと偽らない。
- U03の`needsRecheck`・`progress.status`と出典の`needs_review`は別。復元時はADR-004/005/009〜014を守る。
- ブラウザ内保存とファイル移動は異なるオリジン間の自動同期ではない。バックアップ機能を追加してもU02の未完成下書き保存ルールは変更しない。

## 3. 画面案
- **U01（ホーム）**：保存イベント一覧の近くに補助導線「バックアップを書き出す」「バックアップから復元」。基本CTA「新しいイベントを作る」を最優先に維持。画面を新たに増やすかは未決、まずダイアログ／段階的な補助UIで検討。
- **書き出し**：対象と件数、書き出し内容、ファイル保管上の注意を表示。保存成功済みのスナップショットを対象にする。U02/U04の未保存入力の扱いを明記。
- **復元**：本人がファイルを指定→ローカル検証→内容の件数／重複／対応可否を確認→確定→保存成功後に結果を表示。途中で閉じる、失敗、競合では旧データを保護。

## 5. 決定の優先関係
以前の[STEP4-⑫ MVP v0.1](STEP4_12_MVP_REQUIREMENTS_V01.md)にある「ファイルエクスポート／インポートはMVP外」は**本ADR-015によって明示的に変更**。新たなMVP追加であり、保存の既存責務（U02未完成は非永続、U03進捗は自動保存、U04は確定保存）を覆さない。

**次の重要判断**：インポート時に既存イベントと同じ`eventId`が見つかった場合の扱い。[STEP7-⑩](STEP7_10_BACKUP_IMPORT_CONFLICT_OPTIONS.md)の比較から選択する。
## 後続決定：衝突時A案の正式採用（ADR-016）

本ADRが保留していた**既存イベントとのeventId衝突は、バックアップ側を新しい一意IDでコピー追加し、既存イベントを不変とする**A案に確定。ファイル内部のeventId重複はインポート全体を拒否。本人にコピー件数をプレビューし、確認後の同一トランザクションで全件追加・全件失敗を保証する設計。衝突分類がプレビュー後に変わった場合は再確認する。詳細は[ADR-016](ADR_016_IMPORT_COLLISION_AS_COPY.md)。従前の「衝突処理は未決」という記載は本決定より前の履歴。
