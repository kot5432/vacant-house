# 現行イベント準備支援Webアプリ｜要件定義 v1 草案（2026-11-15）

**状態：草案（未承認・未実装・未試験）。** 現行製品は「初めて単発・小規模の非営利地域イベントを企画する人」が、準備の全体像と状況別の優先順位・その理由・次の行動を理解するためのWebアプリ。富山県を想定し、施設固有の公式情報は高岡市の確認済み資料から段階的に扱う。空き家所有者／物件登録／マッチング／営利開業や、旧障壁質問型の仕様を引き継がない。

## 1. 利用対象と価値

- **主な利用者**：初めて単発〜小規模の体験会・講座・交流会等を主催する個人や小規模チーム。
- **中心課題**：何を、どんな順で準備するか全体像と優先順位が分からない。
- **入力**：基本6問（イベント種類、参加対象、希望時期、会場の決定状況、開催地域、主催者形態）→暫定プラン。施設カテゴリ等は条件付き、人数・責任者・設備・自由説明等は任意の詳細入力。
- **出力**：今優先する確認と理由→具体的な一歩→4領域・P01〜P12の準備全体像→該当する公式根拠。P1/P2/P3は順序の提案であり危険・法令判定ではない。
- **採用済み保存範囲**：生成後進捗変更、ブラウザ内保存、同一ブラウザで後日再開、複数イベント管理・個別削除。ログイン・サーバー同期はなし。
- **今回対象外**：参加者の氏名等の管理、実際の予約・申請、会場の空き判定、営利開業、旧空き家案、AIチャットでの自動認定、共同編集、印刷/PDFとデータファイルの出力・読み込み。

## 2. 機能要件と受け入れ条件

| ID | 要件 | 合格条件 |
|---|---|---|
| FR-01 | 基本6問の入力 | すべての設問に有効な回答をすると暫定プランへ進める。「未定」は有効な選択肢で未回答と区別 |
| FR-02 | 条件付き入力 | 高岡市＋候補/確定＋本人が地域交流センターを選択した場合だけ施設固有の利用者構成を質問。他条件へ転用しない |
| FR-03 | 任意の詳細化 | 人数、責任者、設備、自由説明の入力がなくても暫定プランを表示、入力後は再計算 |
| FR-04 | プラン生成 | 同一の入力・進捗・ルール版で同一結果。タスク未該当と利用者の手動対象外を区別 |
| FR-05 | 優先事項と理由 | 代表1件と他の重要確認、具体的な次の行動、未確認事項を提示。残りの準備を隠さない |
| FR-06 | 準備の全体像 | 4領域・P01〜P12を定義IDと対応させて表示。完了・該当外も確認可能 |
| FR-07 | 進捗編集 | 未着手／進行中／完了／対象外を変更し再計算。任意チェックだけで親タスク自動完了しない |
| FR-08 | 再確認 | 条件変更で影響する完了済みタスクのみ再確認を示し、過去の完了履歴を消さない |
| FR-09 | U04編集 | 未保存ドラフトを確定データから分離し、反映時のみ確定保存。キャンセルで編集差分を破棄 |
| FR-10 | 自動保存 | U03進捗変更後にブラウザ保存。完了応答を受けるまで「保存済み」と表示しない |
| FR-11 | 複数イベント | eventIdで独立させ、Aを変更してもBには影響しない。同一ブラウザで後日再開 |
| FR-12 | 個別削除 | 対象イベントだけ確認後削除。失敗なら一覧から消えたふりをしない |
| FR-13 | 競合・破損・移行 | 旧revision／未対応スキーマ／破損データを無言で上書き・初期化しない |
| FR-14 | 公式情報 | 施設選択・条件が一致した場合のみ、出典・対象・確認日と限界を示す。未確認の締切を創作しない |
| FR-15 | 共通UX | ホーム／基本入力／準備プラン／情報編集の4画面。保存・エラー・未定状態は言葉で表す |

## 3. 非機能要件（目標・測定前）

| ID | 項目 | 初期基準と試験 |
|---|---|---|
| NFR-01 | 応答性 | 同一端末の通常操作で再計算1秒以内を目標。測定端末・ブラウザ・データ件数を技術選定時に固定 |
| NFR-02 | 保存整合性 | イベントと進捗の更新を整合的に保存、競合を検出。クラッシュ／容量不足で破損や偽の保存成功を起こさない |
| NFR-03 | プライバシー | 氏名・住所・GPS・参加者連絡先を入力項目にしない。任意メモには個人情報を入れないよう案内。外部送信・第三者スクリプトは公開前に監査 |
| NFR-04 | 操作性 | 320px相当の幅、文字200%拡大、キーボードだけで基本フロー・進捗・削除が完結する |
| NFR-05 | 決定性 | テスト固定日時と同入力・進捗・ルール版で同じ優先結果。現在日時の参照は明示的な入力として扱う |
| NFR-06 | 出典正確性 | 公式情報のURL、対象、確認日、版、適用条件を管理。古い情報は再確認または案内から除外する運用を定義 |
| NFR-07 | ブラウザ保存の限界 | プライベートモード・容量不足・サイトデータ削除・別端末での復元不可を利用者に説明 |
| NFR-08 | 保守性 | 入力バリデーション、判定、文言、保存、UIを分離。テスト可能な純関数中心 |
| NFR-09 | 互換性 | 対応ブラウザとバージョン、更新・復元・削除の試験環境を選定書に記載 |

## 4. 保存・データの境界

- **保存する**：eventId、イベント条件、進捗と任意チェック、再確認理由、schemaVersion、rulesVersion、revision、作成・更新日時。
- **保存しない（原則）**：生成済みランキングや適用済みの公式案内全文。再開時は現行ルールと出典台帳から再計算。
- **注意**：保存データのルール版から最新ルール版への再計算時に、旧来の完了判断が無効かは必要に応じ再確認する。移行成功とルール妥当性の確認を区別。
- **削除対象**：選択したeventIdの保存データと進捗。共通タスク定義や他イベントは残す。
- **正式採用（2026-11-15）**：U02初回途中の下書きはA案＝永続保存なし。基本6問の画面内入力を保持し、初回プラン生成時のIndexedDB保存成功後だけU03へ遷移。失敗時はU02で入力を保持し再試行。**未決**：進捗率の分母、イベント名任意編集、詳細なデータモデル、各エラーの最終文言。

## 5. 受け入れテスト計画の入口

- 入力：6問・未定／未回答／人数の整数／時期の妥当性／条件付き施設選択。
- 判定：代表優先、複数P1、同順位の安定性、会場確定・変更、子どもの安全、施設固有根拠の適用外除去。
- 保存：二つのイベント隔離、更新と再読込、失敗の視認、競合、削除、未対応スキーマ、ロールバック。
- UI：320px、200%拡大、キーボード、エラー・保存状態・再確認。
- **テスト未実施**。期待結果の詳細は [U03](STEP5_03_PREPARATION_PLAN_UI.md)、[U04](STEP5_04_EDIT_SAVE_ERROR_UI.md) と後続テスト設計を参照。

## 8. 物理会場なしの対応範囲（2026-11-15正式採用）

[ADR-002](ADR_002_NO_PHYSICAL_VENUE_SCOPE.md)によりB案を採用。基本6問を増やさず、`no_physical_venue`はオンラインと断定しない。P07〜P09の**建物専用の確認項目のみ非該当**、親タスクは開催形式／場所の利用条件／必要環境の要確認として残す。屋外の手続き・オンライン固有の条件を自動判定しない。正式なテーブルテストは[判定レビューv1.2](STEP4_RULE_REVIEW_V12.md)に整理。優先の細則は別途決定する。

## 9. 明示的な再確認解除（ADR-004正式採用）

機能要件FR-08を補足：条件変更後の`needsRecheck=true`は、**本人がU03の「再確認を終えた」を明示操作**し、eventId/revision照合付き保存に成功したときだけ解除する。以前の進捗`completed`や本人の`not_applicable`は維持。詳細閲覧や子チェック、U04での再編集だけでは解除しない。保存失敗時は再試行可能で、解除済みと表示しない。出典の適用外・施設許可と本人の完了申告は別。[ADR-004](ADR_004_EXPLICIT_RECHECK_CLEAR.md)。
