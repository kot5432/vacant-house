# ADR-022｜JSONバックアップの互換性は現在形式＋検証済みの既知旧形式（A案正式採用）

決定日：2026-11-15。利用者は[STEP7-⑱](STEP7_18_BACKUP_VERSION_COMPATIBILITY_OPTIONS.md)の**A案を明示採用**。現行の「初めて単発・小規模の地域イベントを主催する人の準備支援Webアプリ」専用。**旧空き家所有者・物件・マッチングアプリのデータは対象外**。設計のみで、コード実装、ブラウザ試験、デプロイは未実施。

## 1. 正式決定

- インポートで受け入れるのは、**現在の対応済みバックアップ形式、および各形式の検証・安全な移行手順・受入テストが完了した既知の旧形式だけ**。移行手順未定義／未検証の旧形式、未知の将来形式、別アプリ用のJSONは**拒否**する。
- **「旧形式も対応する」という方針と、「どの旧版が検証済みか」は別**。最初のバックアップ形式はまだ実装・公開されていないため、実在しない旧`exportSchemaVersion`を対応済みとは宣言しない。対応形式のバージョン一覧は初回公開時および後続のリリースごとに記録する。
- `formatId`は現行プロダクト専用の識別子を固定する。単に`events`配列が存在するJSONや旧空き家版JSONを、自動判別で読み込まない。
- **バックアップ全体の`exportSchemaVersion`と、各イベントの`eventSchemaVersion`を別々に検証**する。アプリ`buildId`、`rulesVersion`、公式出典の`catalogVersion/sourceRevision`も混同しない。
- 旧版の移行は**元の形式の検証→明示的な対応版向け移行→現行形式で全件再検証**。意味の分からないプロパティ、未知タスクID、進捗状態、条件付き入力は、黙って切り捨てたり「完了」へ変えたりしない。損失なしに移行できない場合は復元拒否。
- ファイル全体の上限は[ADR-019](ADR_019_JSON_BACKUP_LIMIT_2MIB_100_EVENTS.md)どおり**2 MiB（2,097,152バイト）・100イベントの両方**。版にかかわらず適用。移行後のデータにもメモリと実保存容量の検証が必要。
- 本人が**プレビューで復元件数・別IDコピー件数を確認して確定した場合だけ**、既存DBを変更せず新イベントを一括追加する。ID衝突は[ADR-016](ADR_016_IMPORT_COLLISION_AS_COPY.md)で別コピー、繰返し復元は[ADR-017](ADR_017_REPEAT_IMPORT_WITH_CONFIRMATION.md)で毎回確認。新レコードのrevision=1・復元日時・元の由来情報は[ADR-018](ADR_018_RESTORED_EVENT_REVISION_AND_PROVENANCE.md)に従う。進捗は保持し、ルールと公式出典は**復元先アプリの現行版**で再評価する。

## 2. バックアップJSONの論理契約

```text
BackupEnvelope
  formatId: 現行イベント準備支援アプリ固有の固定識別子
  exportSchemaVersion: バックアップファイル自体の形式バージョン
  exportedAt: 書出し日時
  sourceBuildId: 書出し時のアプリ版識別子（互換性判断の代わりにはしない）
  eventCount: events.lengthに一致する整数
  events: EventRecordの保存済み情報の配列
    eventSchemaVersion: 当該イベントレコードの保存形式
    eventId / input / progressByTask / revision / timestamps / provenance
```

**これは説明用の論理構造であり、実行できるコードではない**。正式な`formatId`文字列、初期`exportSchemaVersion`、対応イベント版、ルート型・日時型・JSON Schema/TSの配置は実装前の別仕様で確定する。過去の行政情報・ルールの導出結果はバックアップに入れない。

## 3. U01のエラーとプレビュー

| 状況 | 表示案 | データ保護 |
|---|---|---|
| 現行の対応形式 | 「内容を確認してください」＋追加件数・コピー件数 | 本人確定まではDB無変更 |
| 移行可能な検証済み旧形式 | 「以前の形式です。現在の形式として確認後に復元します」 | 移行後全件再検証し、無断欠損なし |
| 未対応の古い形式 | 「このバックアップ形式は現在対応していません。元のファイルは削除せず保管してください」 | DB無変更 |
| 未知の新しい形式 | 「このファイルはこのバージョンのアプリでは読み込めません。アプリの更新を確認してください」 | DB無変更、強制再読込なし |
| 別アプリ／旧空き家のJSON | 「このアプリのバックアップ形式ではありません」 | DB無変更 |
| 形式は対応するが内容破損・未知状態あり | 「一部のデータを安全に読み取れないため、復元できません」＋必要な範囲で理由 | 無断修復・部分取込みなし |

過剰な個人情報をエラーに引用しない。更新案内は[ADR-013](ADR_013_MANUAL_REFRESH_ON_AUTO_VERSION_DETECTION.md)の**本人操作による再読み込み**と矛盾させない。

## 5. 未決・公開前チェック

- 初回リリースで採用する**固定`formatId`文字列と初期版番号**、受入可能版の一覧の管理場所、検証・移行仕様の具体的なテストデータは未決。
- まだ**実在する旧バックアップ版がない**ため、現時点で旧版移行に合格したとは宣言しない。
- JSONを長く安全に扱うための異常な日時、巨大なUnicode書記素／ネスト、ブラウザのメモリ負荷、同一イベントが2 MiBを超えた場合の説明は後続技術レビューで検討。
- 次の利用者確認事項は[STEP7-⑲ 異常な日時の扱い](STEP7_19_IMPORTED_TIMESTAMP_VALIDATION_OPTIONS.md)。
