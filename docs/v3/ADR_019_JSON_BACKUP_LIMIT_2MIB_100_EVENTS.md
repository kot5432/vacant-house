# ADR-019｜JSONバックアップは最大2 MiB・100イベント（A案正式採用）

決定日：2026-11-15。利用者がA案を明示採用。**現行の単発・小規模地域イベント準備支援Webアプリ専用**。旧空き家・物件・所有者・マッチングのデータは対象外。**実装・ブラウザ試験・デプロイなし**。

## 正式決定

- JSONバックアップ**1ファイルにつき最大2 MiB（2,097,152バイト）かつ最大100イベント**。両条件を満たす場合のみ有効。上限**ちょうどは許容**、1バイトまたは1イベントでも超えれば不可。
- **インポート**：ファイル選択後にバイト長を事前確認し、パース・形式・eventCount・全イベント・ID一意性・既存ID衝突を検証。100件超または2 MiB超はDB書込み前に拒否し、元データは不変。
- **エクスポートにも同じ上限を適用**。保存済みレコードを整合したスナップショットとして抽出し、**最終的に生成されるUTF-8 JSONの実バイト数とevents.lengthを検証してから**バックアップを作成する。UIの予測サイズや文字数だけで上限内とみなさない。
- **上限超過時、データを無断で削減・切り詰め・一部だけ書き出して「すべて保存した」と表示しない**。対象件数・実バイト数・上限・エラー理由を示す。上限超過時の**分割エクスポートUIは追加設計・利用者判断待ち**。分割導線が決まるまでは上限超過時の一括書出しを停止し、正式なバックアップが作成できたと表示しない。
- 0件は形式上許容可能だが、0件であることを明示し、復元時に既存イベントを消さない。
- 各フィールドの100/500字制限（ADR-008）と**ファイル全体のUTF-8バイト上限は別**。Unicode書記素の巨大な結合列などに対するフィールドごとの技術サイズ上限は別の設計課題。
- 過去の出典カタログや導出優先度はバックアップに入れず、復元後に最新版から評価。ADR-015〜018のコピー追加、revision=1、由来日時保存、毎回の復元確認、原子的全件追加を維持。

## サイズ計算と一貫性

「2 MiB」はファイルのバイト長、**書出し時は完成したUTF-8エンコード済みJSON全体のバイト長**。ルートメタデータ、引用符・エスケープ、`importedFrom`等を含めて算定する。インポートは実ファイルサイズを判定し、さらに内部`eventCount === events.length`と100件上限をチェック。100件に収まっても2 MiB超なら不可、その逆も不可。

書出し途中で他タブ更新があっても、保存済みレコードの**一貫した読取時点**に基づく。書き出し後に元DBが変更されてもバックアップ内容はその取得時点の保存済みスナップショットであることを説明する。ダウンロード操作の開始を、OSへの確実な保存完了と混同しない。

## U01表示案

- 一括書出しが可能：「保存済みXX件のバックアップを作成します。ファイル上限は100件・2 MiBです。」
- 上限超過：「バックアップの上限（100件・2 MiB）を超えています。データは変更されていません。分割方法については今後の設計で決めます。」
- 復元の容量超過：「選択したファイルは2 MiBを超えています。取り込めません。現在保存されているイベントは変更されません。」
- 件数超過：「このファイルには101件以上のイベントが含まれています。上限は100件です。」
- 書き出しを成功と表示する時も「ファイル生成・保存処理を開始」と「端末に確実に保管」を区別する。
