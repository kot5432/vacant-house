# 製品要求仕様 v3.0 — 地域活動スタート支援（仮称）
作成：2026-11-12／**現行MVPの唯一の製品要求**。設計段階。旧v1/v2とは混在させない。

## 1. なぜ作るか
**解決したい仮説**：地域で何かを始めたい個人・立ち上げ前の小規模チームは、活動の目的が決まっていても、仲間・責任者・開催場所・日程・必要な準備・相談先をどの順番で確かめればよいか分からず行動が止まることがある。
**価値提案**：既存の活動を検索するだけでも、任意の空き家を推薦するだけでもなく、**本人が今できる具体的な一歩まで案内する**。本当にこの課題が多いか・サービスを必要とするかは未検証。

## 2. 利用者
**第一ターゲット**：富山県、とくに高岡市で、非営利の地域活動を新たに企画・実施したい人。
- **個人**：やる内容は決まっているが、協力者や活動場所、相談方法が未定。
- **立ち上げ前の小規模チーム**：仲間はいるが、運営役割・開催条件・会場が未整理。
- 法人格・NPO登録・年齢によって排除しない。ただし未成年による子ども向け活動には**学校・保護者・信頼できる成人や既存団体と安全・責任体制を相談する導線**を含める。
- 既存団体の運営管理、単なるボランティア参加検索、ビジネス起業、賃貸・売買・利益計算は対象外。

**実証の入口**：「子どもが自由に過ごせる場／学習支援を開きたい」。将来の対象：地域交流ワークショップ。営利と食事提供は別の検証が必要。

## 3. MVPで利用者に提供する4つ
| 価値 | 入力/処理 | 画面で渡す成果 |
| --- | --- | --- |
| V1 活動準備の整理 | 活動種類、個人/チーム、準備状況、想定人数/日時、地区 | 決定済み／未定の項目の一覧 |
| V2 最優先の一歩 | 状況に応じた説明可能な定型ルール | **最初に行う1件**＋補助の次の行動最大2件、各理由 |
| V3 既存支援への接続 | 対応地区・活動種類、出典付きの公的な窓口/施設情報 | 誰に何を確かめるか、公式サイトの入口と注意。実在の協力や施設空きを保証しない |
| V4 相談準備 | 本人が入力した非個人情報と定型テンプレート | **相談文を画面で確認・コピー**。自動送信や外部共有はしない |

**完成後の理想の一言**：「まず地域活動の相談先に、こういう活動ができるか確認してみる。伝える内容も分かった」。

## 4. 活動カテゴリの範囲
MVPの選択肢（**初期は2つ＋その他の汎用フォールバック**）：
- `child_place`：子どもの居場所・学習支援（**重点実証**）。
- `community_event`：非営利の地域交流・体験会・ワークショップ。
- `other`：それ以外の非営利地域活動。法令・衛生・安全の個別判断を行わず、汎用の準備と相談を案内。

**含まない**：子ども食堂など食事の調理・配食の個別診断、店舗・カフェ開業、収益事業、住宅・移住、その他の危険性を伴うイベントの実施手引き。食事提供の希望は`other`の汎用相談へ縮退し、食品衛生等の専門相談を明示する。**自由記述からAIが自動分類・適法判定はしない**。

## 5. 利用者の主なフロー
Home → ①やりたい活動と現在の状況 → ②開催に必要な条件・未定事項 → ③**あなたの「次の一歩」**（最優先行動と理由） → ④場所の考え方・相談先（任意の展開） → ⑤相談文コピー。

**初期画面の主役は3場所タイプの比較ではなく「具体的な次の行動」**。必要なら公共施設・既存団体の拠点・空き家を比較して確認事項を見る。

## 6. 入力（最小限）
- 必須：`activityType`（上記3種）、`startingMode`（`solo`個人／`forming_team`立ち上げ前チーム）。
- 準備状況：`supportPeople`（相談・協力してくれる人がいる／これから探す／分からない）、`responsibleLead`（責任者がいる／相談・調整中／分からない）。
- 追加・任意：希望地区（まず高岡市内・未定を許容）、予定時期（未定／予定あり）、頻度（単発／定期／未定）、人数（正の整数／不明）、必要な会場条件（机・通信・静かな空間等）、活動説明文（任意、**判定に使わない**）。
- **名前、メール、電話、詳細住所、参加する子どもの個人情報を要求しない**。外部AI APIへ文章を送信しない。

## 7. MVPの機能（Must）
| ID | 必須 | 受入基準 |
| --- | --- | --- |
| P01 | 活動と状況の入力 | 個人/チームの選択ができ、未定項目も進める |
| P02 | 整理された準備状況 | 決定済み/未確認が正しく表示される |
| P03 | **最優先の次の行動** | 活動・個人/チーム・準備状態に応じ、具体的に何をするかと理由が表示される |
| P04 | 準備の手順 | 追加の行動最大2件、確認方法・注意点を示す。完了や実施を保証しない |
| P05 | 地域の公的資源への入口 | **高岡市の確認済み公的窓口・施設情報のリンク**を根拠と更新確認日付きで案内。対象の施設/制度が使えるとは断定しない |
| P06 | 会場を考える補助 | 既存施設を最初の候補として考え、既存拠点・空き家は条件付きの選択肢として説明する |
| P07 | **相談文の生成・コピー** | 活動種別・人数・日時・確認したい条件を定型文へ反映。本人が編集・確認してコピーできる。**自動送信しない** |
| P08 | 表示とデータの安全 | スマホ、キーボード、エラー説明、出典、架空/未検証、ブラウザー内処理 |
| P09 | 検証可能なルール | 複数ケースで同じ入力は同じ案内。不明・子どもの安全・外部情報エラーの縮退を確認 |

**Should**：地域ごとの施設比較の充実、利用者が選択できる「実際に進めたい一歩」、公式の利用条件リンクを増やす、軽量な印刷表示。  
**Later**：団体/仲間マッチング、実際の空き家物件紹介、予約・問い合わせ、活動資金/補助の要件判定、ユーザー登録・進捗保存、LLMによる提案。

## 8. なぜ単なるチェックリストではないのか（検証すべき差）
- 個人とチームの**準備状況で最初の行動と理由が変わる**。
- 抽象的なアドバイスで終わらず、**出典付きの市の窓口・施設情報につながる**。
- 相談時に何を伝えるかを**自分の条件から下書きできる**。
- ただし、この差が既存の検索・自治体サービス・ChatGPTより便利とはまだ証明できない。ユーザー比較で確認する。

## 9. 成功と非成功
- **検証する成果**：初見の利用者が、自分の状況で現実的な最初の行動を1つ説明し、相談時に確認すべき内容を言えること。
- **別途検証する成果**：実際に問い合わせや施設の確認へ進んだか。ユーザーの許可・同意なしに行動を追跡しない。
- **保証しない**：会場が借りられる、団体・仲間が見つかる、行政の支援を受けられる、活動の安全性や法的条件が満たされる、地域課題が解決した。

## 10. 技術・公開（予定）
React + TypeScript + Vite、静的で版管理された行動テンプレートと公式リソースリンク、クライアント側で優先度判定。DB・ログイン・AI APIなし。入力データはサーバー保存しない。公式ページへの遷移やホスティングの通信ログは別で発生し得るため公開時に明示。
