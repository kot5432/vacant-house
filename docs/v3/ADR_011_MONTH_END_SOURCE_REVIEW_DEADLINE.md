# ADR-011｜月次公式出典点検は各月末締切（A案正式採用）

決定日：2026-11-15。利用者はA案「月末までにその月の点検を完了、未完了なら翌月1日から施設固有の断定を停止」を正式採用した。既定の[ADR-009](ADR_009_OFFICIAL_SOURCE_MONTHLY_RELEASE_REVIEWS.md)（毎月＋各リリース前確認）と[ADR-010](ADR_010_STALE_SOURCE_FAIL_CLOSED.md)（期限超過時は猶予なし停止）を維持。**設計のみ、コード／ブラウザ試験／公開なし。** 対象は地域イベント準備支援Webアプリのみ。旧空き家所有者・物件・マッチングは対象外。

## 1. 正式に決まった期限

- 毎暦月1回、掲載出典ごとに公式原ページの内容・対象条件・リンクとアプリに掲載する文言を点検する。必要なレビューの完了も**その月の末日中**に行う。
- 期限の基準は**日本時間 Asia/Tokyo（JST）**。例えば2026年11月分は11月30日23:59:59.999 JSTまで。**12月1日00:00 JSTに未完了なら、11月分の出典は`needs_review`相当として施設固有の断定を停止**。7日猶予なし。2月やうるう年も各月の末日で判断。
- 月内の点検日を特定の日に固定する必要はない。ただしチームの作業予定日は前倒し設定してよい。「毎月15日まで」「前回点検から30日」の方式は不採用。
- 毎本番リリース前の点検は月次とは別の出荷条件。リリース前に実際に点検とレビューが完了していない施設固有の出典は掲載できない。
- 出典の改定・リンク切れ・誤案内の疑いを把握した場合は月末を待たず停止。月次の期限内であることは**情報の正確性の保証ではない**。

## 2. 出典の月次検証メタデータ（採用ルールから必要な項目）

| 項目 | 用途 |
|---|---|
| `sourceId` | 施設ごとの固定出典ID。別施設に流用しない |
| `baseStatus` | `verified/needs_review/suspended/retired`（出典自体の確認状態） |
| `reviewedMonth` | **原ページ確認と必要なレビューの両方が完了した暦月 `YYYY-MM`**。未完了なら更新しない |
| `checkedAt` | 原ページを実際に確認した日時。予定日で捏造しない |
| `reviewedAt` | 適用範囲・表示文言のレビューを完了した日時 |
| `sourceRevision` | 公式情報の内容・適用範囲の台帳版 |
| `catalogVersion` | アプリが同梱する出典セットの版 |
| `publishedForReleaseAt`（案） | 本番リリース前確認の記録。月次点検済みと混同しない |

- データの欠落・不正な日付・矛盾した`reviewedMonth`を**期限内であると推測してはならない**。一般確認へフォールバック。
- `checkedAt`だけを見て自動的にレビュー完了とみなさない。異なる担当者の確認とレビュー記録を区別する。
- 各月の点検と同じ月に初回出典登録・出荷前確認を済ませた場合、**同じ対象範囲・同じ原ページ・必要なレビューが完了した記録**を当月点検に利用できる。実際に再確認していない他の施設・制度まで完了扱いにしない。

## 3. 期限判定の厳密なモデル（参照日を引数に取る純粋関数の設計）

`asOfJstCalendarDate`を基準とし、**直前の暦月（previousMonth）のレビュー完了記録があること**を、当月における期限超過の判定条件とする。加えて、当月に新規出典を登録して本人と別レビュアーによる確認を済ませたものは、その月の対象として表示できる。

- 2026年11月30日：2026年11月のレビューが未完了であっても、**10月分が正常に確認済み**であり出典がverifiedなら、月末の期限が経過するまではこの「11月未完了」だけで停止しない。
- 2026年12月1日：**11月分が未完了**なら停止。11月分が完了していれば、12月点検は12月末まで実施できる。
- 2027年1月1日：**12月分が未完了**なら停止。
- ただし前々月以前の欠落・停止状態を**翌月だけの偶然の記録で黙って解消しない**。復帰時には原ページ再確認・必要なレビュー・`verified`復帰を明示する。
- 正常な当月新規登録の例外と、初回公開前の`verified`必須ゲートを混同しない。
- 技術的にはUTCのタイムスタンプをJST暦日に変換し、入力した地域イベントの開催日（ユーザーの希望日）と**出典確認期限のJST暦日**を混同しない。

## 4. 画面と進捗

`baseStatus=verified`かつ期限条件・現在の施設適用条件を満たすときだけ、対象の確認日・原URL・短い公式情報を表示。期限切れ・未検証のときは施設固有の断定を外し、U03に「この施設の利用条件は現在再確認中です。最新情報は施設管理者の公式案内でご確認ください」と示す。リンクの安全性が未確認なら無条件に表示しない。

**一般のP01〜P12は維持し、本人の`completed/not_applicable`を変更しない**。`needs_review`は出典状態、`needsRecheck`はイベントタスクの本人再確認という別の軸。条件改定で旧確認前提が変わったときだけ該当タスクの再確認を検討する。

## 5. 未解決の技術・運用制限

- **古いブラウザタブの即時反映は保証できない**。同梱メタデータとJST現在日による再評価で期限超過を検知する設計は可能だが、端末時計のずれ・ビルドが古い場合の復帰は別途検証する。
- 出典台帳が古く、当月実施済み点検がまだ配信物に反映されていない場合、**誤って「再確認中」と表示されることはあり得る**。古いビルドのまま「確認済み」にするより安全側に扱う。
- 更新担当／二人目レビュー担当と代行者、月次記録の管理場所の最終的な実務割当は未決。
- 試験・元の高岡市公式情報の最新閲覧は本ADRの作成によって実施されたものではない。
