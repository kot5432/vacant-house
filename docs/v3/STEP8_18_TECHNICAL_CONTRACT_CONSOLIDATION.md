# STEP8-⑱｜実装前の技術契約・データ境界の統合案（設計のみ）

作成：2026-11-16。**この文書で製品仕様を追加採用しない。** 現行の小規模地域イベント準備支援アプリのみ。旧空き家所有者・物件マッチングのコード・データは用いない。実装、試験実行、デプロイは行っていない。

## 1. 規範の優先順

1. **ユーザーが明示採用したADR-001〜028**。特にADR-003・027・028の優先度、ADR-015〜026のバックアップ・保存保護。
2. 後続のSTEP8-⑩〜⑰の**既決内容の解釈と技術詳細提案**。
3. 既存のSTEP4〜STEP7の初期案は履歴。後続ADRに反する「P08をP1へ上げる」「JSONはMVP対象外」「上限超過時の手段は未決」などを**現在の実装仕様として使わない**。

## 2. 正規化された入力表と追加質問なしの境界

| 入力 | 保存先の正規候補 | 既決の使い道 | 注意 |
|---|---|---|---|
| イベント種類 | `input.eventType` | otherのみP01=P2 | 自由記述の内容を自動分類しない |
| 参加対象 | `input.audience` | undecidedはP02=P2、minors/bothはP05=P1 | `facilityUsersAge`と別 |
| 開催時期 | `input.date`（技術正規候補） | month/undecidedでP03=P2 | 他文書の`schedule`と同じ1問。両方を持たせない |
| 会場状況 | `input.venueStatus` | undecided/candidateはP07=P2 | no_physical_venueはオンライン確定でない |
| 地域 | `input.region` | 施設固有出典の適用判定のみ | 地域のみで行政手続を確定しない |
| 主催形態 | `input.organizerForm` | undecidedでP04=P2 | soloでも責任者確定とみなさない |
| 責任者（任意） | `Known<decided|not_decided>` | kind=undecided／answered.not_decidedでP04=P2 | unansweredはP3条件 |
| 必要設備（任意） | `Known<yes|none_identified>` | answered.yesでP09=P2 | none_identifiedは不要の確定でない |
| 参加人数（任意） | `Known<number>` | 1001人以上に注意 | 自動優先度変更はしない |

**型固定の推奨**：初回公開の`EventInput`キーを`date`に一本化し、JSONで不明な`schedule`を寛容に取り込まない。これは[STEP8-⑩](STEP8_10_CANONICAL_INPUT_MAPPING_AND_ENUM.md)の技術案であり、初回バックアップ正式スキーマ版の確定と同時に最後の型レビューを行う。

## 3. 優先順位の不変条件（ADR-003/027/028）

- **P05**：audience=minors/bothはP1、adults/undecidedはP2。
- **P08**：P2基本。施設公式出典の対象一致だけでP1にしない。物理会場なしでもP08親はneeds_information・P2。
- P01〜P04・P07・P09：既決の限定分岐に該当するときだけP2、通常P3。P06/P10/P11/P12=P3。
- 未解決候補はP1→P2→P3／同区分taskId昇順。代表以外のP1を隠さない。進捗・needsRecheck・revisionを優先度再計算で変更しない。
- P07〜P09は物理会場なしでも親の一般確認を残し、建物専用子項目のみ非該当。出典の適用有無と本人進捗は独立。
- 行政の必要手続、予約・許可、危険度、人数・日数の閾値を入力から推測しない。

## 4. 保存と復元の不変条件

| 操作 | 保存が成功したときだけ起こること | 失敗・競合・キャンセル時 |
|---|---|---|
| U02初回生成 | 有効な基本入力でEventRecordを初回保存→U03 | U02入力保持、DB不変、U03に進まない |
| U03本人進捗 | 該当taskIdだけrevision CASで更新（ADR-026） | 他の入力・進捗へ影響なし、成功表示なし |
| U03明示再確認解除 | 本人操作＆CAS保存成功でのみ解除（ADR-004） | needsRecheckを維持 |
| U04入力編集 | 明示保存＆検証＆CAS成功で新入力へ。非該当の施設固有値を必要な範囲だけクリア（ADR-005） | ドラフトと既存DBを分離し、旧入力を破壊しない |
| U01選択式JSON書き出し | 選択集合をスナップショット検証、完成ファイル2 MiB・100件以内 | 無断切詰め・無断選択解除なし。DB不変 |
| U01 JSON取込み | 現行・検証済み既知旧版のみ、プレビュー承認、別ID複製・revision=1、原子的一括追加 | 全件拒否／既存DB不変 |

**別タブで削除されたイベントを古いタブが復活させない**。旧版アプリが未知schemaのEventRecordを上書きしない。ブラウザ更新は本人の明示操作（ADR-013）。保存成功を偽らない。

## 5. JSON初期形式を凍結する前のレビュー項目

[STEP8-⑫](STEP8_12_BACKUP_JSON_V1_SCHEMA_DRAFT.md)の`formatId`、`exportSchemaVersion`、`eventSchemaVersion`は候補であり、**まだ正式値ではない**。公開前に以下を一組として決め、既知旧版の対応表は実際に検証した版だけ列挙する。

- ルート必須フィールド・型、1ファイル100件／2,097,152実UTF-8バイト、0件書出し禁止（ADR-021）、元ファイルが空のときの読込可否と画面動作。
- EventRecordの必須・任意フィールド、`eventId`の一意性、`input.date`、`Known`値、`progressByTask`、`importedFrom`の非再帰構造。
- 元日時の厳密検証、未来日時の明示確認、既存IDとの衝突を本人承認後に別ID複製、繰り返し復元を許可する動作。
- 旧データが現行の文字数・バイト制限に違反していたら、読取・U03本人進捗は維持、U04全入力保存と対象エクスポートは保護的に停止（ADR-025/026）。

## 6. 状態に基づく文言・エラーの最低契約

- U03の優先理由は**本人が選択した入力**と紐づけ、P1/P2/P3を行政義務・安全認定として表示しない。
- 「未着手（本人進捗）」「対象外（本人判断）」「今回は非該当（ルール判定）」「要再確認」「出典要確認」「保存失敗」を混ぜない。
- 公式出典が期限を越えたら施設固有の現在断定を止め、本人の完了・対象外は保持する（ADR-009〜012）。
- 同時更新／容量不足／スキーマ未対応／JSON不正／選択上限超過を**異なる失敗理由**として表示し、本人が採れる次の一歩を案内する。
- 320px幅、200%拡大、キーボード、動的保存状態の読み上げを実機受入へ。**ここでは操作確認を行っていない**。

## 7. 統合レビュー上の注意点

- **未採用の技術値がある**：JSON専用formatId/版番号、UIの一部文言、実機で確認したUnicode分割と最小ブラウザ版。勝手に正式ADRにしない。
- **実在する外部関係者の確認が必要**：初主催者への需要・理解検証、施設管理者の最新個別運用、公式出典の第二レビュー。
- **実行作業が必要**：コード実装・保存競合・ブラウザ互換性・アクセシビリティの検証。本人から実装の明示指示を受けるまで行わない。
