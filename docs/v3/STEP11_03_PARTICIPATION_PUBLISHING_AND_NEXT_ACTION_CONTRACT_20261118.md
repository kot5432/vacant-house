# STEP11-③｜参加D00〜D02の画面・掲載判定・データ契約最終レビュー案
日付2026-11-18。**MVP構成はADR-030正式採用、以下の具体的なフィールドenumと表示ロジックは実装前レビュー案**。実装・利用者検証・実行テストは未実施。

## 1. 入力・状態の最小構成
- D00：二入口（「参加してみたい」→D01、「企画してみたい」→U01）。主催を使うための参加履歴は不要。
- D01：`municipality`および`topicTag`の2つで絞る（初期高岡市中心、県全域網羅はうたわない）。出典確認済みの個別活動のみ。空の条件なら確認済み一覧を表示。出典リンク・確認日・開催種類はD02でも必ず示す。
- D02：活動名、運営元、日時、場所、対象/年齢条件、費用、申込方法、所要時間、持ち物、初参加歓迎、1人参加可否のうち公式に確認できる事実と未確認を分け、最初の行動1つ＋公式リンク。
- ユーザーの年齢・所在地・プロフィール・参加意志・健康状態を取得しない。活動への参加実績をアプリに保存しない。
- 参加側はビルド同梱の公開カタログ、主催側は個人EventRecord。両者のバックアップ・ID・priorityロジックを共有しない。

## 2. 掲載と表示の2段階判定（順序が重要）

### 編集・掲載判定
| 順序 | 条件 | 公開動作 |
|---|---|---|
| E0 | 公開主体/個別活動名/一次詳細URLのいずれか不明、私的な連絡先の混入 | 通常カードとして掲載不可。索引サイト案内は別枠 |
| E1 | 出典一次ページ未確認、リンク不通、内容が実在の個別募集か不明 | 掲載保留`needs_review` |
| E2 | 出典・確認時点・表示欄の根拠を記録し、別担当レビューあり | `visible`候補。ただし募集が現在開いているとは認定しない |
| E3 | 受付終了/開催終了を確認 | 必要なら過去資料として表示できるが、参加候補の通常一覧からは除外する案 |
| E4 | 誤掲載/撤回要請/リンク先の変更を発見 | 該当カード停止、代替の一般公的・団体索引へ |

### 次の一歩（公開可能な個別活動のみ）
| 先行順位 | 条件 | nextActionCode（候補） | 文言 |
|---|---|---|---|
| 1 | 終了日のある単発・期間開催が過去 | ENDED | この回は終了。新しい活動の情報は公式案内で確認 |
| 2 | 募集終了を原サイトで確認 | CLOSED | この募集は終了。今後の案内は公式情報で確認 |
| 3 | 定期活動の次回開催が未確認、募集状況未確認、情報の更新確認がない | VERIFY_STATUS | 最新の開催・参加受付状況を公式案内で確認 |
| 4 | 応募対象・費用・申込要否に確認できていない点がある | VERIFY_REQUIREMENTS | 参加条件・費用・申込方法を確認 |
| 5 | 公式の参加案内が明示された | READ_OFFICIAL_GUIDE | 公式の参加案内で手順を確認 |
| 6 | 参加案内の確認が不十分だが一次ページはある | READ_SOURCE | 公式の活動情報で詳細を確認 |

**原則**：`confirmed_open`は確認時点の事実であって、現在の残席や受付を保証しない。日時付きで「確認時点に募集の案内あり」と表現。`confirmed(false)`と`unknown`は別。情報不足でも「この人は参加可能」と認定しない。

## 3. カタログ運用の最小責務
| 責務 | 管理対象 | 必要な根拠 |
|---|---|---|
| 収集 | 個別の団体・自治体一次ページ | URL、公開主体、見た内容、日付 |
| 正規化 | municipality、topic、schedule、参加詳細8項目 | 確認できる値とunknownの区別 |
| 別人レビュー | URL/活動対象/条件/表現/著作物 | 確認者とレビュアーの記録 |
| 公開 | 版付きの読み取り専用静的カタログ | ビルド版と出典確認日 |
| 停止・訂正 | 終了、リンク切れ、要請、条件変更 | 要レビューへの変更と再公開手順 |

**募集の自動巡回、スクレイピング、プラットフォームへの書き込みは禁止範囲**。確認責任者と訂正窓口を割り当てられない場合、初期公開は「公式活動索引＋参加前の確認事項」へ縮小する。

## 4. D01/D02文言の否定例
- 「誰でも参加可能」「あなたにぴったり」「今すぐ確実に申し込める」「無料」「1人参加歓迎」は一次資料で裏付けられる場合にのみ限定し、表現も確認時点であることを明示。
- 知らない費用や募集状態を推測で埋めない。
- 索引を1つの架空個別イベントとして数えない。複数企画を1件にまとめて募集中と断定しない。
- ユーザーから個人情報を集めて「参加できます」と判定することをMVPの対象にしない。

## 5. 主催との接続
- D02→U02は任意の「自分で企画する」。必須6問を本人が入力し、参加イベントの内容は自動転記しない。
- U01/保存済みイベントからの再開はD00を強制しない。主催U03進捗・再確認・JSONは参加カタログ更新で変化しない。
- D00〜D02に子チェックは存在しない。主催側の子チェックもADR-031で削除済み。
