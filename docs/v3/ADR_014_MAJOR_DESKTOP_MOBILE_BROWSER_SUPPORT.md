# ADR-014｜対応ブラウザはPC・スマホの主要現行ブラウザ（A案正式採用）

決定日：2026-11-15。**利用者がA案を明示採用済み**。Chrome・Edge・Safari・Firefoxの現行主要版を中心に、PCとスマートフォンでの動作検証を対象とする。これは**検証対象範囲の決定**であり、実機動作を確認済み・全環境対応済みという宣言ではない。具体的な最低対応バージョン／OSは実装後の検証に基づき公開前に確定する。

対象は現行の単発・小規模地域イベント準備支援Webアプリ。旧空き家・所有者診断・物件検索・マッチングを対象にしない。**コード実装、実行テスト、デプロイは未実施**。

## 1. 公式な検証対象の方針

| 実行環境 | 対象（推奨するテストマトリクス） | 備考 |
|---|---|---|
| Windows / macOS | 最新安定版Chrome、Edge、Firefox、Safari（利用可能なOSのみ） | OSに存在しないブラウザ組合せは必須としない |
| Android | 現行版Chrome、Firefox（利用可能な環境）、Edge（対応時） | 端末・OSの組合せは実際の検証可能範囲で決める |
| iOS / iPadOS | 現行版Safari中心、Chrome・Firefox・Edgeは実行可能な範囲で確認 | モバイルブラウザ表示・IME・保存動作を独立確認 |
| 保存が制限された環境 | プライベートモード、保存無効、容量不足、閲覧データ削除 | 全てを「保存保証」と扱わず、失敗と復旧案内を検証 |

**対象外の第一候補**：古いブラウザ、サポート切れOS、埋込WebView、プライベートモードを恒久保存対象として扱うこと。必要に応じて閲覧や試用できても正式サポートの保証にはしない。

## 2. Unicode文字数検証とIME

- [ADR-008](ADR_008_OPTIONAL_TEXT_LIMITS.md)の上限**施設名メモ100字・説明500字**は維持。**文字数単位の実装候補は`Intl.Segmenter('ja',{granularity:'grapheme'})`の書記素クラスタを第一候補**とし、UIカウンターと保存検証で同じ関数を使う。これを採用するための技術的な適合性は主要ブラウザで高いが、**全対応版・絵文字・結合文字の一致は未検証**。
- 文字数と別に、極端な長さの**1書記素**や大量データによる負荷を抑える技術上限（例：UTF-8サイズ）を後続の技術レビューで設計する。100字／500字をバイト数に読み替えない。
- IMEは`compositionstart/compositionend`等のイベントを使用して変換中の文字列を保持し、**変換中の強制カットやエラー確定をしない**。`InputEvent.isComposing`だけへの依存は避け、候補確定前後・Android/iOSの順序差を実際に検証する。
- 超過時は局所エラーとカウンターで説明、U04保存は拒否しつつ、ドラフトを消さない。保存成功前の永続化をしない。
- `Intl.Segmenter`非対応環境で**黙ってUTF-16長さに切り替えない**。同等の書記素実装で計数を維持するか、正式サポート外として機能制限を説明するかは技術判断として記録する。

技術参照：https://developer.mozilla.org/ja/docs/Web/JavaScript/Reference/Global_Objects/Intl/Segmenter / https://developer.mozilla.org/ja/docs/Web/API/InputEvent/isComposing

## 3. IndexedDBとアプリ更新

- イベント入力・進捗は**同一オリジン／同じブラウザのIndexedDB**に保存。Android↔PC、Chrome↔Safariの自動同期を導入しない。ブラウザデータ削除、プライベートモード、容量超過で保存内容が失われ得ることを利用者へ説明。
- U02初回入力は永続下書き保存しない。U03進捗は保存成功後に確定、U04は明示保存。更新失敗・競合で保存済みと誤表示しない。
- 旧タブの`schemaVersion`不一致と`Dexie versionchange`を混同しない。旧タブから新版のIndexedDBへ誤書込しない対応をテストする。
- [ADR-013](ADR_013_MANUAL_REFRESH_ON_AUTO_VERSION_DETECTION.md)どおり**軽量buildIdの自動照合＋本人による再読み込み**、自動リロード禁止。通信エラーで新版を断定しない。月末公式出典失効はビルド識別子の成否と独立して判定する。
- 画面横幅320px、200%拡大、キーボード操作、スクリーンリーダーでの入力エラー／保存状態通知も受け入れ試験に含める。

## 4. 検証行列（実行前の期待）

| ID | 対象 | 合格条件 |
|---|---|---|
| BR-01 | Windows Chrome/Edge/Firefox | U01〜U04、編集と保存と復帰が動作 |
| BR-02 | macOS Safari/Chrome/Firefox | 同一オリジンのIndexedDB、IMEとU04保存を確認 |
| BR-03 | Android Chrome、対象ブラウザ | 文字入力、書記素カウント、保存・復帰・新版通知 |
| BR-04 | iOS Safariと対象ブラウザ | 同上。IME・画面遷移・保存を確認 |
| BR-05 | 書記素（絵文字、結合文字、日本語濁点、改行） | UIカウンターと100/500字の保存判定が一致 |
| BR-06 | 変換中のIMEと境界超過 | 変換を途中でカットしない。確定後にエラー |
| BR-07 | IndexedDBが使えない・容量不足 | 保存成功と偽らず、入力内容を可能な限り保持 |
| BR-08 | 別タブでDB schema更新／revision競合 | 旧タブは上書きせず更新・再読込を案内 |
| BR-09 | 旧タブで新版検知（U02/U04ドラフトあり） | 強制リロードをせず、本人が再読込を選択 |
| BR-10 | 月末JSTを越えた古いタブ | 未点検出典の施設固有断定を停止する設計を検証 |
| BR-11 | 非対応・旧ブラウザ | 黙った文字数単位変更や保存成功偽装をしない |
| BR-12 | 320px／200%／キーボード | 重要操作・エラー・保存状態へアクセス可能 |

## 5. 確定／未決

**正式決定**：PC・スマホ主要現行4ブラウザを中心とする検証範囲。対応バージョンの公開前実測必須。文字数上限・IndexedDB・旧タブの既決事項は変更なし。

**技術レビュー残件**：正式サポートの最低バージョン・実機OS、`Intl.Segmenter`非対応対策とUnicode技術上限、IMEイベント差、IndexedDBの環境別制約、旧タブのビルドID配信・キャッシュ・スキーマ移行の具体技術。いずれもユーザーが承認していない詳細を勝手に製品の正式ルールとして凍結しない。
