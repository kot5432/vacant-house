# STEP8-①｜既存入力が現行制約を超える場合のU03タスク進捗保存（未決の選択肢）

作成：2026-11-15。**本書はユーザー確認前の設計比較であり、A/B/Cは未採用**。現行の地域イベント開催準備支援Webアプリ専用。旧空き家・所有者・物件・マッチングとは無関係。**コード実装・データ移行・テスト実行なし**。

## 1. なぜこの判断が中心価値に関わるか

[ADR-025](ADR_025_LEGACY_OVERSIZED_RECORD_READ_ONLY_UNTIL_FIXED.md)で「現在の文字数・UTF-8サイズ上限に不適合な既存イベントは**閲覧維持**、U04の全入力保存は本人が修正するまで**不可**」を正式採用。

しかしU03の準備プランでは、P01〜P12の進捗（未着手／進行中／完了／対象外）や`needsRecheck`の本人確認操作を保存する。**U04の入力編集とU03の進捗更新は目的が違う**。既存メモが大きいという理由だけで、本人が進めたタスクの進捗保存をどう扱うかが未決。進捗更新時に古い`EventInput`を全体上書きすると、異常入力を切断したり、別タブの変更を消したりする危険もある。

## 2. 利用者が決める3案

| 案 | 既存イベントが入力上限超過のままU03を操作した場合 | 長所 | 課題 |
|---|---|---|---|
| **A（推奨）** | **入力は読み取り専用で保持し、進捗だけを独立CAS付きトランザクションで保存**。U04の全入力保存は修正するまで不可 | 中心価値の準備進捗を止めず、本人メモも消さない | 別タブ競合・schema・再確認理由の整合を十分試験する必要 |
| B | **不適合な入力を修正するまでU03の進捗保存も停止**。閲覧だけ許可 | 保存経路が単純で判定を統一できる | 既存イベントで準備が進んでも記録できず、中心価値を損なう |
| C | **U03進捗保存時にEventRecord全体を書き直し、旧入力のサイズ超過を特例で許容** | 既存の全体保存経路を再利用しやすい | 上限例外と旧タブ上書き・想定外のデータ変更の危険が増える |

**推奨A**：作業進捗はユーザーが意図して行った変更だけを保存する。入力不適合の解消とは独立させ、進捗更新を機に元メモを無断改変しない。

## 3. A案の実装前の安全契約（未承認）

1. U03で更新するのは本人が操作した特定`taskId`の`progressByTask`および必要な`needsRecheck`だけ。**元の入力、作成日時、施設メモ、説明を全体再生成・切断しない**。
2. 現在のイベントが存在すること、`eventSchemaVersion`と保存済み`revision`が期待どおりであること、対象`taskId`が現行P01〜P12であること、進捗enumが有効なことは**必ず検証**。全入力の現在の文字列サイズへの不適合を理由とした無関係な書込変更は行わない。
3. 一つのIndexedDB readwriteトランザクションで現在レコードを読み、revision整合を確認し、進捗だけ更新してrevisionを1つ増やす。**コピーされた旧EventRecordからのまるごと`put`で他の変更を失わせない**。Dexie/IndexedDBでの正確な同時書込保護は実機試験対象。
4. 別タブでU04が入力を修正・イベントを削除・別タスク進捗を保存していた場合、**自動マージ／削除イベント復活をしない**。競合を表示して最新を読込み、本人の再操作を求める。
5. 進捗操作後、既存の`needsRecheck`は[ADR-004](ADR_004_EXPLICIT_RECHECK_CLEAR.md)どおり本人の明示操作・保存成功時にしか解除しない。再確認理由と公式出典の`needs_review`を混同しない。
6. 進捗保存失敗時は「保存できませんでした」と表示し、UIで未保存変更を誤って「保存済み」としない。閲覧可能であることが進捗保存成功を意味すると主張しない。
7. U04の入力全体保存は[ADR-025](ADR_025_LEGACY_OVERSIZED_RECORD_READ_ONLY_UNTIL_FIXED.md)の規則を維持し、上限を超えたまま保存成功させない。バックアップのインポート／エクスポートもADR-025の拒否／停止のまま。

## 4. P01〜P12の中心価値と追加の設計レビュー

この判断の後に[判定エンジン契約](RULE_ENGINE_CONTRACT_V1.md)、[判定表v1.1](STEP4_RULE_DECISION_TABLE_V11.md)の未確定なP01〜P12優先度・該当性の条件、U03進捗の保存と出典期限切れ時の再計算をレビューする。法令上の手続き完了をアプリが勝手に認定しない。公式情報の期限・月次確認はADR-009〜012を維持。実自治体情報の点検は未実施と明記する。

## 次の利用者判断

**A案：入力を不変のままU03の進捗だけ安全に保存／B案：修正までU03進捗保存も停止／C案：全EventRecordの書直しを特例許容**。MVPの中心価値と本人データ保護の両立からA案を推奨。正式選択までは進捗更新の例外取り扱いを決定済みと書かない。
