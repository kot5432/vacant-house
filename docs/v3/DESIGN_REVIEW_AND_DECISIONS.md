## 発見した設計上の矛盾と今回の修正
| ID | 以前の懸念 | 今回の設計決定（未実装） |
| --- | --- | --- |
| D01 | v3.1の結果表示後に初めて「地域交流センターを検討しているか」を聞くと、最初のカードがその制約を考慮できない | 入力ステップ2に任意の「地域交流センターを検討中」質問を置く。後から場所画面で変更した場合は**結果を再計算**する |
| D02 | ユーザーの障壁が会場なのに、安全一般論のみが結果を占めることがある | **子どもの安全は独立して常時表示**。センター未成年制約のような固有の利用上の制約が確定的に該当するときは、最初の確認カードにも入れる。抽象的な優先案内が障壁を消さないようにする |
| D03 | 説明が「3種類の会場の比較」のままだと独自性が見えない | 結果画面の主役を**現状の障壁→条件別の最初の確認1件→確認先・質問**へ置く。会場タイプ比較は任意の補助画面 |
| D04 | 補助金の募集要項に古い募集期限があると、利用者が今申請できると誤認 | **締切済み**の制度はMVPの主結果で募集案内しない。参考として示す場合は「募集終了・次回の条件は要確認」とする |
| D05 | 公共施設の存在・公開時間を知っただけで利用可と誤認 | **公式の一般掲載／管理者の個別承認／予約可否**は必ず分ける |
| D06 | 全ユーザーに高岡市条件を出すと、高岡市外でも使えると誤認 | 希望地域が高岡市外・未定なら一般案内。**地区が不明の場合は高岡特有の条件を確定的に当てはめない** |
| D07 | 「未成年者のみで利用できない」をすべての施設に適用しがち | **高岡市地域交流センター固有の出典**として扱う。ほかの施設では都度確認 |
| D08 | 「質問最大3件」で安全上の重要事項を隠す | 見守り/責任/緊急時/保護者説明等は**カード件数上限とは別**の注意欄へ保持 |
| D09 | 高岡で需要があることを裏付けるアンケートが直接ない | **需要は未検証**と明記。机上でできるのは事実の確認・設計ケースの整理・比較シナリオまで |
| D10 | 「使用できる制度がある」と言うだけならサイトのリンク集と同じ | 利用者の**今の障壁・活動条件・問い合わせ先への質問**を結ぶ設計とし、競合より役立つかは別途検証 |

## 設計上の受入ゲート（結果は未評価）
1. 活動内容・障壁・センター利用の意図を入力後、適切な最初のカードを表示する。
2. 入力を修正したら適切に結果が更新される設計になっている。
3. 施設・制度の条件と本人の状況を混同して「利用許可済み」を出さない。
4. 公式情報の参照先・確認日と、一般的な助言を区別する。
5. 個人でも使え、団体登録や詳細な個人情報を要求しない。
6. リンクが使えない/資料更新が必要なら断定をやめ、公式管理者への確認を促す。
7. 既存施設で実施できれば、空き家を活用するよう誘導しない。
