## 必須ユーザーストーリーの歩き方
1. 参加者：D00→D01（0件でも説明）→D02（公式出典＋未確認）→公式リンク。アプリは申込そのものをしない。
2. 初主催者：D00→U01→U02（6問）→保存成功後U03→P05/P08を含めた親カードを見る。
3. 同一主催者がU04で対象を成人→未成年に変更：P05のP1導出と、以前の完了は保持・必要な要再確認だけ表示。
4. 保存なし・IndexedDB不可・別タブ競合・未知schema時に誤った成功表示や暗黙の上書きがない。
5. JSON 100件/2MiB、選択のみ書出し、プレビュー＋本人承認の復元、異常1件で全件reject。
6. スマホ最小幅320px、文字拡大200%、キーボード操作、フォーカス可視、文言だけで状態理解できること（設計上の受入条件。未検証）。

## コンテスト向け最低限のデモ筋（実装前シナリオ）
- 冒頭：富山の地域活動の困りごとと競合を認識した上で「自分の次の行動が分かる」ことを示す。
- 主催：6問の入力→P05/P08の優先度説明→進捗→U04編集→再確認。
- 参加：D01/D02で出典と未確認の分離→公式ページの確認へ誘導。
- 実装していないなら「構想・モック」と表示し、**作品部門の実動作として撮影しない**。
- AI活用は「何をAIに任せ、人が何を審査/修正し、何を実行したか」を記録。実際の開発内容に合わせて最終化。

## 削ってもよいもの（人の正式判断前の案）
- 個別参加候補が未審査のときは承認済みカード0件＋公式索引を表示。
- 主催機能の導出P01〜12・進捗・データ保護は中心価値なので、削除を安易に提案しない。
- 可視化・自動推薦・チャット・外部ログイン・SNS連携・投稿・予約・決済を拡張しない。
