# ADR-012｜公式出典はアプリの静的ビルドに同梱（A案正式採用）

決定日：2026-11-15。**ユーザーがA案を明示採用**。出典・タスクカタログをVite/Reactのビルドに同梱し、再検証後の施設固有情報の再掲載は**新しいアプリ版を読み込んだときのみ**行う。別配信JSONを起動時に取得するB案、専用APIを呼ぶC案はMVPでは不採用。これは**設計決定のみ**で、コード・CI・動作テスト・Vercel配信は未実施。

現行対象：初めて単発・小規模の地域イベントを主催する人に、準備の全体像と優先確認事項を示すWebアプリ。旧空き家所有者・物件マッチング・用途診断は使用しない。

## 1. 設計上のデータ境界

- Git管理する版付き公式出典カタログ：`catalogVersion, buildId, sourceId, sourceRevision, baseStatus, checkedAt, reviewedAt, reviewedMonth, publisher, officialUrl, facilityScope, applicabilityPredicate, shortSummary, actionHint`。具体的なTS/JSONの配置と厳密なバリデーションスキーマは技術設計で凍結する。
- カタログは**公開ビルド時に読み取り専用資産として取り込む**。運用担当が出典を再確認・レビューしただけでは、既に開かれている画面に新しいレビュー結果が自動到達しない。
- 利用者のEventRecord（IndexedDB）にはイベント条件・進捗・revisionを保持。**公式カタログの新しい状態を利用者のDBへコピーして出典を復活させない**。公式URLへユーザーのイベント回答を送信しない。
- `rulesVersion`・`catalogVersion`・`sourceRevision`・`schemaVersion`は異なる版識別子。データ移行や再確認の判断で混同しない。

## 2. 出典の期限切れと再掲載

- [ADR-009](ADR_009_OFFICIAL_SOURCE_MONTHLY_RELEASE_REVIEWS.md)に従い、掲載出典は**月1回＋各本番リリース前**に原ページ確認・必要なレビューを行う。
- [ADR-011](ADR_011_MONTH_END_SOURCE_REVIEW_DEADLINE.md)に従い月次点検の締切は**JST各暦月末**。前月分のレビュー未完了のまま翌月1日00:00 JSTになれば、[ADR-010](ADR_010_STALE_SOURCE_FAIL_CLOSED.md)に従い**猶予なく施設固有の断定を停止**し、一般的な準備案内へ。
- アプリ起動時・U03表示時・タブ復帰時・開いたまま月境界を越えた場合は、現在読み込んでいるカタログの有効状態を再評価する設計。正確な監視方式・タイマー／イベントは技術選定前の提案であり**実装済みとは扱わない**。
- 出典が再確認済みでも**古いビルドに含まれない新しい結果を勝手にverified化しない**。再掲載は新しいビルドを読み込み、現在の本人の施設条件にも適用できるときだけ。
- 古いタブ・キャッシュ・端末時計のずれにより、**全端末でリアルタイムに停止・更新される保証はない**。更新通知や新版検知の具体方式は追加設計が必要。安全側の判断ができない場合は施設固有の断定を控える。
- `needs_review`は運営が公式出典を確認中という状態。`needsRecheck`は本人のタスク進捗の再確認。出典の失効だけで本人の`completed`／`not_applicable`は書き換えない。

## 3. U03・U04

- U03は施設固有の断定が利用可能な場合のみ出典名・確認日・リンク・適用範囲を提示。
- 失効／未確認／破損の場合は「施設の利用条件は現在再確認中です。最新情報は施設管理者の公式案内でご確認ください」と表示し、一般のP01〜P12は維持。リンク自体が不確かならリンクを無条件に残さない。
- 最新版があると**確認できた場合に限り**「新しい情報を反映するには再読み込みが必要です」と案内。最新版があると推測で表示しない。
- U04の未保存ドラフトがある状態では、アプリが自動で強制再読み込みして入力を破棄しない。再読み込みに伴う入力喪失の注意を設計する。

## 4. 公開運用ゲート

1. 担当者が出典原ページ・対象施設・確認日・適用条件を確認し、別の担当者がレビュー。
2. 台帳の版を更新しGitへ記録。Vercel Previewで条件一致／不一致・失効時・差分を確認。
3. 本番リリース直前の出典確認も実施し、出典カタログとアプリ資産を**同じビルド版**として公開。
4. 新しい公開版の確認と利用者向け更新説明を整える。旧タブでの即時停止保証はしない。

## 6. 次に確認する事項

A案自体は採用済み。残る技術事項は**古いタブで最新版をどう検知するか**（自動検知と再読み込み案内／利用者の手動確認のみ）、時刻・時計異常への対処、ソースカタログ検証、版番号・U04ドラフト保護。これらを提案として整理し、実装前に必要な利用者判断だけ確認する。
