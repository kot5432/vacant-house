# STEP 3｜MVP機能の選定（2026-11-13・検討中）

> **まだユーザーによるSTEP3の最終確認前の提案書。** 本書は確定済みの[STEP1：対象と課題](STEP1_PROBLEM_TARGET.md)と[STEP2：中心価値](STEP2_VALUE_DIFFERENTIATION.md)から逆算して整理した。以前の「最初の一歩だけが主役」「相談文コピー必須」は見直す。**アプリの開発・利用者テストは未実施**。

## 1. 今回の設計原則
**初めて単発・小規模な非営利イベントや体験会を開きたい人**が、**必要な準備の全体像と現在の準備状況に合う優先順位**を理解することが主目的。高岡市の公的情報と最初の行動は、それを支える。

## 2. 機能候補と必要性（STEP3で一つずつ決定）
| 機能 | 推奨 | 理由・提示内容 |
| --- | --- | --- |
| F1. **最低限のイベント情報と現在の状況を入力** | **Must候補** | 開催の種類、個人/チーム、想定対象（子ども向けか等）、人数/日時/会場/担当の決定状況、必要設備。分からない項目は未定でよい。本人の困りごとを別設問では聞かない（⑬） |
| F2. **自分向けの開催準備の全体像を表示** | **Must候補：主役** | 企画条件、運営・安全、会場・手続き、募集・開催前の確認。各領域で必要/要確認/該当しない等を区別し、全員同じタスクを必須と断定しない |
| F3. **準備状況から優先順位と理由を示す** | **Must候補：主役** | 未確認事項・準備の依存関係・該当する施設の注意をもとに今優先する確認を示す。本人の困りごとは追加入力しない（⑬）。**最初の一歩だけの画面にしない** |
| F4. **該当する公的情報を根拠付きで表示** | **Must候補：補助** | 高岡市の公式情報に限り、条件・出典・確認日・まだ不明なことを明記。実際の許可/空き/安全の保証はしない |
| F5. **プランを持ち帰る方法** | **利用方式Aは確定・手段は未決定** | 1回で作成・持ち帰る。コピー/印刷などの具体方式は別途判断し、ログインや継続的な進捗管理は行わない |
| F6. **相談文の下書き・コピー** | **Should候補** | 「誰に何を聞くか」を助けるが、中心価値の提供には必須とまではいえない。STEP3内で別途判定 |
| F7. **既存施設/団体拠点/空き家の比較表示** | **Later候補** | 施設が主役になる旧アイデアと混ざらない。必要な公式情報へつなぐ程度から始める |
| F8. **募集・申込・参加者/スタッフ管理** | **今回対象外** | Peatix等の既存プロダクトが担う部分。開催準備の道筋と判断に集中する |

## 3. 「今の状況」の扱い
- 「決定済み」「未定」「確認が必要」「該当しない」を分ける。**入力がないこと＝不適格・危険**とは扱わない。
- 安全上の重要な確認（子どもの見守り等）は別枠で保持。**規則上の施設制限が該当する場合は見落とさせない**。
- 開催予定日や人数が未定でも先へ進める。具体的な開催許可・法律適合を機械判定しない。
- 何を先にすべきかは状況別の**提案**であり、全イベントに普遍的な唯一の正解として言い切らない。

## 5. STEP3-⑤「参加対象者」：確定（2026-11-13）
**ユーザーがAの4分類を採用：**
1. **子ども・未成年（18歳未満）**
2. **大人（18歳以上）**
3. **両方**
4. **まだ決まっていない**

- 質問は**「主に誰に参加してほしいイベントですか？」**。主催者の人数・年齢と**参加者の対象**を混同しない。
- 対象者が未定でもプラン生成に進める。参加者の氏名・連絡先・生年月日は集めない。
- **子ども・未成年**か**両方**なら、見守りや安全・責任体制・保護者連絡などの確認を準備プランに含める。**未定**なら必要性が未確認という扱いで、安心・安全を保証しない。
- 参加対象の選択から**主催者本人が未成年かどうかを推定しない**。特定施設の利用条件を参加対象だけから自動で判定しない。
- 対象学年・詳細年齢は今の必須入力にせず、必要なら後で検討する。

## 6. STEP3-⑥「参加予定人数」：確定（2026-11-13）
**ユーザーがA「具体的な人数の任意入力＋まだ未定」を採用。**

- 質問例：**「参加者は何人くらいを想定していますか？」**
- 数字が分かる人は**1以上の整数**で入力。未入力または「まだ未定」を許容する。小数、0、負数、異常に大きい数には適切な入力確認を設計する（上限は今は未決定）。
- この値は**参加者の想定人数**であり、主催者・スタッフ人数とは区別する。未定を0人と解釈しない。
- 準備プランでは、人数に応じて**会場定員、机・機材、スタッフ・見守りの体制などの確認事項**を表示する。人数が未定なら、まず規模を考える行動を示す。
- 人数から**会場が確実に借りられる、法的に許可が得られる、安全に運営できる**とは判定しない。

## 7. STEP3-⑦「開催希望時期」：確定（2026-11-13）
**ユーザーがA「日付が決まっている／月くらいまで決まっている／まだ未定」の3段階を採用。**

- 質問：**「いつ頃開催したいですか？」**
- **日付が決まっている**：年月日を入力する（例：2027-02-14）。
- **月くらいまで決まっている**：年月を入力する（例：2027-02）。具体的な開催日が決まったとは扱わない。
- **まだ未定**：日時の入力なしでプラン作成可能。
- 入力は**開催希望**であり、予約や許可が取れたことを意味しない。過去日や無効な日付を入力した場合の扱いはUIと判定仕様の段階で検討する。
- 日付が決定している人には会場の申込期間・準備上の期限を**公式情報で確認する**よう案内。具体的期限を推測して表示しない。
- 月単位の人には候補日の具体化と会場確認、未定なら開催時期の検討をプランの準備項目にする。
- 開催時間帯・所要時間などの追加入力は**未確定**であり、この決定には含めない。

## 8. STEP3-⑧「開催場所・会場の決定状況」：確定（2026-11-13）

**ユーザーがAの4分類を採用。** 質問：「会場・開催場所は、どこまで決まっていますか？」

| 選択肢 | 準備プランに反映する例 |
| --- | --- |
| **① まだ探していない／決めていない** | 会場の条件（規模・設備・アクセス等）の洗い出し |
| **② 候補はあるが利用は未確定** | 候補の利用条件・管理者・申込方法・承諾の確認 |
| **③ 利用する場所が確定している（本人申告）** | 当日の設備・定員・利用条件・動線の再確認。アプリが予約済み・許可済みと認定しない |
| **④ 物理的な会場は使わない** | オンライン等の場合は会場予約ではなく開催方法の確認へ。オンライン開催までMVPでどこまで支援するかは別途判断 |

- **会場の準備状況**と**開催地域**、**具体的な候補施設**は別の情報。これを1問で推定しない。
- 場所が確定していても、施設の利用が実際に認められるか、子ども向け活動が安全かどうかはアプリで保証しない。
- 旧空き家マッチング/物件診断/実際の施設予約は扱わない。

## 9. STEP3-⑨「開催地域の入力」：確定（2026-11-13）

**ユーザーがA：選択式の4分類を採用**。質問は「どの地域で開催する予定ですか？」で、**主催者の住所ではなく開催予定地域**を尋ねる。

1. **高岡市**
2. **富山県内のその他の市町村**
3. **富山県外**
4. **まだ決まっていない**

- 初期MVPで**高岡市の確認済み公式情報のみ**を地域固有案内に使用する。その他・県外・未定は一般的な準備ガイドとし、地域固有情報の未対応を明記する。
- GPS、正確な住所、主催者の居住地は不要。**未定でもプラン生成へ進める**。
- **高岡市を選ぶだけで高岡市地域交流センターを利用していると推定しない**。公式の施設固有条件は、**対象施設の本人選択、関係する主催者の条件、公式出典の適用範囲**がそろう場合のみ表示する。
- 物理的会場を使わないイベント（オンライン等）に地域の入力をどう扱うかは、オンライン支援範囲を決める際に再検討する。開催市町村をでっち上げない。

## 10. STEP3-⑩「候補施設の入力方法」：確定（2026-11-13）

**ユーザーがA「確認できる施設カテゴリの選択＋任意の施設名メモ」を採用。**
- **表示条件**：STEP3-⑧の会場状況が「候補あり（利用未確定）」または「利用場所が確定している」のとき。会場未定・物理的会場なしでは尋ねない。
- **高岡市を開催地域に選んだ場合の選択肢**：「高岡市地域交流センターを検討している」「それ以外の会場」「種類が分からない」。**施設名は任意の本人用メモ**。
- **高岡市以外・開催地域未定の場合**：高岡市の施設固有選択肢を誤適用しない。必要に応じて任意の施設名メモを表示し、一般的な「会場管理者と利用条件の確認」を案内する。
- **判定に用いるのは本人が明示的に選んだ施設カテゴリのみ**。自由記述の施設名からルールや施設適合性を推定しない。施設の予約・承諾・安全性を保証しない。
- 高岡市地域交流センターについても、**個々の施設の利用可否・承認・設備は各センターで確認**する。施設名が任意欄に入力されたことを「予約できた」証拠にしない。
- **本人の住所・GPS・他人の個人情報を収集しない**。施設の種類の追加は出典を確認できたときに別途検討する。

## 11. STEP3-⑪「運営責任者と該当施設の利用者年齢構成」：確定（2026-11-13）

**ユーザーがA「全員に責任者の決定状況を確認＋施設固有の条件に関係するときだけ年齢構成を確認」を採用。**

- **全員への質問**：「イベント運営の責任を持つ人は決まっていますか？」→「決まっている／まだ決まっていない／分からない」。氏名・連絡先の入力は不要。一人主催でも本人が担当するものと決めつけない。
- **該当者のみへの質問**：⑨**高岡市**＋⑧**候補あり／場所確定**＋⑩**高岡市地域交流センター**の明示選択時に、「そのセンターを利用する人は未成年者だけの予定ですか？」→「未成年者のみ／成人を含む／まだ分からない」。
- **データの分離**：主催者の年齢構成、イベント参加対象者、施設を実際に利用する人の範囲は同一とは限らない。施設規則にいう「利用」の解釈があいまいなら管理者へ問い合わせる。
- **出力の目的**：責任者が未定なら「担当と責任体制を整理」を提示。高岡市地域交流センターで未成年のみを想定する場合は、**その施設の公式共通注意と管理者への確認**を優先して示す。成人を含む場合でも「利用可能」と断定しない。
- 公式出典の対象と確認日を表示し、公的条件・一般的な注意・個別の許可判定を分ける。その他の公共施設や民間施設に同条件を拡大しない。
- 子どもの参加があるなら、責任者・施設の回答によらず見守り・安全・保護者への案内などの確認を残す。
- **正確な年齢・生年月日・氏名など個人情報は収集しない**。最新の施設条件は公開・実装前に改めて確認する。

## 12. STEP3-⑫「必要設備・備品」：確定（2026-11-13）

**ユーザーがA「簡単な質問＋該当者だけ任意の設備複数選択」を採用。**

- 質問は「会場や準備で、必要だと思う設備・備品はありますか？」。回答は**「ある／特に思いつかない／まだ分からない」**。最初から詳細備品リストを要求しない。
- **「ある」の人のみ**、任意の複数選択として「机・椅子／電源・インターネット／PC・映像・音響／その他」を出す。未入力でもプランに進める。具体的な台数や費用、購入先は必須にしない。
- 選んだものは**必要と本人が考えている設備**であり、「確保済み」「会場側にある」ことを表さない。選択に応じ、会場の設備・持込み可否・必要数量の**確認タスク**を提示する。
- **会場未定**なら会場の選定条件、**候補あり・会場確定（本人申告）**なら設備の有無と使用条件の確認につなげる。
- 「特に思いつかない」「まだ分からない」を「設備不要」や「安全」とは判定しない。公的な会場条件・調理や火気などの専門的な利用可否を、この設備入力だけで判定しない。
- **採用が確定しているのは入力方式Aとその設問内容**。詳細な表示タイミング・必須性・画面数は今回の棚卸しで改めて検討する。

### 13.2 問題点の優先順位

1. **入力が長く、価値を見る前に離脱するリスク**：中心価値は最初の全体像・優先順位。9件の質問を初回に一列に並べると準備管理ツールに近づく。短い入力でまず全体像を出す案を検討する。
2. **④主催形態と⑪運営責任者が心理的に重複**：両者は違う情報だが、同一の「体制」カードにまとめると意味を説明しやすい。**回答の一方から他方を推測しない**。
3. **⑥予定人数と⑫備品は未定でも進める**：質問自体は採用済みだが、最初の概要に必要な情報より後に尋ねる、または任意詳細入力として扱う改善余地が大きい。
4. **当初の検討上の不足**：③〜⑫に「いま困っていること」の入力はない。これは⑬で**追加入力しない方針をユーザーが採用**した。本人が何を最も不安に思うかは判断できず、提案は**入力された客観的条件に基づく優先順位**に限定する。
5. **内容説明が判定に使われない**：②の自由記述は本人用表示であり、文章を解析して専用の手続きを断定しない。したがって「その他」などでは汎用ガイドにとどまることを明示する。
6. **オンライン・高岡市以外**：⑧「物理的会場なし」と⑨「高岡市以外」を選んだ人の地域固有情報は対象外・未対応となる場合がある。対応範囲を明記し、関係ない地域の規則を出さない。
