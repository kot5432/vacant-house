# ADR-021｜バックアップ書き出し画面は初期未選択・100件以内だけ全選択可能（A案正式採用）

決定：2026-11-15。利用者が[STEP7-⑰](STEP7_17_EXPORT_SELECTION_UI_OPTIONS.md)の**A案を正式採用**。現行の地域イベント開催準備支援Webアプリのみを対象とする。旧空き家所有者・物件・マッチングのデータ／機能は使用しない。**設計のみ、実装・実機テスト・デプロイは未実施**。

## 1. 正式に採用したU01選択動作

1. 「バックアップを書き出す」画面を開いた直後は**選択イベント0件、すべてのチェックはオフ**。以前の書き出しでの選択、ブラウザ別タブの選択を黙って引き継がない。
2. **現在の保存済みイベント総数が1〜100件であれば「すべて選択」が利用可能**。選んだ全件が2 MiB以内とは限らないため、最終的な完成JSONバイト長の検証は別途実施する。
3. **保存済みが101件以上の場合、「すべて選択」は使用できない**。理由と「対象イベントを個別に100件まで選択してください」と表示し、本人による個別チェックを可能にする。上から100件を自動選択しない。
4. 個別選択は**最大100件**。100件選択済みで101件目を押しても、既存の100件のチェックを解除・別件へ置換しない。追加できない理由を、入力近くと選択件数欄で伝える。
5. **0件選択時の「書き出す」は無効**とし、0件を理由なく空JSONへ変換しない。すべての選択を解除する操作を提供する。
6. **常時「選択X件／保存済み総数Y件／今回のファイルに含まれないY-X件」**を表示し、書き出し前に対象イベント一覧を確認できる。バックアップファイルをローカルへ保存するため、任意メモを含む可能性も案内する。
7. 1〜100件選択でも、完成したUTF-8 JSONが**2,097,152バイトを超えたら出力禁止**。選択を減らして再試行する導線と容量超過理由を示す。無断でフィールドやイベントを切らない。
8. 選択後に別タブで対象イベントが削除・変更された場合、古い選択をそのまま正しいものと見なさず、**対象一覧と選択の再確認**を求める。

## 2. 選択状態とバックアップのデータ境界

- 選択は**一時的なUI状態**（設計上は`selectedEventIds: Set<eventId>`）。本人のEventRecordや進捗・revisionを書き換える操作ではなく、インポートしたことの履歴とも別。
- 画面を開いたときに保存済みイベント一覧を読み、その時点の総数に基づいて全選択の利用可否を判断。別タブで総数が101件以上になった場合は、選択を黙って縮小せず最新状態を示して再確認する。
- 書き出し確定時は選択IDの全件存在を再確認し、**保存成功済みの一貫したEventRecordスナップショット**だけをBackupEnvelopeに含める。U02初回未完成・U04ドラフト・U03未コミットの差分を保存済みとして書き出さない。
- 1ファイルにつき**100件・2 MiB両方**を遵守（[ADR-019](ADR_019_JSON_BACKUP_LIMIT_2MIB_100_EVENTS.md)）。上限を超える場合は本人が選び直し、残りは別操作で出力（[ADR-020](ADR_020_MANUAL_EVENT_SELECTION_EXPORT.md)）。分割済みファイルの網羅履歴・自動複数ファイル化はMVPに導入しない。
- ファイルの生成／ダウンロード開始は端末にファイルが確実に保管された証明ではない。成功文言を区別する。

## 3. U01のUI文言案

- 初期：「書き出すイベントを選択してください。選択中 0件／保存済み 5件」
- 150件の場合：「保存済みイベントが100件を超えているため『すべて選択』は使えません。書き出すイベントを100件以内で選択してください」
- 100件選択済み：「1ファイルの上限は100件です。別のイベントを入れるには、選択を1件解除してください」
- 最終確認：「このファイルにはX件を含み、Y件は含みません。選択したデータには任意メモが含まれます」
- 容量超過：「選択中のデータが2 MiBを超えています。イベントを減らして再試行してください。保存済みデータは変更されていません」

文言は仮案で、実機のアクセシビリティ試験で修正できる。**初期未選択と100件以内だけの全選択は正式な仕様**。

## 5. 次の実装前の判断

**JSONバックアップの互換バージョン範囲**（同じ版だけ／既知旧版も取り込む／将来版に広く寛容にする）の比較を[STEP7-⑱](STEP7_18_BACKUP_VERSION_COMPATIBILITY_OPTIONS.md)に用意。バックアップ版とイベントDB版の相違、移行がデータの意味を変えないことを明示する。文字数・個別項目の技術バイト上限、時刻異常、P01〜P12のルールカバレッジと公式出典原ページの最新点検は引き続き残件。
