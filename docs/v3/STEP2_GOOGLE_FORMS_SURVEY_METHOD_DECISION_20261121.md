# STEP2｜需要検証はGoogleフォームを採用（2026-11-21）

- **決定**：ユーザーはSTEP2の調査方法としてA案「Googleフォームでアンケート」を採用。まずフォーム回答を集め、必要なら一部の回答傾向について追加検討する。
- **目的**：参加側（地域活動の情報発見と参加条件）と初主催側（準備の順序・不足情報）の**実際の経験・困りごと**を別々に把握し、需要仮説を検証する。
- **既存キット**：[USER_VALIDATION_INTERVIEW_SURVEY_PACK_20261119.md](USER_VALIDATION_INTERVIEW_SURVEY_PACK_20261119.md)を質問設計の出発点とする。参加/主催の両方を全員に強制せず、Googleフォームのセクション分岐で回答負担を抑える。
- **設問案（正式版はレビュー後）**：共通（過去半年の行動・探した手段・参加/主催の立場）、参加分岐（最近の活動・探して困った情報・実際の対応・必要だった情報・既存手段で十分だった点）、主催分岐（開催経験・活動内容・準備で困った点・最初に取った行動・既存資料で十分だった点）、最後に自由意見（任意）。
- **設問設計原則**：実際の行動→具体的な障害→現在の代替手段を先に聞く。「このアプリが欲しいか」の誘導やポジティブ回答のみの収集を避ける。『困らなかった』『探していない』『その他』『答えたくない』を必要に応じて設ける。参加者が将来主催したいかは任意の補足質問として扱い、強制しない。
- **配布・保存の前に決める**：対象者と配布先、回答人数の目安、学校/チームの調査ルール、未成年の任意同意、回答保存先・閲覧者・保存期間・削除手順。氏名・メールアドレスは原則収集しない。回答者のGoogleログインを必須にしない設定を検討。
- **状態**：調査方法のみ確定。フォームは未作成、未配布、回答0件（実収集未実施）。正式な質問文・配布文・設定はこれから利用者と確認。アプリ実装・実行テスト・公開なし。
