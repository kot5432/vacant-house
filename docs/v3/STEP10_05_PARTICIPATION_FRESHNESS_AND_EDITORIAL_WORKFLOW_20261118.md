# STEP10-⑤｜参加活動の情報鮮度・停止・「次の一歩」契約 v0.4（2026-11-18）

**状態：実装前の運用・技術設計案。** ADR-030の「参加3画面＋主催4画面」は採用済み。ただし更新頻度と活動の掲載審査は担当レビューが未完了。コード・実行テスト・CI・公開・主催者への連絡なし。

## 1. 解決したい矛盾
公開サイトで`2026-11-18`に「受付中」を見つけても、`2026-11-19`にも受付中とは保証できない。出典データの`recruitment=confirmed_open`（確認**時点**の事実）と、アプリの`effectiveDisplay`（表示**時点**に安全に言えること）を区別する。単純な`verified`フラグを「現在募集」と表示しない。

## 2. 保存事実と導出状態

| 別々に保持する情報 | 事実で表せること | 表示時の扱い |
|---|---|---|
| `source.checkedAt` | 最後に原ページを人が確認した時刻 | 「最終確認日時」として表示 |
| `source.reviewStatus` | 人による掲載審査の状態 | needs_review/archivedは現在の募集確定として表示しない |
| `recruitment.state` | 人が確認した時点の`confirmed_open/confirmed_closed/unknown` | 状態のみで最新の応募可否を認定しない |
| `recruitment.checkedAt` | 受付情報の確認時刻 | 参加条件の更新日時と混同しない |
| `schedule.type/date` | 単発/定期・公開日程の確定程度 | 過去の日付で再募集を推測しない |
| `effectiveDisplay` | 上の根拠と評価時刻からの表示用の判定 | 元カタログを本人の操作で書き換えない |

## 3. 更新期限は「募集受付中」という強い表示と連動

### 推奨する保守的な初版案（別レビュー前）
- 初回MVPは**検索結果と詳細画面に「現在受付中」の断定的な見出しを原則使用しない**。一次出典に記録された事実を`確認日時付き`で提示し、常に「参加条件と最新受付状況は公式案内で確認」を次の行動にできるようにする。
- `confirmed_open`はカタログの監査用事実として保持できるが、**現在も受付中というライブな状態保証には使用しない**。日数閾値（24時間/7日等）を制定するまで待たなくても誤認を防げる。
- 開催・募集終了が**確定**したら`ENDED/CLOSED`を優先。公式が再募集を掲載した場合は別レビューで状況を更新。
- 定期活動は開催予定日時がないとき、次回開催を予測・自動計算しない。確認日が過去なら「次回日程は公式で確認」。
- 出典リンクが切れた場合は個別活動カードを掲載保留/要確認へ。元の公式ポータル等の安全な一般案内先を別途用意。
- 公開前の掲載確認・その後の点検は、**実際に担当できる4人の誰かが責任を持つ**ことを前提。責任者未割当なら公開時の確認済み募集表示をしない。

### なぜ日数で自動合格させないか
募集状態はいつでも変化し得る。前日に確認しても空き・参加資格・最新募集を保証しない。過去にチェックした資料の信頼性は「確認時点の信頼度」であって今の参加保証ではない。

## 5. 管理・点検の手順（1活動につき）
1. D担当（仮）が原ページを開いて活動名、主体、地域、日程・参加条件・費用・公式URLを転記し、**不明欄を空でなくunknown**にする。
2. どの記載を確認したかと確認日時を台帳に記録し、写真・個人の非公開連絡先を転載しない。
3. B担当（仮）が別人レビューで、募集の断定や「初参加歓迎」の根拠のない書き換えがないかを確認。
4. 公開する版`catalogVersion`と掲載状態を固定。リンク不通や更新不能となったら次版で`needs_review/archived`へ切替える。**自動更新したと宣言しない**。
5. 本人による企画EventRecord・U03進捗・JSONバックアップには触れない。
