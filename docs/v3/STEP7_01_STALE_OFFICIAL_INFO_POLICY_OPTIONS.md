# STEP7-①｜公式出典の月次点検が未実施だった場合の掲載方針比較

作成日：2026-11-15。**提案・利用者未承認。** ADR-009では「月1回＋毎本番リリース前の点検」が正式採用済み。本書は**その頻度を変更せず、予定どおり点検できなかった場合の画面表示**だけを検討する。現行イベント準備支援Webアプリ専用。旧空き家／所有者／物件／マッチングは対象外。実装・テスト実行・現行公式サイトの再照合は未実施。

## 1. 決定が必要な理由

月次点検の予定日を過ぎても、例えば担当不在・元ページの取得不能・確認結果のレビュー未完了等で未実施の場合がある。現行の台帳には`checkedAt`と`status=verified/needs_review/suspended/retired`がある。**「前回確認した時点では正しい」と「今月も確認済み」は異なる**。画面が古い情報を正しいものとして断定しないため、未点検時の扱いを明示する。

## 2. 3つの案

| 案 | 月次点検の期限を過ぎた場合 | 利点 | 注意 |
|---|---|---|---|
| **A（推奨）** | **期限到来時点で対象出典をneeds_reviewとして扱い、施設固有の断定文を停止**。一般確認・公式リンク案内に切替 | 古い根拠を確実に断定しない | チーム側の一時的な未点検でも専用案内が消え、利用者体験に影響 |
| B | 期限から7日間は`verified`を維持し、超過でneeds_reviewに移す | 作業都合で一時的に遅れても余裕 | 7日の期間に根拠を再確認せず掲載する。猶予は制度上の根拠がない |
| C | 期限経過後も`verified`を維持し、次の点検まで確認日を表示し続ける | 情報が途切れない | 未点検の情報がいつまでも残る可能性 |

**共通**：元ページの明確な改定・誤案内・施設条件の不一致を把握した場合は、期限前・猶予期間中でも`needs_review/suspended`にして断定を止める。

## 3. A案採用時の細かな仕様（すべて提案）

- 「月1回」の期限の数え方は**暦月単位**とし、前月中の最終確認後、次月分の確認がないまま当月の点検予定日を過ぎたら期限超過とする案。月末最終日・休日の扱いは、採用時に決める。
- 出典の実地確認が完了しても、2人目のレビュー未完了なら`verified`に戻さず`needs_review`を維持。
- 出典失効の確認はアプリ同梱の静的データだけで自動的に知ることができない可能性がある。**月次の運用チェックで台帳を更新し、次の公開版へ反映する**のが基本。ブラウザの旧タブへ即時停止を保証しない。
- 状態を戻すときは原ページ・施設カテゴリ・対象条件・表示文言の再確認とレビューを実施し、`sourceRevision`を更新する。
- 利用者へ「施設の利用条件は現在再確認中です。最新情報は施設管理者の公式案内をご確認ください」と表示し、確定的な期限・許可可否は表示しない。
- 遅延があった事実と復旧時刻を台帳へ記録する。点検していないのに`checkedAt`を更新しない。
- 本番リリース前の点検は月次点検と独立して必須。リリース前に未点検であれば公開ゲート不合格とする案。

## 4. 設計・テストの受入観点

| ID | 状況 | A案なら期待 |
|---|---|---|
| STALE-01 | 月次点検期限を過ぎて未点検 | needs_review相当、該当施設の断定停止 |
| STALE-02 | 当月確認が済み、レビューも済み | verified維持、対象条件一致時に表示 |
| STALE-03 | 原ページが読めず未検証 | needs_review、古い説明を断定しない |
| STALE-04 | 未点検中に明確な誤案内を発見 | 即時suspended相当へ判断 |
| STALE-05 | 再確認＋レビュー完了 | verifiedに戻して新版の対象条件を再評価 |
| STALE-06 | 旧タブの配信物 | 即時反映を保証できないと明記し、更新通知／版検出の技術検証対象 |
| STALE-07 | 本番リリース直前に未点検 | リリースゲート不合格、根拠の見直しが必要 |
| STALE-08 | 関係ない施設やタスク | 無関係の公式出典と進捗を一律に停止しない |

## 5. ここまでの設計との整合

- ADR-009の月次・リリース前の頻度を変更しない。
- ADR-004の本人による再確認解除の操作を変えない。
- ADR-005の施設固有入力クリア、ADR-002の物理会場なし一般確認を変更しない。
- 公式出典の`needs_review`は**運用側が出典の正確性を再検証する状態**であり、ユーザーの進捗`needsRecheck`とは別。

## 6. ユーザーへ確認する点

**月次点検の期限超過時の対応はA案（推奨）／B案（7日猶予）／C案（期限超過しても確認日付きで表示継続）のどれを採用するか。** A案は情報の古さに慎重で、小規模な出典台帳なら運用設計もしやすい。一方で出典がない時期は一般案内にフォールバックするため、施設固有の案内量が減る。
