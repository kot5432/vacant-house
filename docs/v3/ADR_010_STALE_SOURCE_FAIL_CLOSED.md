# ADR-010｜月次点検期限超過時の施設固有断定の停止（A案正式採用）

決定：2026-11-15。ユーザーが「期限を過ぎたら施設固有の断定を停止し、一般確認案内へ切り替える」A案を明示採用。**現行の地域イベント準備支援Webアプリ専用。旧空き家物件・所有者診断・マッチングは対象外。設計のみで実装・試験・公開は未実施。**

## 1. 正式決定

1. [ADR-009](ADR_009_OFFICIAL_SOURCE_MONTHLY_RELEASE_REVIEWS.md)の**月1回＋毎本番リリース前＋初回掲載前の公式原ページ確認**を維持する。
2. 対象出典の**予定された月次点検期限が過ぎ、点検・必要なレビューが完了していない**とき、当該出典は`needs_review`相当として扱い、**施設固有の断定表現を停止**。確認すべき一般項目と、確認可能な公式案内への導線を残す。出典そのものに問題の疑いがある場合、リンク先の安全性や有効性を確認できなければそのリンクも無条件に表示しない。
3. **猶予期間を設けない**。7日間は無条件で表示する案、および古い情報の掲載を無期限に継続する案は不採用。
4. 点検未完了を「確認済み」と記録しない。`checkedAt`は実際に原資料を確認した日時とし、予定日／リリース日で書き換えない。
5. 原ページ・適用範囲・文言を再検証してレビューが完了した場合にだけ`verified`への復帰を許す。過去の本人の`progress.status`は変更せず、出典が変更された影響タスクだけ再確認を検討。
6. `needs_review`（出典管理の状態）と`needsRecheck`（本人タスクの再確認状態）は**異なるもの**。出典停止だけで本人の完了を取り消さない。
7. 最新版を開いていない古いブラウザタブや静的ファイルには**即時に停止が反映される保証がない**。リリース手順、更新検知・再読み込み、未更新の注意表示は公開前に別途設計・検証。

## 2. 表示ゲート

| 状況 | 個別施設の断定文 | 一般準備プラン | メッセージ |
|---|---|---|---|
| 点検期限内、原ページ・対象条件とも検証済み、`verified` | **対象一致時のみ表示** | 維持 | 公式出典と最終確認日を提示 |
| 期限超過、月次点検未完了 | **表示停止** | 維持 | 「この施設の利用条件は現在再確認中です。最新情報を施設管理者の公式案内でご確認ください」 |
| 原ページ閲覧済みだが必要なレビュー未完了 | **表示停止** | 維持 | 再確認中と表示 |
| 明らかな誤案内・リンク改ざん等の疑い | **表示停止**、必要ならリンクも停止 | 維持 | 確認先の案内のみ |
| 廃止済み・対象外 | **表示しない** | 維持 | 必要に応じ一般確認 |
| 再確認・レビュー完了 | 現行条件と一致した場合のみ再掲 | 維持 | 新しい確認日・対象条件を提示 |

## 3. 運用する期限の定義と未決部分

- 正式に決まったのは**「月次点検の期限超過時点で猶予なく停止する」**という表示方針。月内の具体的な点検日（例：第何営業日）は**まだ選択されていない**。
- 点検日・休日・担当不在時の代行方法を確定した後に、台帳へ`reviewDueDate`または同等の明示的な期限を追加する案を推奨する。**確認日から30日と機械的にみなすことは未採用**。
- 日付判定に使う基準の暦日とタイムゾーン、同じ日を含むか、レビュー完了時刻の基準は実装前の技術契約で定義する。月次予定日が未登録の場合は期限内と**推定してはならない**。運用状態を`needs_review`として扱う、という安全側の提案は次段のデータスキーマ決定で審査する。
- 静的Viteアプリに`reviewDueDate`と`checkedAt`を同梱して表示時に再評価する方式と、運用担当者が期限超過時に新版を発行する方式は併用可能。ただし現行の静的配信で旧タブ・時計ずれ・更新失敗に対して完全な停止保証はない。
- 出典の更新と利用者のイベント内容を**外部へ送信する設計ではない**。外部の情報収集は運用担当が原ページを確かめる仕事であり、ユーザーデータの送信ではない。

## 4. 設計テスト（期待値のみ、未実行）

| ID | 状況 | 合格条件 |
|---|---|---|
| STALE-A01 | 月次点検期限前かつverified・対象一致 | 出典の確認日と対象範囲付きで表示可能 |
| STALE-A02 | 月次点検期限超過・未点検 | 施設固有断定を即時停止、一般確認は維持 |
| STALE-A03 | 期限超過直後（猶予なし） | 7日猶予や無期限掲載はしない |
| STALE-A04 | 原ページだけ確認済み・二人目レビュー未完了 | verifiedに戻さず断定停止 |
| STALE-A05 | 原ページが改定・リンク切れ | 期限前でも出典停止へ |
| STALE-A06 | 再確認とレビューが成功 | 版と確認日・適用範囲を更新し、適用条件一致時のみ再掲 |
| STALE-A07 | 現行条件が別施設・別地域 | ほかの施設の内容へ流用しない |
| STALE-A08 | 点検遅延で出典停止、本人P08はcompleted | completedは保持し、自動未着手へ戻さない |
| STALE-A09 | 古いブラウザタブ・配信更新不可 | 即時全端末停止を保証したと表示しない |
| STALE-A10 | 月次点検予定日が未設定 | 期限内と推測してverified表示しない（安全側の詳細設計案） |

## 5. 承認済みと次の課題

**正式採用**：点検期限を越えた施設固有断定の即時停止、猶予なし、一般プラン維持、原資料と適用条件の再確認後だけ復帰。**別途未決**：月内の期日、担当・代行、reviewDueDateの保存形式、期限境界、アプリが古い版の際の警告方法。これらは根拠情報・責任分担を含めて設計で次に具体化する。
