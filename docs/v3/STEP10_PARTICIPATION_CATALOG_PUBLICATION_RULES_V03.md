## 1. カタログの必須条件・厳密な出典の管理

| 項目 | 初版の提案契約 | 公開前のレビュー |
|---|---|---|
| catalogVersion | `YYYY-MM-DD.N`形式の公開カタログ版（提案） | 誤更新・将来移行をしない運用を確認 |
| listingId | 重複しない固定の非個人識別子 | 同じ告知と同じ活動を重複登録しない |
| activityTitle | 団体が公開している正式名称 | 原ページと照合 |
| organizerDisplayName | 公開された団体名のみ | 個人名・個人の電話/emailは載せない |
| municipality | 公開一次ソースで明示された市町村名 | 不明なら不明のまま |
| topicTags | `children_education/community/culture_crafts/environment/other`（案） | 分野推定の誤りをレビュー |
| scheduleType | `single_date/date_range/recurring/unknown`（案） | 定期行事の次回開催を作り出さない |
| scheduleText | 出典にある日付・時刻のみ、確認できない部分は不明 | 年や曜日を補完しない |
| currentRecruitment | `confirmed_open/confirmed_closed/unknown`（案） | 最新の募集受付を自動認定しない |
| primarySourceUrl | 正確な個別活動の一次URL | リンクが活動詳細へ通じるか |
| verification | 公開元・人の実確認日時・レビュー者・再確認状況 | 監査できるメモを記録する |
| fieldEvidence | 後述の初参加8項目 | 公式にない歓迎/無料/資格を推測しない |

## 2. 参加詳細での8項目

| D02表示の項目 | データ上の状態 | 必須表示/省略 |
|---|---|---|
| 開催日・場所 | `confirmed/unknown/not_applicable` | 不明なら「開催情報を公式ページで確認」 |
| 参加対象・年齢条件 | 同上 | 未記載なら「参加条件は未確認」、本人に属性入力させない |
| 参加費 | 同上 | 未記載なら「費用は未確認」 |
| 参加方法/申込要否 | 同上 | 公式へのリンクのみ。自前申込なし |
| 所要時間 | 同上 | 未記載なら非断定の「未確認」 |
| 持ち物 | 同上 | 未記載＝不要ではない |
| 初参加歓迎 | 同上 | 未記載＝歓迎と断定しない |
| 一人で参加可能か | 同上 | 未記載＝可能と断定しない |

**データ品質ルール**：`confirmed`には原URL・根拠確認日・資料で明示された値が必要。falseとunknownは別（例「初参加歓迎ではないと明記」vs「歓迎の記載なし」）。not_applicableは根拠なしで指定しない。内容を直接転記しすぎず要約・公式リンクに留める。

## 3. 次の一歩の判定表（案）

| 先行条件 | 画面に出す結論 | 外部へのリンク |
|---|---|---|
| 情報元不明/誤リンク/公開主体不明 | 掲載保留。D01には確認済み活動として出さない | 推測URL禁止 |
| 開催終了が確定 | `ENDED`：終了した活動と明示 | 参照として原ページ（あれば） |
| 募集終了が確定 | `CLOSED`：受付終了 | 申込可能とは表示しない |
| 確認期限を過ぎた/募集状態不明 | `VERIFY_STATUS`：最新の開催・募集状況を確認 | 原ページ |
| 参加条件・費用・申込方法が不明 | `VERIFY_REQUIREMENTS`：不足項目を列挙し公式情報を確認 | 原ページ |
| 申込方法が確認できる | `READ_OFFICIAL_GUIDE`：公式案内に進む | 公式の個別案内 |
| 上記のどれにも該当しない | `NO_VERIFIED_NEXT_ACTION`：確認できる案内がない | 無理にCTAを出さない |

**優先順は上から。** 未確認の項目が複数あるときも1つの第一歩＋補助のチェック項目を表示。ルール自体は主催P01〜P12のpriorityとは完全分離。

## 4. 更新と掲載停止の運用表（提案であり自動更新機能ではない）

| イベントの種類 | 点検のタイミングの提案 | 情報が古い場合 |
|---|---|---|
| 単発・締切あり | 初回掲載前、募集状態が変動する可能性があるため公開直前に再確認 | `confirmed_open`を無条件に維持せず`unknown`へ |
| 定期・随時の活動 | 最初の掲載時に確認、以後の更新担当が周期を設定 | 次回開催日は確認できない限り不明 |
| 公式索引・相談窓口 | 出典更新のタイミング/定期点検の計画 | 掲載先のリンクと内容を要確認へ |

- 主催側の行政出典に採用した**月末JST点検の既決ADRを、この参加募集カタログの自動期限と混同しない**。
- 参加側の点検担当がいないとき、募集状態の断定をしない。掲載撤回依頼の連絡手段・誤記訂正フローは公開前に決める。
- コンテスト用の録画は最新募集を保証する証拠にならない。デモ用架空データは明示的に「架空」と表示し、実在の募集と区別する。
- 公開URLと画像等の転載利用許諾は別。写真の無断転載や施設関係者の承諾を推測しない。

## 5. 主催側との結合禁止事項

1. 参加活動の`schedule`と主催`input.date`は異なるデータモデル。主催側`input.schedule`は作らない（ADR-029）。
2. 参加イベントを「企画」に変える操作は**通常の新規U02**。値の自動複製、黙ったイベント保存はしない。
3. 参加閲覧履歴・お気に入りを既存EventRecord/BackupEnvelope v1に足さない。
4. 参加カタログを更新しても主催の進捗、本人の対象外判断、再確認状態は変えない。
5. 参加の募集状態と主催の優先順位を同じP1/P2/P3で表さない。
