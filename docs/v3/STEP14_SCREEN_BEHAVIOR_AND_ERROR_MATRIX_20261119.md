## 明示的な状態遷移
- `idle→saving→saved`／`idle→saving→error`。保存中の二重送信を避ける。
- 保存完了の表示は**DB確定後**。UI上の仮変更と保存済み値を分ける。
- U03の`completed + needsRecheck`は「以前完了、条件が変わったため再確認」と文章で示す。完了を勝手に取り消さない。
- ユーザーの`not_applicable`とルール由来の`applicable=no`は視覚的に区別する。
- 公式出典期限切れは施設固有文を一般確認へ戻すだけ。P08=P2のまま、本人進捗/revisionは無断変更しない。
- D02→U02は既存活動のコピーモードではなく**完全な新規未保存草稿**。
- D01/D02とU01/U03/U04の状態は分離。参加側の更新がIndexedDB変更を起こさない。

## アクセシビリティと画面狭幅の設計受入
- 320px幅/200%拡大で主操作・エラー・出典確認日・次の一歩・理由が切れない。
- Tab/Enter/Space/Escapeで主要機能を利用、フォーカス状態が見える。
- 色のみでP1/完了/未確認/エラーを伝えず文章も付ける。
- 動画デモ用の見かけの活動データには「例示」と明記。確認していない活動を公開候補として装わない。
