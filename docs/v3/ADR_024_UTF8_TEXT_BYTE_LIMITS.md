# ADR-024｜任意テキストにUTF-8技術バイト上限を追加（A案正式採用）

決定日：2026-11-15。利用者が[STEP7-⑳](STEP7_20_TEXT_BYTE_SAFETY_LIMIT_OPTIONS.md)の**A案**を明示採用。対象は「初めて単発・小規模の地域イベントを主催する人向け準備支援Webアプリ」のみ。旧空き家所有者・物件・マッチングを対象としない。**設計文書だけ更新。コード実装・実行テスト・Vercel公開なし。**

## 1. 正式に決定した閾値

| 入力 | 保存フィールド | 書記素数上限（ADR-008維持） | UTF-8実バイト上限（本ADR追加） |
|---|---|---:|---:|
| 施設名の任意メモ | `venueNameMemo` | **100書記素** | **4 KiB = 4,096バイト** |
| イベント説明（任意） | `eventDescription`（実データ設計の命名と要照合） | **500書記素** | **16 KiB = 16,384バイト** |

**両方の上限を独立に満たす**。見た目の文字数（書記素クラスタ）とUTF-8のバイト数は別で、文字数上限をバイト数に置き換えない。上限ぴったりは有効、1書記素／1バイトでも超えたら保存前にエラー。無断切詰め・自動削除・別文字への置換はしない。

## 2. 文字数・サイズの計算契約

- 書記素数は[ADR-014](ADR_014_MAJOR_DESKTOP_MOBILE_BROWSER_SUPPORT.md)で検証対象とした現行主要ブラウザで`Intl.Segmenter('ja',{granularity:'grapheme'})`を第一候補とし、実機で一致を検証する。非対応時に**黙ってUTF-16の長さへ切り替えない**。
- UTF-8実バイト数は**フィールドの文字列をUTF-8に符号化した長さ**（実装候補は`TextEncoder`）。JSONの引用符・バックスラッシュ・エスケープ等を含む**完成JSONファイル全体の2 MiB上限は別**で、どちらも守る。
- 日本語IMEの変換中には`maxLength`による強制切断やエラー確定をしない。文字が確定した段階で書記素数・バイト数の違反を表示し、**保存は拒否するが編集ドラフトを保持**。U04編集では明示保存が成功するまで既存イベントを不変とする。
- 文字列の異常に長い結合文字・ZWJ絵文字・結合濁点・肌色修飾・改行・サロゲート周辺の扱いをテストし、**UIカウンターと保存前・JSON復元の検証で同一ルール**を使う。入力を黙って正規化・切断しない。

## 3. 書出しとインポートの安全境界

- **エクスポート**：保存済みイベントを無断切詰めせず出力する。既存レコードが新しい制限を満たさない場合でも**一部除外して「バックアップ完了」と偽らない**。その取扱いは旧版互換ポリシーを踏まえた別の技術設計課題とし、上限に適合しないレコードの原因を説明する。
- **インポート**：ファイルの物理容量2 MiB・100件、`formatId/exportSchemaVersion/eventSchemaVersion`検証後、**全イベントの任意フィールドに書記素数とUTF-8フィールドバイト上限を適用**。1件でも超過したら自動切詰め・一部復元せず**ファイル全件拒否、既存DB無変更**。
- 安全に検証可能な既知旧版でフィールド意味を保持した移行ができる場合のみ、[ADR-022](ADR_022_BACKUP_KNOWN_VERSION_COMPATIBILITY.md)に従う。旧形式の長文を勝手に切り詰めて現行形式へ合わせない。
- エクスポート／復元で元の入力・進捗を守り、[ADR-015](ADR_015_JSON_BACKUP_EXPORT_IMPORT.md)〜[ADR-023](ADR_023_BACKUP_TIMESTAMP_STRICT_WITH_FUTURE_WARNING.md)で決定した既存イベント不変・別IDコピー・revision=1・原子的保存・未来日時の本人確認を維持する。

## 4. U04のエラー文言案

- 書記素数超過：「施設名メモは100文字までです。現在はXX文字です。」
- バイト数超過：「施設名メモのデータサイズが4 KiBを超えています。文字を減らしてください。」
- 説明欄：「イベント説明のデータサイズは16 KiBまでです。」
- IME変換中は強制切断しない。変換確定後に該当欄のエラーを表示し、**保存・プラン変更をブロック**。保存失敗でドラフトを消さない。
- どの上限に違反したかを**書記素数／データサイズで別々に**示す。専門用語を過度に強調せず、ラベルやエラーを色だけに依存させない。

## 6. 次の検討事項

- **バイト上限が新たに導入されたとき、既に保存されているレコードのサイズが上限超過している場合の扱い**は[STEP7-㉑](STEP7_21_EXISTING_OVERSIZE_RECORD_OPTIONS.md)で利用者判断を求める。
- 実際の初期データフィールド名、旧版スキーマの受入範囲、Unicode検証処理の技術選定、UTF-8エンコードエラー扱い、ブラウザと端末の実測は実装前に詳細化する。4/16 KiBの**仕様としての採用**は確定したが、実機で妥当性を検証したと主張しない。

## 後続決定：既存保存済みイベントの制限超過（ADR-025）

既に保存された上限超過イベントは**U01/U03で閲覧を維持し自動変更しない**。本人がU04で該当入力を上限内へ修正し、全項目検証とrevision CASが成功したときだけ保存できる。JSONインポートは現行制約違反で全件拒否、エクスポートは選択イベントに違反があれば対象と理由を示して全件書出し停止（無断除外／切断禁止）。U03進捗保存の独立性はSTEP8-①で検討。[ADR-025](ADR_025_LEGACY_OVERSIZED_RECORD_READ_ONLY_UNTIL_FIXED.md)。
