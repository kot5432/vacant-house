# MVP開発計画 v3.0（設計のみ）
更新：2026-11-12。**Issue、コード、アプリ画面、実行テスト、デプロイは未作成**。

## 1. 開発する順序（Must）
| タスク | 内容 | 受入条件 |
| --- | --- | --- |
| A01 | 3活動カテゴリ・個人/チーム・入力値の型 | 不明値、人数異常、自由記述の非解析が明示 |
| A02 | ホームと2ステップ入力 | 個人でも団体登録なしで開始。戻っても入力が残る |
| A03 | 準備状況の要約 | 決定済み・未定、責任者・人数・日時が明確 |
| A04 | 定型優先度エンジン | 活動×個人/チーム×準備状態から最初の一歩＋最大2件。理由付き |
| A05 | 結果画面 | 最初の一歩が最初に見える。安全事項は別枠 |
| A06 | 参考先の公式情報カード | 高岡の公的相談/施設ページ3件程度、出典・確認日・利用可否未確認 |
| A07 | 既存施設/既存団体の拠点/空き家の条件表示 | 空き家を必須にしない、個別物件/予約機能なし |
| A08 | 相談文の下書きとコピー | 自分の非個人情報の条件のみを入れ、未定を保持。ユーザーが確認。自動送信なし |
| A09 | デモ・安全・受入テスト | solo/teamの具体例、人数異常、未調査、リンク無効、スマホ、キーボード |
| A10 | 作品動画用の実演シナリオ | 動作した範囲だけ紹介し、生成AIを使った工程を正確に開示 |

## 2. 優先順位付きの受入ゲート
**Gate 1**：個人とチームの2種類が別々の最初の一歩を出す（C01〜C05）。  
**Gate 2**：各結果で理由と「誰に何を確認するか」が説明できる。子どもの安全/責任の注意を省略しない。  
**Gate 3**：実在の高岡市公式リンクがあり、実際の利用許可を保証していない。  
**Gate 4**：利用者が相談文を自分で確認・コピーできる。入力は自動送信・保存しない。  
**Gate 5**：動くアプリでスマホ/キーボード/入力保持/エラー/デモ表示を確認。  
**Gate 6**：需要検証は「未実施/実施した範囲」を区別し、既存サービスと比べて価値があるか報告。

## 3. 時間が足りない場合
削る：装飾・地図・エリア細分化・会場タイプの詳細比較・相談文の多言語化。  
**残す**：個人/チームの違い、活動条件→最優先の一歩、理由と確認方法、最低限の公的参考先、相談文コピー、安全注記、品質検証。

## 4. 明確に作らないもの
所有者向け6用途診断、空き家物件の検索、団体マッチング、予約/問い合わせ送信、営利の開業判断、子ども食堂の食品衛生可否判定、AI APIによる自由文章生成、アカウント/DB。

## 5. 開発・調査前提
まずチームで[v3現行仕様](README.md)を確認。実装開始の明示指示があるまで設計のみ。実際の団体への連絡や聞き取りには、参加者同意・学校等の必要な確認と個人情報の扱いを決めてから着手する。

## 6. 追加の価値検証
「要件が整ったから作る」ではなく、[需要・競合検証](EVIDENCE_AND_VALIDATION.md)の結果でMVPを見直す。**初回テストで従来の検索や市の相談を超える助けが得られなければ、機能を増やす前に課題設定を改める。**
