# STEP5-⑤ UI残件整理と推奨仕様（2026-11-15）

> 対象は単発・小規模の地域イベント準備支援Webアプリ。旧空き家診断・物件マッチング・旧「困りごと入力→相談文コピー」は含めない。**初回下書き非保存（A案）は利用者が2026-11-15に正式採用済み**。それ以外のUI細則は引き続き推奨設計案・未承認。
> 関連：[要件v0.1](STEP4_12_MVP_REQUIREMENTS_V01.md)、[U01/U02](STEP5_02_HOME_SETUP_WIREFRAMES.md)、[U03](STEP5_03_PREPARATION_PLAN_UI.md)、[U04](STEP5_04_EDIT_SAVE_ERROR_UI.md)。

## 1. 未決事項の提案

| 項目 | 推奨仕様 | 理由・留保 |
|---|---|---|
| U02初回途中下書き | **正式採用A案：MVPでは永続保存しない。** 基本6問の回答は画面内移動中に保持し、プラン生成時に初めてイベントを保存 | 採用確定。再読み込み・タブ閉鎖では未完了入力は復元しない |
| U02の条件付き施設質問 | 第2段階「開催条件」の地域・会場の直後に施設カテゴリ。該当センターの利用者構成はその後に表示 | 同一の前提を近くに置く。表示の条件はSTEP3の確定値に従う |
| U03詳細開閉 | タスクは複数同時に展開可能。初期表示はすべて閉じる（優先カードのみ開いている） | 複数タスクの比較が可能。大量表示の長さを抑制 |
| タスク進捗の見せ方 | `未着手／進行中／完了／対象外` + 要再確認。**進捗率バーはMVP初期表示から除外** | 非該当と要再確認の分母設計が未完。誤解を防ぐ |
| Homeタイトル | イベント名は必須にせず種類を仮タイトルとし、必要なら開催時期も併記 | 基本入力を増やさない |
| 適用外の表示 | 条件から不適用になったタスクと利用者が「対象外」にしたタスクを区別して表示 | 集計・説明の混同を防ぐ |
| 保存状態 | `変更あり／保存中／このブラウザに保存しました／保存できませんでした` | 永続性を保証しない表現 |

## 2. U02 下書き非保存案の影響

- U02画面内の戻る・進むでは入力を保持する。
- ブラウザの再読み込み・タブ閉鎖で途中入力が失われる可能性がある。未完成のまま離脱しそうなときに分かりやすく説明する。
- プラン生成が成功し、初回イベントの保存トランザクションが成功した時点で、U03へ遷移。保存失敗時は基本入力を保持し再試行可能にする。
- **2026-11-15正式採用（A案）**。将来、実測で入力途中の離脱が課題となった場合のみ、変更提案を作成する。

## 3. レイアウトの初期トークン候補（正式な採用前）

- コンテンツ最大幅：ホームと準備プラン `960px` 前後、入力・編集 `680px` 前後。
- 基本余白：4/8/12/16/24/32pxの段階。本文基準16px、補足14px以上を基本にする。文字拡大時は固定高さを避ける。
- 主色：落ち着いた青緑のアクセント。**彩度・コントラストは試作とアクセシビリティ検証後に確定**。
- モバイル：1カラム。PCでも優先理由と次の行動は近接配置。320px幅・200%拡大・キーボードのみを受入条件とする。
- 強調は主操作・現在位置・優先事項に集中させ、色だけでP1/P2/P3や状態を識別させない。

## 4. 操作時の整合性

1. U03進捗変更：画面内の一時状態更新→ローカル保存→成功表示。失敗時は最新の保存版との違いを維持して再試行。
2. U04条件変更：元の保存済みイベントから分離した編集ドラフト→「変更を反映」→検証・依存タスク再確認→ローカル保存→U03に戻る。キャンセルは編集差分を破棄。
3. U01個別削除：確認→そのイベントのみ削除→成功後に一覧更新。競合・削除失敗では古いタブが復活させない。
4. 保存失敗中の画面移動は未保存内容が失われる可能性を説明し、再試行か戻るか本人に選ばせる。
5. 施設固有注意は高岡市＋本人が明示した施設カテゴリ等、適用前提がそろったときだけ表示する。

## 5. 次の判断ゲート

- **確定**：U02の途中入力は永続保存しない。基本6問→保存成功→U03に進む。生成済みプランの保存方式Bは継続。
- UI色、詳細トークン、優先度の全ルールは実装テスト前に追加の仕様審査が必要。
- 文書は設計上の候補で、ユーザー操作試験や需要を実証するものではない。
