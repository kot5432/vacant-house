# STEP7-⑰｜U01バックアップ書出しの初期選択と全選択の挙動（利用者選択前）

作成：2026-11-15。**本書は未決の比較資料**。正式採用済み：[ADR-019](ADR_019_JSON_BACKUP_LIMIT_2MIB_100_EVENTS.md)（1ファイル2 MiB・100件）、[ADR-020](ADR_020_MANUAL_EVENT_SELECTION_EXPORT.md)（本人がイベントを選択して1ファイルずつ書出し）。現行地域イベント準備支援Webアプリのみ。旧空き家案のデータは対象外。コード・実行試験・デプロイなし。

## 1. まだ決まっていないUX

本人が「バックアップを書き出す」を押したとき、**どのイベントに最初からチェックを付けるか**。また、100件より多い場合に「すべて選択」をどう扱うか。ここを曖昧にすると、無断間引きや「一部しかバックアップしなかった」の見落としにつながる。

## 2. 3案の比較

| 案 | 初期の選択状態 | 「すべて選択」の扱い | 長所 | 短所 |
|---|---|---|---|---|
| **A（推奨）** | **初期チェックなし** | **保存済みが100件以内の場合のみすべて選択可能**。101件以上は「すべて」を不可とし、個別に最大100件選択するよう説明 | 本人が含めるイベントを明示でき、黙って対象を縮小しない | 少数イベントでも選択操作が必要 |
| B | **保存済み100件以内なら初期全選択**、101件以上は初期なし | 100件以内の場合だけ全選択可能 | 少数イベントのバックアップが速い | 初期全選択を見落とし、想定外のメモまで書き出す可能性 |
| C | **初期チェックなし** | 101件以上でも全件にチェックできるが、上限超過エラーと再選択を求める | 全体件数の可視化は直感的 | 書き出せない状態をわざわざ作りやすい |

**推奨A**：ファイルに個人的な任意メモが含まれ得るため、初期選択なしで本人が出力対象を確認するのが分かりやすい。少数イベントなら「すべて選択」で簡単に選べる。

## 3. 全案共通の既決仕様

- 何件選んだか、総数、ファイルに含まれない件数を明示。
- 100件・2 MiBは**独立した制限**。「すべて選択」できる100件でも、生成JSONが2 MiB超なら書出し不可。
- **勝手に先頭100件だけ選ぶことや、本人に知らせず対象を解除することは禁止**。
- 0件選択のまま意図せぬ空JSONを出さないよう、書出し操作を無効にする案を推奨（厳密なUI細則は本選択後に確定）。
- 書出し可能なファイルのダウンロードを開始しても、端末へ確実に保存されたと断定しない。
- 途中で別タブで削除されたイベントを黙って除外しない。対象一覧を更新して本人へ再確認。
- 分割した複数ファイルの一括復元・クラウド自動同期はMVPに追加しない。
