# ADR-030｜富山の地域活動「参加＋企画」二入口MVPの採用

- 決定日：2026-11-18
- 状態：**利用者が「その方向で進めましょう」と承認したMVPの方向・範囲を正式採用。設計のみ／コード・テスト実行・CI・公開は未実施**
- 対象：富山県内の地域活動に関わりたい人向けWebアプリ。**旧空き家活用・所有者マッチングではない**
- 正本の参照：[v0.2詳細設計](TOYAMA_PARTICIPATE_ORGANIZE_IMPLEMENTATION_HANDOFF_V02_20261118.md)、[MVP案](TOYAMA_PARTICIPATE_ORGANIZE_MVP_PROPOSAL_20261118.md)、[高岡の活動候補台帳](TOYAMA_PARTICIPATION_PRIMARY_SOURCE_CANDIDATES_20261118.md)

## 背景と決めたこと

中心課題は「富山で地域活動を始めたり、参加したりする最初の一歩が分からない」。既存の参加アプリや情報一覧と重なる地図・推薦・口コミではなく、**必要な参加条件の明確化と、確認できる次の行動**を参加側の価値とする。主催側は既決の条件別の準備優先順位・理由・公式情報の適用を中核とする。

### 採用したMVPの構成

1. **参加D00〜D02**：D00は「参加する／企画する」の入口。D01は確認済みの富山の活動一覧と**地域・活動分野**による絞り込み。D02は初参加向けの判断材料・出典・未確認情報・ひとつの「次の一歩」・運営元の公式案内へのリンクを示す。
2. **企画U01〜U04**：既存の基本6問、P01〜P12優先度・理由・第一歩、進捗/再確認/編集、IndexedDB、JSONバックアップを維持する。D00からU01、参加の詳細から任意でU02へ。主催に進むことを参加側の完了条件にしない。
3. **富山の地域性**：初期掲載と公式出典の重点は高岡市。対象が実在する富山県内の活動、地域・施設・主催者が公表した情報に基づく。「県全域で活動が網羅されている」とは宣言しない。
4. **参加カタログの境界**：一般公開の活動データは読み取り専用の静的カタログとして**既存の主催EventRecordとは別**に設計する。利用者の保存データ/JSON v1に参加活動・履歴を追加しない。
5. **確認できない情報の扱い**：「無料」「誰でも歓迎」「現在募集中」「参加できます」を推測しない。出典のない活動を水増しせず、公式案内と未確認事項に縮小できる。
6. **初版に含めない**：イベント投稿、申込/決済、チャット、ログイン、GPS地図、AI推薦、口コミ、参加履歴、スクレイピング、一括自動登録、主催イベントの公開/共有。

### 変更しない正式決定

- **ADR-001〜029を変更しない**。既存U01〜04は維持し、既存のルールとバックアップの正式仕様を上書きしない。
- P05：`minors/both=P1`、それ以外P2（ADR-003）、P08の基本P2・出典によるP1自動昇格なし（ADR-027）、P01〜P12の限定P2条件（ADR-028）。
- `input.date`、バックアップ`formatId="toyama-community-event-prep-backup"`と初回version1（ADR-029）。
- U02の未保存下書き、U03本人進捗CAS、U04明示保存、JSON100件/2MiBと原子的取込。
- 技術：React + TypeScript + Vite、IndexedDB + Dexie、Vercel（ADR-001）。

## このADRの承認に**含めていない**事項

- D01の分野タグのリテラル/市町村列挙、D02の完全な保存型・項目順、情報鮮度の日数閾値、掲載責任者・周期・撤回窓口、掲載できる個別イベントは**未採用**。個別の設計Issue #14/#15/#17でレビューする。
- 「5〜10件」は候補調査数の目安であり最低掲載数ではない。公式情報の候補5件は**掲載承認・現在募集中・利用者需要の証拠ではない**。
- 主催側の`optionalDescription/importedFrom`と子チェックIDなど、従前のスキーマ未決事項はIssue #1のまま。
- 実装・テスト実行・CI・デプロイ・外部団体への連絡は**別の明示許可**が必要。4人の実際の担当割当も未了。
