# STEP 5-②｜U01/U02 ワイヤーフレーム・操作仕様 v0.1

> 現行対象：富山県内で初めて単発・小規模の非営利地域イベントを主催する人向け準備支援Webアプリ。旧空き家活用／所有者診断／マッチングの仕様は取り込まない。
> **文章ワイヤーフレームと設計提案。UI実装・実行検証・利用者検証なし。** 現行MVP境界は [STEP4-⑫要件定義](STEP4_12_MVP_REQUIREMENTS_V01.md) 、4画面全体は [STEP5画面設計](STEP5_SCREEN_DESIGN_V01.md) を参照。

## 1. デザインの前提

- 日本語・スマートフォン優先。広い画面でも読みにくい横長フォームを作らない。
- 背景は白〜明るい中立色、強調色は落ち着いた青緑の候補。色やフォントの具体トークンは未決定。
- 各画面の主目的を1つにし、進捗・エラー・保存状態を色だけで伝えない。
- 本人の困りごと追加入力、相談文コピー、空き家・物件の提示、予約・申請機能は設けない。

## 2. U01 Home — 画面構造

```text
[サービス名]                          [このサービスについて]
-----------------------------------------------------------
地域イベントの準備を、わかりやすく。
初めてのイベント開催で必要な準備と優先順位を整理。
[＋ 新しいイベントを作る]  ← 主CTA
-----------------------------------------------------------
保存したイベント (N件)
 ┌────────────────────────────────────┐
 │ イベント名または種類による仮タイトル  [開く] │
 │ 種類 / 参加対象 / 開催希望時期        │
 │ 最終更新日時                        [⋯ 削除]│
 └────────────────────────────────────┘
 （複数件は同形カードを反復）
[このブラウザへの保存について／データ消失の注意]
```

### 情報・表示規則
- 0件：カード枠なし、「まだイベントはありません」を短く示し、新規作成CTAを中心に。
- 1件以上：最終更新降順、同時刻は安定ID順。件数を表示。
- イベント名は必須質問に追加しない。任意名がないときはイベント種類から仮タイトルを作成（「その他」等でも識別が曖昧になるため、同名の場合は開催時期や作成日時を補助表示）。
- 一覧の「○/12完了」などは、該当しないタスク・要再確認・母数の仕様が決まるまで使用しない。
- イベントを開くとU03へ。新規作成はU02へ。
- 削除はカードの副操作から確認画面を出し、イベントを特定する。キャンセルは副作用なし。処理成功後のみ一覧から削除。失敗時は成功表示しない。
- 保存済みデータを読み込めない場合、「0件」と偽らない。破損・移行失敗・未対応バージョンを区別し、安全な再試行を案内する。

### U01 の操作状態
| 状態 | 主表示・許す操作 |
| --- | --- |
| 初回／0件 | サービス説明＋新規CTA |
| 1件以上 | 新規CTA＋イベント一覧 |
| 読み込み中 | 読み込み表示、件数を確定扱いしない |
| 読み込み失敗 | データを上書き・初期化せずエラーと再試行 |
| 削除確認中 | 対象イベントの識別・不可逆性と取消 |
| 削除失敗 | 元カードを保持し、再試行案内 |

## 3. U02 Event Setup — 基本入力3ステップ案

**基本6問は増やさない。** 画面上のフォームを関連内容でまとめる3段階UI（仮設計）。入力値・選択肢はSTEP3確定仕様を正とする。

| 入力画面段階 | 基本質問 | 追加の表示 |
| --- | --- | --- |
| 1. イベント | Q1 イベント種類：体験会・ワークショップ／勉強会・講座／交流会・意見交換会／その他。Q2 参加対象：子ども・未成年／大人／両方／未定 | 任意の自由説明は初回に要求しない |
| 2. 開催条件 | Q3 開催希望時期：年月日／年月／未定。Q4 会場状況：未定／候補あり／本人申告で場所確定／物理会場なし（**建物の会場を使わない**の意味。オンラインとは限らない）。Q5 開催地域：高岡市／県内その他／県外／未定 | 日付・月の選択に対応。未定は有効回答 |
| 3. 主催体制 | Q6 主催者形態：一人／複数／未定 | 高岡市＋会場候補あり／決定＋地域交流センター選択時のみ、施設利用者の年齢構成を確認。施設カテゴリ選択は開催条件段階に置くか主催体制段階に置くかをSTEP5詳細レビューで決める |

> **条件付き確認は基本6問の集計に含めない**。必要な人にだけ出す。選択に関係しない古い条件値を自動的に施設規則へ適用しない。

### U02のバリデーション・状態
- 基本6問に回答してから生成。選択肢「未定」は有効な回答。エラーを未回答欄に近接表示し、他の入力を消さない。
- Q3日付・年月は妥当な形式と存在する年月日を確認する。過去日を不許可にするかはデータ仕様で未決定。行政の期限を日付から推測しない。
- **Q4=物理会場なしの場合はADR-002の限定支援B案を適用**。建物予約専用のチェックは表示しないが、屋外の利用条件やオンライン特有の手続きが不要と断定しない。物理会場なし＝オンライン開催と推定しない。基本6問は増やさない。
- 地域「高岡市」だけでは高岡市地域交流センターを選んだと推定しない。**本人がセンター施設カテゴリを明示したときだけ**施設固有の年齢条件を質問する。
- 参加対象の「未成年」と、施設利用者が「未成年のみ」は区別する。責任者が確定したとも推定しない。
- 途中で地域・会場条件を変え、施設カテゴリが非該当になった場合は施設固有の結果を消して再計算。データ自体の保持・消去はデータ設計で明確化する。
- **2026-11-15採用確定A案**：初回入力途中の下書きは永続保存しない。U02の3段階間では画面内の入力を保持し、再読み込み・タブ閉鎖後の復元は保証しない。プラン生成時に入力検証→IndexedDB保存を試み、**保存成功後だけU03へ遷移**。保存失敗時はU02の入力を保持し再試行可能にする。
- エラーで先へ進めないときは説明と修正場所を示す。何が未入力かを色のみで伝えない。

## 4. U03・U04との接続

- U02「準備プランを見る」→U03：**優先する確認と理由→今できる一歩→準備全体像（4領域P01〜P12）→該当公式情報**。進捗は利用者が生成後に変更する。
- U03からU04：任意詳細入力（人数、責任者の決定、設備の必要性／種類、イベント内容の説明）と基本条件の編集。再計算時に完了履歴を黙って消さず、必要なタスクに再確認を付与。
- U03からU01：保存が未完了の場合は状態を明示。失敗しているのに保存済みとは表示しない。
- U01からU03：後日、同一ブラウザの保存済みイベントを読み込む。複数イベントは安定IDで分離。

## 5. レスポンシブ／アクセシビリティ

- スマートフォンは単一カラム。選択肢は十分なタップ領域とし、320px幅でも横スクロール不要。
- PCでもフォーム本文の幅を絞り、質問文・補足・選択肢・エラーを近接させる。
- キーボードで選択、戻る、次へ、削除の確認を完結できる。進行状況を数字と文字でも示す。
- フォント、配色、コンポーネント寸法は後のデザインシステムで統一。現在の例示デザインは確定トークンではない。

## 追加｜U01/U02の新版検知と再読み込み（ADR-013正式採用）

U01では同一オリジンの軽量なビルド識別子を自動確認し、差異が確認できた時のみ「新しいバージョンがあります」と通知。**自動で再読み込みしない**。U02で基本6問の入力途中に更新が見つかっても、React内の入力を維持し、再読み込みすると**初回下書きが永続保存されず失われる**ことを明確に伝えてから本人が操作する。U02のステップ移動・未定回答・作成保存失敗の既存動作は不変。識別子取得失敗は新版ありと断言しない。詳細：[ADR-013](ADR_013_MANUAL_REFRESH_ON_AUTO_VERSION_DETECTION.md)。

※古い本文章中の「過去日の許否は未決」は[ADR-006](ADR_006_ALLOW_PAST_SCHEDULE.md)で更新済み。過去実在日は注意のみで許容する。

## 互換性補足｜U01/U02のブラウザ保存・IME（ADR-014）

スマホ・PCの主要現行Chrome/Edge/Safari/Firefoxを検証対象とする。U02は6問の未完成入力を永続保存しないため、他ブラウザ・端末で再開できるとは表示しない。IMEの変換途中を妨げず、ブラウザ更新通知による強制再読み込みを避ける。存在する過去日を注意つきで有効とするADR-006に従う。PC・スマホの実機操作は未検証。[ADR-014](ADR_014_MAJOR_DESKTOP_MOBILE_BROWSER_SUPPORT.md)。

## U01補助導線：JSONバックアップ書出しと復元（ADR-015）

新規イベント作成を主CTAとし、「保存データの管理」に「バックアップを書き出す」「バックアップから復元」を置く。書出し前に保存成功済み件数と、任意メモに個人情報が含まれ得ることを説明。保存済みデータの一貫したスナップショットだけを書き出し、U02未完成入力やU04ドラフトはバックアップ済みとしない。

復元は**ファイル選択→ローカル検証→件数・衝突・エラープレビュー→本人の確定→結果表示**。検証前にはDBを書き換えない。失敗時は元イベントを保護し、イベント0件と偽らない。復元後のルール・出典は現行アプリ版で再評価。重複IDの最終対応は[STEP7-⑩](STEP7_10_BACKUP_IMPORT_CONFLICT_OPTIONS.md)の判断待ち。[ADR-015](ADR_015_JSON_BACKUP_EXPORT_IMPORT.md)。

## U01復元プレビューとコピー追加（ADR-016正式採用）

バックアップ選択後に全件検証し、プレビューに**「追加するイベントX件／そのうち既存IDとの衝突により別コピーになるY件／既存イベントZ件は変更なし」**を表示。ファイル内で同じeventIdが重複した場合はエラーを出し取り込み禁止。既存IDの衝突なら**バックアップ側を新IDの別イベントとして追加**し、既存イベントを更新／削除しない。重複コピーが増え得ることと、イベント別の元名称・日時が分かる補足を示す。本人が「X件を復元」を押すまでDB無変更。

プレビュー後の別タブ更新で衝突件数が変わったら**いったん停止し、再プレビュー後に明示再承認**。原子的な保存成功後だけ結果と新しいイベント一覧を表示。失敗は元の一覧を維持し「復元済み」としない。新規イベント作成CTAは最上位のまま。詳細：[ADR-016](ADR_016_IMPORT_COLLISION_AS_COPY.md)。

## U01バックアップの繰返し復元プレビュー（ADR-017正式採用）

同一JSONファイルを再び指定しても**自動禁止・自動スキップしない**。毎回、検証後に「新たに追加X件／そのうち別コピーY件／既存Z件は維持」と**重複コピーがさらに増える可能性**を表示する。**ファイルが以前取り込まれたと断定しない**（履歴・ファイルハッシュは保存しない）。本人が「X件を復元」を明示的に選択して初めて保存を開始。戻る／キャンセルはDB不変。別タブで衝突状況が変化したら再プレビュー・再承認。結果は全件保存成功が確認されたときだけ表示。旧空き家JSONは不正ファイルとして拒否。[ADR-017](ADR_017_REPEAT_IMPORT_WITH_CONFIRMATION.md)。

## U01一覧｜復元日時・元の日時の区別（ADR-018正式採用）

バックアップから復元したイベントは、**今回の復元日時を新EventRecordの作成・更新日時として扱う**。最終更新順の一覧では今回の復元日時に基づき並ぶ。イベントの開催日時（Q3）は変えない。復元イベントには「バックアップから復元」を補助表示、既存eventIdと衝突して別コピー追加した場合は「別コピーとして追加」と明示する。詳細表示で「復元日時」「元の作成日時」「元の更新日時」を区別し、一覧を過度に長くしない。過去の日時は`importedFrom`から読み取り、旧イベントのDB履歴と同期したものとして扱わない。**revision=1から新規開始**。コピーのコピーの元情報は直接の前段階だけを保存。今回の復元について全件成功か全件失敗を維持。[ADR-018](ADR_018_RESTORED_EVENT_REVISION_AND_PROVENANCE.md)。
