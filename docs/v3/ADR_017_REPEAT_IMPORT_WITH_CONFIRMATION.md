# ADR-017｜繰り返しJSONインポートは毎回件数・コピー増加を表示し、本人の承認で許可（A案正式採用）

決定日：2026-11-15。**利用者がA案を明示採用。** 現行の単発・小規模地域イベント準備支援Webアプリ専用。旧空き家所有者・物件・マッチング等のデータは扱わない。**設計のみ。実装、動作試験、公開は未実施。**

関連：[ADR-015 JSON入出力](ADR_015_JSON_BACKUP_EXPORT_IMPORT.md)、[ADR-016 衝突時の別IDコピー](ADR_016_IMPORT_COLLISION_AS_COPY.md)、[STEP7-⑫比較](STEP7_12_REPEAT_IMPORT_OPTIONS.md)。

## 1. 正式に採用した利用者向け動作

- **同じJSONバックアップを何度でもインポート可能**とする。過去に取り込んだかどうかを、ローカル履歴・ハッシュで自動判定しない。ハッシュ記録・同一ファイル再取込み禁止は初期MVPでは不採用。
- **毎回、インポート確定前にプレビューを表示**する。ファイル内総件数、新規追加件数、既存eventIdとの衝突によって**別コピーになる件数**、既存DBのイベント件数と、**既存イベントは変更しない**ことを明記する。
- 同じファイルをもう一度取り込むと複製が増える可能性がある旨を毎回表示する。ファイル名・イベント名・説明文が似ていても「以前と同一ファイル」と**断定しない**。
- ユーザーが「X件を復元」等を明示選択した場合のみ追加。ファイルを選択・検証・プレビューした段階ではDBに書かない。キャンセルは副作用なし。
- **既存DBとのeventId衝突はADR-016の別IDコピー**。ファイル内部で同じeventIdが2回以上ある場合は、ファイル不正として全件インポートを拒否。
- 一括追加は全件成功／全件失敗。プレビュー後に別タブでID衝突分類が変化した場合は、前の承認を使い回さず**新しいプレビューと再承認**を要求する。

## 2. U01の画面文言と導線

**提案するプレビュー例**（件数は架空）：

> バックアップ内のイベント：3件  
> 今回追加するイベント：3件  
> うち別コピーとして追加するイベント：2件  
> 保存済みのイベント：4件（変更しません）
>
> 同じバックアップを再び読み込むと、イベントのコピーがさらに増えることがあります。

主操作：「3件を復元」／副操作：「キャンセル」。ファイルが無効・保存容量が不足・別タブで状況が変わった場合は、正確なエラーと再確認導線を表示する。主操作に重複警告を隠さず、色だけで警告を伝えない。

## 3. データモデル・取込履歴の扱い

- **インポート済みファイルのSHA-256等の履歴テーブルはMVPで追加しない**。以前に取り込んだことの自動判定、ハッシュ一致による自動スキップ・ブロックは行わない。
- 別コピーを作るときは**新しい一意eventId**を割り当てる。新EventRecordのrevisionは独立した初期値とする（厳密な初期値は技術仕様未決）。
- 既存のイベントレコード・revision・進捗は変更しない。復元したイベントの入力・本人進捗と再確認情報を保持する。
- 別コピーかどうかのU01表示は設計対象だが、**取込履歴の永続記録を前提としない**表示方式を検討する。必要に応じて新イベント単位の由来メタデータを別途判断。
- 複製を増やせる設計なので、毎回、インポート**保存直前**の実際の衝突状況を再確認し、プレビューと違う場合は承認を取り直す。

## 4. 受入テスト（期待値のみ・未実行）

| ID | 条件 | 期待 |
|---|---|---|
| REPEAT-A01 | 初回インポート | 件数とコピー件数をプレビュー、本人確定後に全件追加 |
| REPEAT-A02 | 同じJSONを2回目に選択 | 追加／コピー件数と複製増加の注意を**再表示**。選択だけでDB無変更 |
| REPEAT-A03 | 2回目に本人が「復元」を選択 | 新たに別IDコピーを追加。既存の元イベントは不変 |
| REPEAT-A04 | 2回目のプレビューをキャンセル | DB無変更 |
| REPEAT-A05 | 同名で異なる進捗を持つファイル | タイトル一致だけで同一ファイルと断定・拒否しない |
| REPEAT-A06 | 同じファイルを3回目に取込 | 件数を再計算・通知し、本人承認後なら追加できる |
| REPEAT-A07 | プレビュー後に別タブがイベント追加 | 衝突分類が変化したら再プレビューと本人再承認 |
| REPEAT-A08 | JSON内部でeventId重複 | 全件拒否、DB無変更 |
| REPEAT-A09 | 途中でIndexedDBの保存失敗 | 全件ロールバック、復元成功と偽らない |
| REPEAT-A10 | 旧空き家用JSON／未知schema | 取込拒否。形式を推測変換しない |

## 5. 正式決定と残件

**確定**：履歴・ファイルハッシュによる重複追跡なし、同一ファイルの繰返し復元は許可、**毎回の件数／コピー増加注意＋本人の明示確認**、既存不変・別ID複製・全件原子的追加は維持。

**次に判断する論点**：インポートによる新規イベントのrevision初期値と、元イベントの作成日時・復元日時をどう扱うか。[STEP7-⑭](STEP7_14_RESTORED_EVENT_METADATA_OPTIONS.md)を参照。JSON最大サイズ・件数や旧版対応範囲は、まだ技術レビューが必要。
