# ADR-025｜新UTF-8上限を超える既存イベントは閲覧を維持、修正後のみU04保存（A案正式採用）

決定：2026-11-15。ユーザーは[STEP7-㉑](STEP7_21_EXISTING_OVERSIZE_RECORD_OPTIONS.md)の**A案を正式採用**。対象は現行の単発・小規模地域イベント準備支援Webアプリのみ。旧空き家・所有者・物件・マッチングとは無関係。**設計資料のみ更新。実装・実行試験・デプロイなし。**

## 1. 決定した利用者向け動作

- IndexedDBに**既に保存済み**で、施設名メモが4,096 UTF-8バイト超／イベント説明が16,384 UTF-8バイト超など現在の制限に不適合なイベントでも、**読み取り可能ならU01一覧・U03詳細を表示**する。入力や進捗、再確認情報、revisionを**自動削除・自動短縮・自動変更しない**。
- U01/U03に「このイベントには現在の入力サイズ上限を超える項目があります。内容を確認し修正してください」と控えめな注意・U04への導線を設ける。内容や個人情報を警告文に過剰に引用しない。元内容は閲覧可能で、画面を開くこと自体は保存操作にしない。
- U04編集では**上限超過の欄を特定**して、書記素数・UTF-8バイト数と許容値を区別して表示。**本人が上限内に修正し、全入力検証とrevision CASが成功したときだけ明示保存可**。不適合のまま別の項目だけ直しても、U04全体の保存を成功させない。
- U04のキャンセル、IME編集中、保存失敗、他タブ競合では、**保存済みの元データも編集ドラフトも勝手に消さない**。本人が修正した文字列を自動切断せず、本人が明示保存を選ぶ。
- **U03のタスク進捗・再確認の保存は入力U04保存とは別責務**。既存入力のサイズ不適合だけを理由に進捗を無言で初期化しない。U03が入力全体を再検証する必要性や技術上進捗の部分保存が可能かは[STEP8-①](STEP8_01_CORE_VALUE_RULES_AND_LEGACY_PROGRESS_REVIEW.md)で安全設計を検討し、**U03進捗が必ず保存できると未検証の段階で保証しない**。
- [ADR-024](ADR_024_UTF8_TEXT_BYTE_LIMITS.md)の文字数（100/500書記素）とバイト数（4/16 KiB）制限を維持。旧イベントだけを例外扱いして新たな上限違反のU04保存を成功させる**B案は不採用**。

## 2. JSONバックアップの扱い

- **インポート**：現在の形式または検証済み既知旧形式を読込後、全イベントの書記素・バイト数を現行規則で検証。**どれか1件でも超過ならファイル全体を拒否**し、既存DBは不変。テキスト切詰め・不適合イベント除外・部分取込みを行わない。
- **エクスポート**：本人が選択したイベントにサイズ不適合があったら、**選択全件を含む有効バックアップを生成できない理由と該当イベントを示し、書出し全体を停止**。不適合イベントだけ黙って省く、データを短くする、前回成功のように表示することは禁止。本人は**選択を見直す**か、U04で該当テキストを**本人の判断で修正**して再度書き出す。
- 不適合な古いイベントをそのまま残している間、現行形式の完全なバックアップを生成できないことがある。**復元不能／書出し不能を利用者に隠さない**。ファイル全体の2 MiB・100件、本人選択の規則と、元イベントの入力・進捗保持は変えない。
- 既に存在する旧バックアップのサポートは[ADR-022](ADR_022_BACKUP_KNOWN_VERSION_COMPATIBILITY.md)に従う。旧版移行が検証済みでも現行上限を満たせなければ無断変換・欠損なしに復元を拒否する。

## 3. 画面文言案

- **U01/U03**：「このイベントには現在の文字数またはデータサイズ制限を超える項目があります。内容は削除されていません。編集画面で確認してください。」
- **U04**：「施設名メモは100文字・4 KiB以内にしてください。現在の入力はサイズ上限を超えています。修正してから保存できます。」
- **エクスポート**：「選択したイベントの中に、現在の入力サイズ制限に適合しないものがあります。データを省略せずにバックアップするため、書き出しを中止しました。対象を変更するか、内容を修正してください。」
- **インポート**：「このファイルには現在の入力サイズ上限を超えるイベントがあります。元のファイルは変更されず、保存済みイベントも変更していません。」

## 5. 未決事項

「閲覧可」と「U04修正後だけ保存可」と「現行上限違反のJSONは入出力不可」は正式採用。**U03の進捗のみの保存時に上限超過フィールドがあるレコードをどのように保護するか**、既存上限違反を含むデータの将来の救済、正式なフィールド名と現在の保存スキーマの固定、P01〜P12の判定網羅性については、[STEP8-①レビュー](STEP8_01_CORE_VALUE_RULES_AND_LEGACY_PROGRESS_REVIEW.md)で追跡する。
