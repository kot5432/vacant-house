# STEP8-⑧｜P01〜P12の未決優先度をどう固定するか（製品判断ゲート・未採用）

作成：2026-11-16。**本資料は比較と推奨であり、どの案も正式採用していない。** 既決の[ADR-003](ADR_003_PRIORITY_RULES_ADOPTED.md)・[ADR-027](ADR_027_P08_P2_NO_FACILITY_AUTO_ESCALATION.md)を変更しない。現行地域イベント準備支援Webアプリのみ対象、旧空き家案なし。実装・テスト実行なし。

## なぜ今判断が必要か

中心価値は「自分の状況に合った準備の優先順位と次の一歩」。現在の[判定契約](RULE_ENGINE_CONTRACT_V1.md)にはP01〜P04、P07、P09などの**P2候補**があり、P06/P10〜P12にはP3基本の推奨案がある。**理由コード案・表示文は整えられるが、優先度の昇降条件が未採用のままでは利用者へ提供する順序が一意に決まらない**。

以下を混同しない。
- **既決**：P05は未成年のみ/両方=P1、成人のみ/対象未定=P2。P08はP2基本、施設公式情報だけでP1に自動昇格しない。物理会場なしでもP08親は要情報・P2。同じ優先区分ではタスクID昇順。
- **未決**：P01〜P04/P06/P07/P09〜P12の初期優先度、入力条件によるP2/P3の変更。説明文や候補表は採用済みルールそのものではない。
- **禁止**：開催14日前という架空の固定期限、行政申請の必須判定、施設予約の可否、保護者・責任者の法的義務の断定。

## 比較する3案

| 案 | P05/P08以外のMVP優先度 | 長所 | 注意 |
|---|---|---|---|
| **A（推奨：限定的な条件分岐）** | P01〜P04、P07、P09は基本P3。**該当する入力が「未定」や設備指定等の明示状態**ならP2へ。P06/P10〜P12は基本P3のまま。新しいP1昇格は導入しない | 入力した状況に応じて順序が変わり、「なぜ先か」を説明しやすい | 条件と理由が妥当か実ユーザーへの確認が必要。明示されていない情報を「未定」とみなさない |
| B（保守的な固定優先度） | P01〜P04、P07、P09を一律P2、P06/P10〜P12を一律P3。入力による昇降はP05の既決以外ほぼなし | 実装・テストと説明が単純 | 個別状況への適合が弱く、ユーザーの「自分に合う優先順位」とのギャップが大きい |
| C（詳細条件で広く昇降） | 各タスクに複数の入力条件でP1/P2/P3を割当（例：日程・参加人数・会場候補等） | 高度な個別化が可能 | 6問だけで根拠が足りない条件、恣意的な重要度、テスト組合せ増大のリスク |

**Aを推奨する理由**：中心価値である個別の準備順と、初回MVPの入力負担・根拠説明のバランスを取れる。**P1を広く増やさない**ので未検証の重要度・法的断定を避けやすい。ただしこの表は未決の製品判断で、Aを採用したことにはしない。

## A案を採用した場合に詰めるべき「条件案」（すべて未採用）

| タスク | P2へ上げる可能性がある本人の明示条件 | P3を基本とする場合の理由 |
|---|---|---|
| P01 | イベント種類=その他、または本人が企画内容の整理を求める | 種類の選択だけで企画内容の不足を断定しない |
| P02 | 参加対象=未定、または人数検討を希望した場合 | 任意人数の空欄は0人・人数未定と同義ではない |
| P03 | 開催時期=未定、または「月のみ」で具体日未定 | 月のみは未回答ではなく有効な概算時期 |
| P04 | 主催形態=未定、または責任者の明示未定 | 個人主催だから担当者が決まったとは推測しない |
| P07 | 会場=未定／候補検討中 | 会場確定＝予約済みとはみなさない |
| P09 | 任意の必要設備が本人により指定された | 任意設備欄空白＝設備不要とは断定しない |

**精査が必要な問題**：上の「責任者の明示未定」「人数検討希望」等の値が実際の基本6問・任意項目に存在するかの型照合。存在しない値を入力済みとして分岐してはいけない。採用後に既存の入力型と照合し、表を縮退させてもよいが、基本6問の追加は別の本人判断が必要。
