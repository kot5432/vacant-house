# ADR-007｜参加予定人数B案（1,000人超は注意・入力と保存は許可）

決定日：2026-11-15。**利用者がB案を明示採用済み**。現行の「初めて単発・小規模の非営利地域イベントを主催する人の準備支援」Webアプリのみ対象。旧空き家所有者・物件・マッチング・用途診断は含めない。**実装・テスト実行・デプロイは未実施**。

## 1. 正式採用したルール

- 人数`attendeeCount`は**任意**。未回答、未定、有効な数値回答を区別し、未回答・未定でも暫定プランを生成可能。
- 数値回答は**1以上の安全な整数**（`Number.isSafeInteger(value) && value >= 1`）。0、負数、小数、NaN、Infinity、型が違う値、`Number.MAX_SAFE_INTEGER`を超える値は入力エラー。
- **1〜1,000人：数値として有効で、このルールによる規模注意なし。**
- **1,001人以上：数値として有効で、注意を表示したうえで保存可能。** 上限で遮断しない。1,000人は製品上の説明しきい値であり、法律・条例・許認可・小規模イベントの公式定義ではない。
- 数字が大きいことだけから必要スタッフ数、施設定員、消防・保険等の適用、許可の要否、イベントの安全・可否を自動判定しない。P02／P05の一般確認の文脈として入力した人数を活用できるが、公式根拠のない定量規則は作らない。
- 表示例：「このアプリは小規模な地域イベントの準備を中心に案内します。参加人数が多い場合、必要な確認事項を網羅できないことがあります。」警告は阻止エラーではなく注意。

## 2. 入力と正規化の境界

- フォーム上で空欄（`unanswered`）と「人数はまだ未定」（`undecided`）は別状態。
- 有効な数値回答は`{kind:"answered",value:1001}`のように**整数の数値**として保存。警告の有無を恒久保存せず、表示時に値から導出する。
- 文字列→数値は**文字種と整形ルールを明示してから**行い、`Number("")=0`などの暗黙変換を認めない。全角数字、カンマ区切り、前後空白の受理・エラー文言は補助仕様で検討。
- 入力エラーはU04ドラフトを破壊せず、保存前に局所表示。警告のときは`変更を反映する`で保存可能。
- **警告による優先度P1/P2/P3の自動変更を行わない**。優先順位はADR-003と現行タスク契約に従う。

## 4. 採否の境界

**正式採用済み**：任意人数、1以上の安全整数、1,000超は注意のみ、入力・保存を拒否しない。

**まだ未決**：自由記述の文字数上限とUnicode単位、人数入力の全角数字／カンマの扱い、公式情報のレビュー頻度と担当。技術は[ADR-001](ADR_001_TECH_STACK_ADOPTED.md)、日時は[ADR-006](ADR_006_ALLOW_PAST_SCHEDULE.md)、データは[DATA_DESIGN_V1.md](DATA_DESIGN_V1.md)。
