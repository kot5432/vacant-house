# STEP 4｜準備の全体像・優先順位・根拠の判定契約（設計案／2026-11-13）

> **STEP 3で確定した入力方式（①〜⑫）、⑬「困りごと追加入力なし」、⑭「重要確認→次の行動→全体像」の採用方針に合わせて更新した設計案。** 本書の12項目の詳細判定・優先順・表示文は**ユーザーによる最終確定前**。以前の「活動障壁 `blocker` を必須・任意で聞く設計」と「最初の一歩だけを主役にする設計」は、現行MVPの判断根拠に使わない。プログラム実装・動作テスト・利用者検証は未実施。

関連資料：[STEP 3の決定事項](STEP3_MVP_BOUNDARY.md)／[中心価値](STEP2_VALUE_DIFFERENTIATION.md)／[公式根拠台帳](OFFICIAL_SOURCE_REGISTER.md)。

## 1. 目的と入出力の境界

**対象**：初めて単発・小規模の非営利イベントを開催する個人・小規模チーム。出力の主役は「準備の全体像」と「なぜ今その確認を優先するか」。実際の予約、施設利用の承認、専門的な安全判断、法令適合・補助金適格判定は行わない。

- **基本6問（採用）**：イベント種類（③）、参加対象（⑤）、開催希望時期（⑦）、会場の決定状況（⑧）、開催地域（⑨）、主催者形態（④）。
- **条件付き確認**：候補会場があるときの施設カテゴリ（⑩）、高岡市地域交流センターが明示されたときの施設利用者の年齢構成（⑪）。該当施設の条件を誤表示しないため、必要なら最初の暫定プラン前に確認する。施設名の自由入力は任意の本人用メモで、ルール判定には使わない。
- **任意の詳細化（採用）**：参加予定人数（⑥）、運営責任者の決定状況（⑪）、設備の必要性と必要な場合の設備種類（⑫）、活動内容の説明文（②）。責任者に関する質問は**全員向けの入力項目として用意**するが、暫定プラン以前の回答は必須にしない。未回答は未確認とする。
- **聞かない**：本人の「今いちばん困っていること」（⑬でAを採用）、イベント参加者の個人情報、主催者の住所やGPS、施設の正確な予約情報。
- **利用方式**：暫定プランの表示→任意で詳しくする→同じ利用中に再評価→1回で持ち帰る。ログイン、継続的な進捗管理、サーバー保存はMVP外。

### 1.1 入力・未定・状態の区別

| 区別 | 意味 | 禁止する推論 |
| --- | --- | --- |
| **条件が分かっている** | 本人が日時、対象などの値を入力した | その準備作業が完了したとはみなさない |
| **未定（本人の明示）** | 本人が「まだ決まっていない」と回答した | 「入力忘れ」「開催不可」「0人」とはみなさない |
| **未確認（未回答・情報不足）** | アプリが把握していない | 本人が準備していないと断定しない |
| **要確認** | 利用条件、設備、運営体制などの確認が役立つ | 規則違反・危険・申込不可だと断定しない |
| **対象外** | 条件から、その準備項目が該当しない | 同領域のほかの確認まで不要と扱わない |

**注意**：これらは準備作業の進捗ステータスではない。未回答の責任者は「未確認」であり「責任者なし」ではない。会場確定は「施設の許可済み」ではない。

## 2. 4領域・12項目の条件別判定表（未確定の設計案）

**各行は準備領域に表示する基本項目**。共通項目は表示しつつ、条件に応じて説明、優先度、次の行動を変更する。施設に固有の注意は該当条件以外に表示しない。P1/P2/P3は提案する*確認・行動の順序*であり、危険度・法律上の義務の自動判定ではない。

| ID・領域 | 基本項目 | 表示条件・条件分岐 | 優先の根拠・候補 | 次にできる行動例 |
| --- | --- | --- | --- | --- |
| **P01 企画** | 内容・目的の整理 | 全員に表示。「その他」なら活動の具体化が必要か確認。自由記述は解析しない | 内容や進め方が具体化されていない場合 **P2候補**、そうでなければP3 | 誰に何を体験・学習・交流してほしいか、企画の概要を整理する |
| **P02 企画** | 参加対象・人数の整理 | 対象未定→対象の検討。人数未回答→未確認、本人が未定と答えた→未定、人数入力あり→会場・体制への照合。主催者・スタッフ数と混同しない | 対象や規模が会場・安全準備の前提なら **P2候補**、そうでなければP3 | 対象・参加人数の目安を整理し、必要に応じ定員やスタッフ体制を確認する |
| **P03 企画** | 開催時期・費用の整理 | 時期未定→候補時期を考える。月のみ→候補日を検討。日付あり→該当施設の申込期間を**公式情報で確認**。費用は専用入力未確定のため常に未確認 | 開催時期が後続の準備の前提なら **P2候補**。日付から独自の予約締切を計算しない | 候補日・費用項目を整理し、必要な申込期間を公式に確認する |
| **P04 運営** | 責任者・役割分担 | 全員に表示。⑪責任者が未定→未定、未回答→未確認、決定済み→本人申告の決定。④一人/複数人から責任者の有無を推測しない | 責任者が未定、特に複数人で役割が分かれそうな場合 **P2候補**。未回答は欠員と断定しない | 運営責任者の決定状況を確認し、必要な担当を整理する |
| **P05 運営** | 安全・見守り | 全員に一般的な安全確認を残す。参加者が未成年/両方→見守り・保護者への連絡等を追加。対象未定→子ども向け注意の要否は未確認。成人のみ→子ども固有項目は省略 | 子どもが参加すると分かる場合は**重要確認P1候補**。事故や法律違反が確定したという意味ではない | 見守り・連絡・安全上の責任体制を確認し、必要に応じ適切な成人や専門窓口と相談する |
| **P06 運営** | 当日の進行・不測の事態 | 全員に表示。イベント種類に応じ、体験の進行／説明・講座資料／交流進行などを補足 | 特別の制約がなくても必要な**P3**の確認。入力だけで準備済みとは判定しない | 当日の流れ、緊急連絡方法、役割を紙に整理する |
| **P07 会場** | 会場の選定・決定 | 会場未定→選定条件。候補あり→候補の条件と承諾確認。確定（本人申告）→探し直しの提案はしない。物理会場なし→**物理会場選定は対象外** | 会場が未定/候補未確定なら後続準備への依存関係から**P2候補** | 規模・アクセス・設備等の希望を整理する／候補先へ利用条件を確認する |
| **P08 会場** | 施設利用条件・手続き | 物理会場ありで表示。⑨高岡市＋⑧候補/確定＋⑩高岡市地域交流センター明示で公式根拠カードの対象。同センターの利用者が未成年のみか未定なら関係する注意を示す。他施設には適用しない | 該当センターの利用者が未成年のみ/年齢未定→施設固有の**重要確認P1候補**。センターで成人を含む場合も利用条件の確認は残す。他施設の一般確認はP2候補 | 対象センターの管理者へ利用資格、初回の問い合わせ、申込条件を確認する。根拠出典・確認日を提示 |
| **P09 会場** | 設備・備品と利用環境 | ⑫「ある」＋種類選択→該当設備の確認。⑫「思いつかない／不明／未回答」→設備不要とはみなさない。会場未定なら選定条件、候補/確定なら利用可否。物理会場なしの場合はオンライン支援の範囲を別途検討 | 具体的な設備が会場選定・開催形式の前提なら**P2候補**、未指定ならP3の一般確認 | 必要な設備の数量、施設での使用、持込み可否・電源等を確認する |
| **P10 募集** | 募集・告知方法 | 全員に表示。参加対象に応じた伝達方法の検討。告知サービスや募集開始状態は現行入力では未確認 | 初期は**P3**。特定の締切や募集が完了したと推測しない | 募集する相手・募集方法・案内文の基本情報を整理する |
| **P11 募集** | 参加方法・連絡事項 | 全員に表示。未成年参加なら必要に応じ保護者向け情報の確認を補足するがP05の安全確認と重複させない | 初期は**P3**。氏名や連絡先など個人データを収集する機能は作らない | 参加方法、持ち物、集合場所や当日の連絡方法を整理する |
| **P12 募集・開催前** | 開催前の最終確認 | 全員に表示。日時未定なら「日時確定後に行う準備」とする。日付が決まっていても確認済みと推定しない | 初期は**P3**。準備段階で未実施であることを断定しない | 進行表、案内、当日の役割・備品・緊急連絡を開催前に確認する |

### 2.1 「物理的な会場は使わない」の扱い（未確定の支援範囲）

- P07の物理会場選定、P08の施設利用規則、P09の会場備品など**物理会場にしか適用できない内容は対象外**にする。
- 4領域は表示してよいが、③会場領域の説明には**「開催方法・利用環境は対応範囲を確認中」**と記し、オンラインイベントの配信方法・プライバシー・通信環境を十分に支援できると断定しない。
- オンライン開催をMVPの対象に含めるかは未決定。物理的な会場がないという理由で架空の開催地域や施設条件を作らない。

## 3. 優先候補の選定と説明（提案ルール）

1. **該当性判定**：入力条件から、そのイベントに関係のある12項目を選ぶ。施設固有の公式情報は対象施設が**本人により明示**され、[公式根拠台帳](OFFICIAL_SOURCE_REGISTER.md)で対象と確認日を追える場合だけ紐付ける。
2. **状態を別に付ける**：日時/会場/責任者など、回答済み/未定/未確認を区別する。「条件が決まった」ことと「必要な作業が完了した」は別。
3. **P1を候補化**：子ども向けの見守り・安全体制や、該当施設の利用上の重要注意を優先して確認する。**P1は危険認定ではなく確認の優先候補**。
4. **P2を候補化**：会場、日時、責任者、必要設備など、別の準備が依存する未定事項・条件の確認。未回答は不足の確定ではないので、理由を「状況が分からないため確認」と書く。
5. **P3を保持**：募集、連絡、進行、開催前の確認など。P1/P2より低くても**準備の全体像から消さない**。
6. **代表カード**：該当する最上位の候補を1件選び、「何を確認するか」「なぜ優先か」「今できる具体的な行動」を紐付けて提示。同じ優先度が複数なら**同順位**として残し、代表の選択は公開した一定の並び順で固定する（例：P08の該当施設の重要確認→P05安全→P07会場→P04運営→P03時期→P09設備→残りID順）。この並びは**未確定の設計例**であり、最適性を証明したものではない。
7. **詳細入力後に再評価**：⑥⑪⑫等が入力・変更されれば全項目を現在の入力から再計算。以前の条件から生成した施設固有の注意や優先カードは残さない。
8. **根拠の表示**：「入力から分かる事実」「準備上の一般的な提案」「公式情報の条件」の3つを区別。公式情報には対象施設・リンク・確認日・利用可否は個別確認の注記を付ける。

**会場が『本人申告では確定』でもP08の手続き確認は残す。『予定人数15人』から施設の収容可否は判定しない。日付から架空の申込期限を表示しない。**

## 4. 結果画面の出力契約（STEP3-⑭の採用方針に対応）

出力は以下の**4ブロック**。最初の行動1件だけを見せる旧画面へ戻さない。

| 画面上のブロック | 必ず含む情報 | 非表示にしてはいけないもの |
| --- | --- | --- |
| **優先する確認事項** | 見出し、本人入力に基づく理由、P1/P2/P3の意味、未確認の限界 | 複数該当する重要な確認を裏で捨てない |
| **次にできる行動** | 対応する1件の具体的な行動、必要なら適切な問い合わせ先の種類 | 個別の許可・予約・安全の保証をしない |
| **準備の全体像** | 4領域にまとめた12基本項目（該当時の説明・対象外状態、未定/未確認を区別）、重要なほかの確認 | 優先度が低いという理由だけで他項目を消さない |
| **根拠と詳細化** | 施設の出典/確認日、一般的助言との区別、任意詳細を加えた際の再評価導線 | 古い条件、他市町村・別施設への誤適用 |

ここでの12項目は「イベント開催の合法性・安全性に必要な作業の網羅」を保証しない。

## 6. 残る設計判断と実施していないこと

- **未確定**：12項目の最終採用、同順位時の表示順、より細かな条件（火気・食品・屋外開催などは今の6問では判断不可）、オンライン開催の対応範囲、相談文コピー/持ち帰り手段の具体方式。
- **再確認が必要**：高岡市の施設規定の更新、条件と年齢構成の個別適用。必要な場合は利用者自身が施設管理者へ確認する。
- **実施していないこと**：コード実装・自動テスト、外部への連絡、利用者インタビュー/評価、募集・予約・申請。設計上の期待結果を「テストに通った」と表現しない。
