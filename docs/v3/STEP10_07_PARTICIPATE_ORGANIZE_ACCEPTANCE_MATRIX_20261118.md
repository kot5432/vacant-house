## 4. 画面の空状態・異常系
- D00：入口は両方独立。D01用の掲載データが一時空でもU01にアクセスできる。
- D01：0件の場合は絞込解除と原ポータルへの案内。読み取りカタログ破損時は「データを表示できません」、架空のカードを作らない。
- D02：未確認は明示。根拠のない申込ボタンなし。URL不正のときリンクを非表示/掲載停止。
- U02〜U04：保存・編集・競合の既存契約を守る。参加画面に入っただけでIndexedDBの記録を変えない。
- 画面幅320px、拡大率200%、キーボード、読み上げでも「未確認」「受付終了」「保存済み/未保存」が文字で区別されることを後日試験。

## 5. ユーザー価値の検証設計（実施前）
2群を別々に比べる。参加希望者：サポナビ/既存サービスの実際の公開案内 vs D01/D02の**同じ活動情報**。主催希望者：行政の一般ページ＋通常チェックリスト vs U02/U03。比較前後で、本人が「次の行動と理由」を説明できるか、元情報から正しく参加条件/相談先を探せるかを観察。**情報量/提示時間を合わせる**。AI推薦機能・イベント数の多さで比較しない。具体的な人員、質問者、実施日、結果は空欄のまま。
