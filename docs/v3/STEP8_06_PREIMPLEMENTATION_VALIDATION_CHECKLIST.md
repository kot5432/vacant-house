# STEP8-⑥｜設計から実装前検証へ移るための品質・利用者検証チェックリスト（草案）

作成：2026-11-16。**設計のみ／実際の検証・公式サイト原ページ再照合・実装・CI・デプロイは未実施**。現行の地域イベント開催準備支援アプリのみ対象。旧空き家所有者・物件登録・マッチングを含めない。

## 1. 既決事項を守るための確認順

1. **価値仮説**：利用者は初めての小規模イベント主催者か。6問でイベント条件が伝わり、P01〜P12全体像と「次の一歩」が理解できるか。
2. **推奨の根拠**：P05は未成年を含むとP1、成人・対象未定はP2（ADR-003）。P08は施設出典の一致だけでP1へ自動昇格しない（ADR-027）。その他の未決優先度を既決として実装しない。
3. **地域情報**：利用条件の有効性・対象範囲・公式確認日を出典台帳と突合。期限切れ時は施設固有断定を停止（ADR-009〜012）。原ページを実際に照合する前に「確認済み」と表示しない。
4. **保存安全性**：U02初回下書きは永続保存しない。U03進捗とU04入力修正を別責務にし、revision比較・needsRecheckの明示解除・旧入力不適合時の保護を確認（ADR-004/025/026）。
5. **JSONバックアップ**：形式と版（ADR-022）、元日時（ADR-023）、復元時revision（ADR-018）、容量（ADR-019）、本人選択書出し（ADR-020/021）、重複復元（ADR-016/017）を相互に満たす。
6. **端末とアクセシビリティ**：モバイルSafari・Chrome／デスクトップ主要ブラウザ、スクリーンリーダー、キーボード、IME、拡大表示。**テスト計画の期待値と実測結果を別管理**。

## 2. 利用者ヒアリング案（未実施）

| 場面 | 利用者への課題 | 観察する事実 | 仕様上の禁止 |
|---|---|---|---|
| U02 | 初めて企画する小規模体験会を設定する | 6問の迷い、入力スキップ、かかった時間 | 未入力から施設や法的義務を断定しない |
| U03 | 「まず何をするか」を説明してもらう | 理由と優先順位の理解、P05/P08の誤認 | P2を「申請必須」と説明しない |
| U04 | 会場を変更し保存・再確認をする | 入力保持、取り消し、needsRecheckの意味 | 既存進捗を勝手に初期化しない |
| U01 | 150件中100件を選択しバックアップ、残りを別ファイルにする | 未選択件数、2 MiB上限、保存先の理解 | 自動で100件だけに切り詰めない |
| U01 | 同じバックアップを再び取り込む | プレビューと複製増加への理解 | 確認前に追加しない |

利用者には「正解を当ててもらう」のでなく、画面だけを見て理解した内容とつまずきの発生箇所を記録する。イベント主催経験の有無・イベント種類などの属性は分析目的に最小限とし、氏名・連絡先・個人情報は不要なら収集しない。検証対象者数や合格基準は計画案として別途設定し、実施済みと記載しない。
