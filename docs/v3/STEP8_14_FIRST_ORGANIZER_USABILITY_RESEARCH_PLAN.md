# STEP8-⑭｜初主催者による中心価値の検証計画・観察記録票（実施前）

作成：2026-11-16。現行の小規模・単発地域イベント準備支援Webアプリの**利用者検証計画だけ**。参加者募集、インタビュー実施、計測、実際の画面操作、実装はしていない。旧空き家所有者／物件の需要検証とは切り離す。

## 1. 検証する価値仮説

「初めて小規模地域イベントを主催する人は、6問に回答してP01〜P12の準備全体像と自分が始める一歩を理解できる。優先理由の説明があれば、自分に合う準備順だと納得できる」。**まだ実証していない**。満足度だけでなく本人の説明・具体的な次の行動を観察する。

## 2. 対象・進め方の提案（人数は実施計画の仮案）

- 対象候補A：初めて体験会・交流会などを企画したい人（本命）。
- 対象候補B：過去に1〜2回、地域イベントの企画を経験した人（説明の見落としを発見する補助）。
- **初回は各対象の混在で4〜6名程度の探索的なユーザビリティ検証を推奨**。これは統計的な需要証明や正解率の有意差を主張できる人数ではない。人数の確定や募集は未実施。
- デザイン試案、文章ワイヤーフレームでも机上の理解検証は可能。ただし動作実験と同等と扱わない。参加者に説明しない状態で操作した内容を優先して記録する。
- 個人名や連絡先は成果記録表へ原則書かず、識別は参加者ID。未成年者への参加依頼や録音・撮影は主催者の適切な同意・安全配慮と学校／保護者等の必要な手続きの範囲で検討。招待・実施・録音は今回行わない。

## 3. セッション構成の提案（未承認の実施目安）

| 段階 | 依頼すること | 記録する観察 | 誘導しない事項 |
|---|---|---|---|
| 導入 | 架空の小規模イベントをこれから主催すると想定 | 経験の有無と不安の種類 | 開催に必要な行政手続きの正解を言わない |
| U02 | 基本6問を回答し、準備プランを読む | 回答の迷い、未定の理解 | 「未定は悪い」と誘導しない |
| U03 | 今まず何を確かめるかを自分の言葉で話す | 代表タスク・理由・次の一歩の理解 | P1が法的義務だと示唆しない |
| 進捗 | 完了／対象外／再確認を比較する | アプリによる判定と本人判断の区別 | 完了＝許可・安全を保証しない |
| U04 | 会場候補を変え、保存と戻るを扱う | 未保存と保存済み、再確認の理解 | 保存成功前に成功と説明しない |
| U01 | 150件中から対象を選んでバックアップする想定 | 含まれない50件の理解、端末保存の認識 | 全件バックアップ完了と偽らない |
| 振り返り | 実際にイベントを開くなら最初に何をするか | 行動の具体性、画面で分からなかったこと | 誘導質問や過剰な賛辞 |

## 5. 集計と判断の仕方

- **定量の参考値**：最初のタスクを自力で発見した人数、優先理由の説明に納得できた人数、進捗を誤認した人数。小標本なので「需要がある」と結論付けない。
- **定性**：混乱した用語・表示順・不要な入力・本当に次の一歩が分かるか。必要な機能を推測ではなく利用者の発話・行動に基づき整理。
- **軽微な改善**：文面、余白、見出し、アイコンの説明、エラー文言、チェックボックスの配置など。既決の意味・保存仕様は保つ。
- **重大な変更の相談が必要**：基本6問の増減、P01〜P12の構成、ADR-028の優先度条件変更、新たな法的義務判定、個人情報収集の拡張。
- **合格条件を後から都合よく変更しない**：初回は探索的な課題発見目的とし、正式なリリース判定基準や成功率は実施前に別の審査で固定する。

## 6. インタビューだけで確認できないこと

- 実際の法的義務、施設の許可可否・予約可能性、安全性は公式窓口・関連制度の個別照合が必要。
- スマートフォンでのファイル保存・IndexedDBの競合や異常時の挙動は**コード／実機試験なしには保証できない**。
- 参加者が良いと言っても、日常的な需要・継続利用・地域課題の改善効果が実証されたわけではない。
- まだ募集・調査・ヒアリングを実施していない。
