# STEP6-③｜残る入力・施設情報保持の決定ゲート（2026-11-15）

> 状態：ユーザー確認前の選択肢比較。既決事項（[ADR-001](ADR_001_TECH_STACK_ADOPTED.md)技術、[ADR-002](ADR_002_NO_PHYSICAL_VENUE_SCOPE.md)物理会場なし、[ADR-003](ADR_003_PRIORITY_RULES_ADOPTED.md)優先度、[ADR-004](ADR_004_EXPLICIT_RECHECK_CLEAR.md)再確認解除）は変更しない。現行イベント準備支援Webアプリ専用。旧空き家や物件DBは対象外。コード・テストなし。

## 1. 最初に決める：非該当になった施設固有回答をどう扱うか

例：高岡市の地域交流センターを利用する予定で、候補施設カテゴリと施設利用者構成を入力済み。その後、会場状態を「物理会場なし」、または開催地域を他地域へ変更した場合。

**必ず守る条件**：新しい入力条件で対象外の施設固有情報は、優先順位・公式出典の適用・P08の注意文章に使ってはならない。以前の進捗（完了／本人対象外）と、必要な再確認履歴を安易に削除しない。

| 項目 | A案：入力値を保持する | B案：非該当の施設固有入力を消す |
|---|---|---|
| 再び同じ施設を選ぶ | 以前の入力を再提示できる | 再入力が必要 |
| 古い情報の誤適用 | 現在の条件に応じた無効化と再選択時の再確認が必須 | 古い入力を引き継がないので単純 |
| データ最小化 | 現在使わない施設情報が残る | 保存する情報を最小化できる |
| 編集を取り消したい場合 | U04の編集ドラフトを破棄すれば旧入力を保持 | **U04確定保存時のみ**消去、キャンセルなら元の値を保持 |
| 開発とテスト | 入力値の「保存済だが判定対象外」を厳密に区別 | 確定前データと永続データの差分・クリア確認が必要 |
| 推奨 | 長期の行き来が多い場合に有利 | **B案を推奨（MVPでの誤適用抑制とデータ最小化）** |

### B案を選ぶ場合の詳細

1. U04で変更中は確定DBを変えない。キャンセルすればすべて元のまま。
2. 「変更を反映する」時に、基本6問の最新条件で施設固有入力の該当性を判定する。
3. 非該当となった**施設カテゴリ、施設利用者の年齢構成、施設名の任意メモ**をイベント本体から削除または`unanswered`へ正規化する。**実際の削除フィールド一覧・再確認reasonCodesは採用時に明示**。
4. 保存成功とともにP07〜P09の現行説明・公式根拠を再計算。旧進捗`status`は保持。影響する完了／本人対象外のタスクへ再確認を付与。
5. 元の施設条件に戻しても古い施設固有値を自動復元しない。必要なら本人が施設情報を入力し直す。
6. 確定保存が失敗した場合は、以前の施設情報はDBに残り、画面内の編集ドラフトは維持して再試行する。
7. **対象外という理由だけで全イベントの入力や本人のタスク進捗を一括削除しない**。

### A案を選ぶ場合の詳細

- 施設カテゴリ等を保存済みでも、現在`region/venueStatus`の条件が非該当ならルールエンジンへ渡さない（現在条件から明示的な射影値を作る）。
- 以前の施設に戻した時も**本人に改めて選択を確認**し、旧値で施設公式条件や完了を自動確定しない。
- 自由記述施設名・参加対象から該当センターの利用条件を推定しない。
- 個人情報が残り得る任意メモは表示と削除機能を検討する。

## 2. 次に決める入力検証（この文書では保留）

| 論点 | 推奨案と理由 | 決定待ち |
|---|---|---|
| 過去の日付 | 警告を出して入力は保持する。日時の表記違いで一律に入力不能にしない | 要確認 |
| 人数の上限 | 1以上の安全整数をまず検証。小規模MVPとして極端な数の注意・上限は定義が必要 | 要確認 |
| 任意メモ上限 | 施設名100字・イベント説明500字程度を暫定候補。画面上の文字数カウントと保存の基準を一致 | 要確認 |
| 条件付き入力の空欄 | 未回答を「未定」と勝手にみなさず、施設固有の条件を断定できないと表示 | 現行原則と整合 |
| 公式出典の更新頻度 | リリース前点検＋古い情報の非表示/再確認を必須。定期更新の運用者と周期は別途決定 | 要確認 |
