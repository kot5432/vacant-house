# 技術選定 ADR-001｜正式採用（2026-11-15）

**状態：ユーザー明示承認済み。設計の決定であり、コード生成・依存インストール・デプロイ・利用者テストは未実施。**

## 対象
初めて単発・小規模の非営利地域イベントを主催する人向け「準備の全体像と状況別優先順位」を提供するWebアプリ。**旧空き家所有者診断、物件登録・マッチング、開業支援、障壁入力→相談文コピー案は対象外。** GitHubリポジトリ名 `vacant-house` は履歴上の名称である。

## 採用決定

| 領域 | 決定 | 範囲 |
|---|---|---|
| フロントエンド | **React + TypeScript + Vite** | ブラウザで動く静的SPA |
| 永続化 | **IndexedDB + Dexie** | ログインなし、同一ブラウザ内のイベント・進捗・削除・版管理 |
| デプロイ先 | **Vercel** | 静的アセットの公開、GitHub連携・プレビュー運用 |
| サーバーDB／Auth | **採用しない（MVP）** | データを共有サーバーへ保存しない |

**重要：** ユーザーが明示的に承認したのは上表の3つの選定とサーバーDB不要の既存MVP方針。テストランナー、CSS方式、ルーティング、状態管理、バリデーションの追加ライブラリは以下の「推奨・未確定」に分ける。

### 推奨・未承認の周辺技術
- **Vitest**：純関数の判定ルール・バリデーション単体テスト。
- **Playwright**：ブラウザのIndexedDB操作、再読み込み、2タブ競合、UI E2E。
- **CSS変数＋CSS Modules等**：依存を増やさずデザイントークンを管理。Tailwindも代替候補。
- **React標準状態**：4画面では必要な範囲から始め、複雑になればStoreを導入。
- **React Router または同等のルーティング**：SPAの直接URLやVercel rewriteと整合。選択未確定。
- **バリデーションは共有スキーマ**：TypeScript型だけでは保存時の実データ検証にならない。Zod等は比較後採否。

## 採用理由

- **要件適合**：4画面、基本6問、ルールエンジン、生成後の進捗更新、同一ブラウザで複数イベント再開。SSR、外部AI推論、アカウントは不要。
- **AIコーディングのレビュー性**：TypeScriptの型、純粋関数、保存Repository、UIをファイル・責務別に隔離して、レビュー役が差分とテストを確認できる。
- **保守性**：ルール版・データスキーマ版・出典版を分離。施設条件は特定の該当条件にのみ適用。
- **Vercelとの適合**：Viteは静的成果物を出力可能で、Vercelで配信できる。Vercelを選ぶためにNext.jsを導入する必要はない。
- **運用負荷**：クラウドDBの運用を不要にできる。ただしブラウザデータの消失リスクは残る。

## 他案を採用しなかった理由

- Next.js：サーバー機能とSSRの利点を現MVPでは必要とせず、クライアント境界の注意点が増える。将来必要になれば再検討。
- Vue/Svelte + Vite：実現可能だが、今回はReactを選択。製品価値の優劣ではない。
- localStorage単独：トランザクション・競合更新・複数イベントの扱いでIndexedDBを優先。
- Cloudflare Pages：静的ホスティングとして適するが、今回Vercelを選択。旧提案資料のCloudflareは**不採用の比較候補**。

## 採用に伴う注意

1. IndexedDBは**サイトのオリジン単位**。VercelプレビューURL、本番URL、ローカル開発URLでデータは自動同期されない。
2. 「このブラウザに保存」はバックアップ成功を意味しない。ブラウザの容量不足、サイトデータ削除、プライベートモードで失われ得る。
3. 進捗はU03から自動保存、イベント条件はU04の「反映する」で確定保存。初回U02の未完成下書きを永続保存するかは**別途未決**。
4. Vercelのプロジェクト設定、価格・Hobbyの個人／非商用制限、チーム権限を公開前に確認。**アカウント・契約・公開操作は行っていない**。
5. `/events/:id` の直接アクセスはSPA rewriteを検討。未確認のルートや静的アセットに誤った200応答を返さないようE2Eで確認する。
6. 使用依存のバージョンは実装開始時に固定し、lockfileとCIを整備する。バージョン番号を現在決め打ちしない。
