# ADR-020｜JSONバックアップ上限超過時は本人がイベントを選択して分割書き出し（A案正式採用）

決定日：2026-11-15。ユーザーが[STEP7-⑯](STEP7_16_EXPORT_SPLIT_OPTIONS.md)の**A案**を明示採用。現行の「初めて単発・小規模の地域イベントを主催する人向け準備支援Webアプリ」専用。旧空き家・物件・所有者・マッチングのデータは対象外。**設計のみ、コード実装・動作試験・Vercel公開なし**。

## 正式に決定した内容

- 保存済みイベントが1ファイルの上限を超えた場合、**本人が出力対象のイベントを選択**し、上限内のJSONを1ファイルずつ書き出せるようにする。残りも本人が別の操作で選択して書き出す。
- [ADR-019](ADR_019_JSON_BACKUP_LIMIT_2MIB_100_EVENTS.md)の上限は**1ファイルあたり最大100件、かつ完成UTF-8 JSON最大2,097,152バイト（2 MiB）**。**両方**満たす必要があり、上限ちょうどは有効。
- **勝手な間引き、先頭100件への自動制限、全文・進捗・由来情報の無断切捨て、自動複数ファイル生成はしない**。選択範囲と未選択件数を必ず明示する。
- エクスポートの対象は**保存成功済みEventRecordのみ**。U02未完了入力、U04未保存ドラフト、U03未コミットの進捗変更を「バックアップ済み」と誤表示しない。
- 本人の選択IDに該当するレコードを整合した読取時点で抽出し、**完成したBackupEnvelope JSONの実UTF-8バイト数とeventCount**を計測してから書き出し可否を確定する。概算は表示補助に限り、上限判断の正本ではない。
- 書き出し後の元DB・保存進捗・revisionは変更しない。**ファイルの生成やダウンロード開始は、端末での確実な保管完了を意味しない**。ほかのイベントが未出力なら「全件バックアップ済み」と表示しない。
- JSONのインポート側の上限、[ADR-015](ADR_015_JSON_BACKUP_EXPORT_IMPORT.md)〜[ADR-018](ADR_018_RESTORED_EVENT_REVISION_AND_PROVENANCE.md)の検証・衝突時別ID複製・本人承認・原子的追加・復元日時はそのまま。

## U01画面の決定事項

1. ホームの保存イベント一覧を主操作から分離した**「バックアップを書き出す」補助導線**を設ける。
2. 既存イベントをチェック選択可能とし、**選択件数／保存済み総件数／このファイルに含まれない件数**を常時確認できる。
3. 上限を超えた場合は具体的な理由（選択101件、完成JSONが2 MiB超など）を示し、本人が対象を変更できる状態に戻す。勝手に一部だけ書き出さない。
4. エクスポート確定前に「このファイルに含まれるX件／含まれないY件」を明示。**未選択イベントはこのファイルには含まれない**と注意する。
5. 書き出し後も同じ補助導線から残りを選択して別ファイルに書き出せる。複数ファイルの自動管理・復元時の自動一括読み込みはMVPには追加しない。
6. 保存中に別タブで削除・更新された場合、**選択していた件数と実スナップショットのIDが変わったことを黙って無視しない**。安全側に処理を停止し、最新の対象一覧を確認させる。

## 実装前の細則と未決の部分

- 選択UIのチェック操作と「すべて選択」の具体挙動、0件選択時のボタン状態、選択の初期値、ファイル命名規則、複数回分割したファイルを区別する案内は**詳細UI案として別途整える**。
- **1イベントだけ**で完成JSONが2 MiBを超える場合、選択を減らしても解決しない。現行の2 MiB上限を維持し、1イベント内部の分割・部分的なデータ欠損を勝手に導入しない。利用者へ理由を説明する。この問題は書記素の極端な長さを含む入力の技術上限検証にも依存。
- 「複数回に分けて書き出したイベントの全件網羅」を自動追跡する履歴テーブルは本ADRでは追加しない。ファイル単位で未選択件数を正確に案内する。
- 署名・暗号化・クラウドアップロード等はMVPで導入しない。JSONは個人のメモを含み得ることを説明。

## 受入テスト（期待値、未実行）

| ID | ケース | 合格条件 |
|---|---|---|
| SELECT-01 | 150件から100件を選択、生成JSONが2 MiB以内 | 選択された100件だけを含む。未選択50件を明示 |
| SELECT-02 | 150件を全件選択 | 勝手に100件へ絞らず、件数超過エラー |
| SELECT-03 | 99件選択でも完成JSONが2 MiB超 | 書出しを拒否、本人に再選択を促す |
| SELECT-04 | 最初に100件、次に残り50件を選択 | それぞれ独立した有効JSONを作れる。元DB不変 |
| SELECT-05 | 1件の完成JSONが2 MiBを超過 | 部分削除して救済せずエラーと制約を説明 |
| SELECT-06 | 選択IDが別タブで削除された | 実際の選択を勝手に変更せず、再確認を要求 |
| SELECT-07 | U03保存中・U04未保存ドラフト | 未コミット変更を「書き出し済み」と扱わない |
| SELECT-08 | モバイルでダウンロードをキャンセル | 端末への保存完了を主張せず、元DB不変 |
| SELECT-09 | 書出したファイルをインポート | 100件・2 MiBの上限と形式に適合することを検証 |
| SELECT-10 | 0件選択 | 意図せぬ空バックアップと誤解させないUIを検証 |
| SELECT-11 | JSONに日本語・絵文字・由来情報 | 完成UTF-8 JSONの実バイト数で容量判定 |
