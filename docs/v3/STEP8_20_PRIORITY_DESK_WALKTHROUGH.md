# STEP8-⑳｜ADR-028優先順位の机上ウォークスルーと残る設計リスク

作成：2026-11-16。**文書仕様から人が計算した予想結果の机上レビュー**。コードを動かした結果、ブラウザ操作、初主催者への調査、現実のイベント準備効果の実証ではない。対象は現行の地域イベント準備支援Webアプリ。旧空き家案なし。

## 1. 前提（全例）

- 入力は基本6問すべて有効な架空の回答。別途明示した任意入力以外は`unanswered`。進捗は特記なければ全タスク`not_started`・`needsRecheck=false`。
- [ADR-028](ADR_028_LIMITED_P2_PRIORITY_BY_EXISTING_INPUTS.md)によるP01〜P04/P07/P09の限定P2、P05とP08の既決、P06/P10/P11/P12=P3。
- 代表は全未解決をP1→P2→P3、同優先度ID小さい順に評価。公式施設出典の適用状況はP08自動P1の理由にしない。
- 以下は**対象12タスクすべてのうちpriorityに影響するもの**を明示。タスクの完全な該当性と子チェックは別の既決契約で評価する。

## 2. 架空の6シナリオ

| ID | 架空イベント条件 | P2以上となるタスク（既決表からの推定） | 未解決代表の推定 | 観察した設計上の特徴 |
|---|---|---|---|---|
| DESK-01 | 体験会、子どもと大人、開催月のみ、会場候補、高岡市、個人主催 | **P05=P1**、P03/P07/P08=P2 | **P05** | 「会場の確認」より子どもを含む参加者の見守りを先に示す |
| DESK-02 | その他、参加対象未定、開催日確定、会場確定、高岡市、主催形態=団体 | P01/P02/P05/P08=P2 | **P01** | 同優先度ではID順。企画内容→参加対象を示す |
| DESK-03 | 交流会、大人、開催日確定、会場なし、地域未定、個人主催、設備未回答 | P05/P08=P2 | **P05** | P07/P09親はneeds_information・P3の一般確認を残し、「オンライン」と断定しない |

全ケースの`P01〜P12`のうち上記にないものは原則P3と想定。ただし`applicability=no`の場合には表示用のpriorityがnullとなる既存契約が優先される。**実装時に全件フィクスチャで再確認が必要**。

## 3. 机上レビューで顕在化したUXの注意点

1. **P05が成人対象でもP2**のため、会場未定のP07=P2よりIDが若いP05が代表になる。これはADR-003で採用した同順位ルールから自然に生じる挙動。もし「会場未定なら絶対にP07を先に」と変更するなら**別のユーザー製品判断が必要**。
2. **P08は一般的な利用条件確認としてP2基本**なので、会場確定の人にもP2で残る。「許可が必要と判定された」という意味ではなく、「確認することを勧める」という説明を明記する。
3. イベント種類が`other`の場合P01=P2になるが、内容が悪いと診断していない。P01の理由文は**本人の回答に基づく整理提案**に限定する。
4. `no_physical_venue`で`equipmentNeed=yes`ならP09=P2になり得る。これは建物設備の予約ではなく、開催方法に必要な環境・備品全般の確認として説明する。
5. 任意責任者の`unanswered`と`undecided`を混同するとP04の誤昇格が起こる。UIの文面と正規保存値が一致することをレビューする。

## 4. 机上の判定と実証の線引き

- **この結果から確認できること**：文書上のP1/P2/P3・同順位ID昇順から矛盾のない説明が作れるか。
- **確認できないこと**：実際の初主催者がこの順位を妥当と感じるか、入力を正しく理解できるか、実機で保存・再開・復元できるか、地域のイベント準備が成功するか。
- **利用者確認への持ち込み候補**：DESK-03の「会場なしでもP08確認」、DESK-04の「時期未定を優先」、DESK-06の「未成年参加と施設利用主体の違い」。回答に誘導しない。
- **ユーザー判断が必要になる場合**：現行の順番を変更したい、P01〜P12の新P1を増やしたい、基本6問を増減したい、法律・施設の利用可否判定を追加したい。
