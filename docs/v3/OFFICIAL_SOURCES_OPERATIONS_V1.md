# 公式出典台帳・情報更新運用 v0.1（2026-11-15）

> **運用設計案。現時点で公式サイトの最新文書・利用条件の実地再確認は行っていない。出典IDやURLは検証後に台帳へ登録する。** 対象は初めての地域イベント準備支援Webアプリ。旧空き家データ・施設マッチング・行政申請の代行ではない。
> 関連：[ADR-002](ADR_002_NO_PHYSICAL_VENUE_SCOPE.md)、[ADR-005](ADR_005_CLEAR_INAPPLICABLE_FACILITY_INPUT.md)、[開発運用計画](DEVELOPMENT_OPERATIONS_PLAN_V1.md)、[判定契約](RULE_ENGINE_CONTRACT_V1.md)。

## 1. 提供する公式情報の境界

- MVPでは**高岡市の本人選択した施設カテゴリに限定**して、出典・確認日・対象条件とともに利用者自身の確認先を案内する。
- `region=takaoka`だけで出典を表示しない。候補／本人申告確定、本人の明示施設カテゴリ、出典台帳の対象・条件の一致を検査。
- `no_physical_venue`では建物施設の出典を現在の結果から外す。屋外やオンラインの許可が不要と断定しない。
- 施設の空き状況、利用承認、法的適合、安全保証、申請が通るか、費用の確定額などをアプリで自動判定しない。
- **出典本文を丸ごと引用しない**。URL、短い事実確認項目、適用範囲、必要なら管理者へ確認する一歩を表示。

## 2. 推奨する版付き出典台帳

| フィールド | 意味・検証 |
|---|---|
| `sourceId` | Gitで維持する安定ID。別施設へ使い回さない |
| `title`, `publisher`, `url` | 公式ページの名称・管理者・確認できたURL。推測で生成しない |
| `sourceType` | 利用案内／申請手続き／利用規約／料金案内等 |
| `facilityCategory`, `region`, `applicabilityPredicate` | 適用する施設・地域・本人入力の条件 |
| `checkedAt` | 担当者が元ページを最後に確認した日付。公開日・改定日とは別 |
| `publishedAt`, `revisedAt` | 元資料に記載がある場合のみ記録（不明なら不明） |
| `summary`, `actionHint` | 誤解を招かない短い説明、利用者が行う確認 |
| `status` | `verified / needs_review / suspended / retired`。`verified`以外は自動的な施設固有断定の根拠としない |
| `sourceRevision` | 内容変更時に増やす版 |
| `verifiedBy`, `reviewNotes` | レビュー担当と判定理由。個人情報の記録は最小化 |

*運用頻度は[ADR-009](ADR_009_OFFICIAL_SOURCE_MONTHLY_RELEASE_REVIEWS.md)で月1回＋毎本番リリース前に正式採用。台帳の実ファイル形式（TS/JSON）、月内実施日、`verifiedBy`の表現、担当者は未決。*

## 3. 更新のワークフロー

1. **初回登録**：公式の原ページへアクセスし、公開元・URL・適用施設・注意点・確認日を二人目が照合。確認不能なら`needs_review`にして施設固有の断定文を出さない。
2. **公開／リリース前**：既に登録されている公式出典への到達性、文言・対象施設・改定日、掲載条件の変化を確認。リンク切れや改定疑いは`needs_review`/ `suspended`へ変更。
3. **差分の審査**：改定で出典の適用条件が変わる場合は、`sourceRevision`やルール版、タスクP08等への影響、過去完了タスクへの再確認要否をレビュー。
4. **変更反映**：出典とルールの版をGitで追跡。PRに対象条件・検証日・画面表示例・テスト差分・レビュー者を記載。
5. **利用者への影響**：利用者の進捗を自動完了／未着手に書き換えない。影響を確認できる場合のみ`needsRecheck`を付与。旧出典条件の表示を停止し、一般的な「管理者に確認する」案内へフォールバック。
6. **誤案内の疑い**：最初に危険な断定表現や施設固有の誤情報を停止し、再確認後に修正。施設・行政が審査済みだと表示しない。

## 4. 表示可否ゲート（推奨）

| 台帳状態 | 出典の取り扱い |
|---|---|
| `verified`かつ現在条件が適用対象 | 出典名・公式リンク・確認日・対象範囲・注意付きで表示可能 |
| `verified`だが利用者条件が対象外 | 該当イベントの現在のプランには出さない |
| `needs_review` | 確定的な施設条件を表示しない。一般的な確認案内のみ |
| `suspended` | 施設固有の表示を直ちに停止 |
| `retired` | 現行プランから除外。削除した本人の進捗履歴は復活させない |
| ページが一時的に取得不能 | 断定を停止し、利用者には管理者への確認を案内 |

**重要な制限**：ブラウザ内だけで動く静的SPAは、ユーザーが古いアプリの配信物を開いたままの場合、**遠隔から即時に古い表示をすべて停止させる保証がない**。急ぎの訂正はVercel側の公開資産更新と再読み込み案内を組み合わせ、更新確認の設計・テストを必要とする。オフライン利用の保証はMVP範囲外。

## 5. 出典版と保存ルール版の関係

- `sourceRevision`は公的情報の更新、`rulesVersion`はアプリの条件判定の更新、`schemaVersion`はDexie保存形式の変更を意味する。
- ルールや出典の更新で本人の完了歴を自動削除しない。変わった施設条件に依存する場合だけ再確認を検討。
- 現在の入力が対象施設から外れたときは[ADR-005](ADR_005_CLEAR_INAPPLICABLE_FACILITY_INPUT.md)に従い施設固有回答をクリアし、古い出典を新条件へ流用しない。

## 7. 次の確認ゲート

- **確認頻度は[ADR-009](ADR_009_OFFICIAL_SOURCE_MONTHLY_RELEASE_REVIEWS.md)で決定済み**：初回掲載前／月1回／毎本番リリース前。担当者・月内実施日・不在時の代行はチーム内で指定する。
- 運用開始前には**実際の高岡市公式資料にアクセスし、対象条件・URL・更新日・施設への確認先を検証**して台帳登録する。**本書は最新の条例・施設利用案内の内容を確認済みと主張しない**。
- 情報が未確認のときは安全側の「一般確認のみ」を優先。イベント開催に必要な全ての制度を網羅すると表示しない。

## 8. 状態遷移と更新停止・再開（詳細設計案）

[公式情報の状態遷移・誤案内停止・再開表](OFFICIAL_SOURCES_STATUS_TRANSITIONS_V1.md)で`verified / needs_review / suspended / retired`の遷移と、旧タブへの即時反映を保証できない限界を整理した。**月1回点検と毎リリース前点検はADR-009正式採用**。初回登録・各リリース前の確認と出典レビューを、開発前の運用決定で確定する。最新の高岡市公式文書の確認実施を意味しない。

## 10. 月次＋毎リリース前の更新頻度（ADR-009正式採用）

初回掲載前、**月1回**、**毎回の本番リリース前**に原ページと対象施設／適用条件／確認日を点検する。変更・誤案内疑いを把握したら期限を待たず`needs_review/suspended`にし、施設固有断定を停止する。**月次点検の未実施を確認済みと誤表示しない**。担当者・月内実施日・代行・未点検の猶予／停止基準は未決。原文の2026-11-15時点の最新確認を本書だけで証明しない。決定正本：[ADR-009](ADR_009_OFFICIAL_SOURCE_MONTHLY_RELEASE_REVIEWS.md)。

## 11. 月次点検の期限超過による表示停止（ADR-010正式採用）

**点検予定期限を過ぎて必要な原ページ確認・レビューが完了していない場合、その出典を`needs_review`相当として扱い、施設固有の断定を猶予なく停止**。一般的な準備確認と公式の確認先への案内は残す。ただしリンク有効性も確認できないときはリンクを無条件に表示しない。最新情報の確認を終え、レビューが完了してから`verified`へ再開。**期限当日の算定、具体的な月内実施日、欠席時代行、旧タブへの更新**は実装前の詳細課題。月次点検はADR-009の確定事項で、失効時の表示方針は[ADR-010](ADR_010_STALE_SOURCE_FAIL_CLOSED.md)で確定済み。出典台帳の過去の公式閲覧記録と現在の最新確認は別。

## 12. 月末の点検締切（ADR-011正式採用）

月次点検は**日本時間の各暦月末日中**に原ページ確認と必要な二人目レビューを完了する。未完了のまま**翌月1日00:00 JST**を迎えた出典は`needs_review`相当として、施設固有の断定を停止。7日猶予、毎月15日固定、前回確認から30日という比較案は採用しない。月内新規登録とリリース前の出典確認が当月分の点検を兼ねる場合は**出典単位・原ページと適用条件・レビュアーの実記録**が一致することが必要。本人のイベント進捗は保持。データモデルと境界テストは[ADR-011](ADR_011_MONTH_END_SOURCE_REVIEW_DEADLINE.md)。古いタブの更新の強制は保証できない。

## 13. 出典の配布方式（ADR-012正式採用）

公式出典の状態・対象条件・確認日・`catalogVersion`は**Viteアプリの静的ビルドに同梱**する。Git上の出典だけを更新しても、開いたままのブラウザへ更新内容は自動反映されない。再検証済みの施設固有案内を再掲載するには、出典を同梱した新しいアプリ版の読み込みが必要。月末失効の安全側の表示停止は同梱データとJST基準で判定する設計。本人の保存済みイベントは出典ビルドとは別のIndexedDBに保持。仕様正本：[ADR-012](ADR_012_BUNDLED_OFFICIAL_SOURCE_CATALOG.md)。
