# STEP22｜富山参加・企画MVPの需要と独自性検証設計

2026-11-19。**対象者の実際の回答、利用観察、比較測定は未実施。** 価値仮説が正しいと決めつけない。

## 1. 調べる仮説（参加と企画を分離）
| 群 | 仮説 | 否定される条件の例 |
|---|---|---|
| 参加希望者 | 地域活動の存在を見つけても、参加条件/申込/第一歩の分かりにくさが障壁 | 既存の一覧/公式URLだけで迷わず行動できる |
| 初主催者 | やりたい活動はあるが、準備の全体像/順序/公的確認先が分からない | 課題は主に資金・スタッフであり手順表示では変わらない |
| 既存競合 | 「情報の網羅性」ではなく「最初の一歩」「優先順位」で差別化できる | 既存のサポナビ/市公式/チェックリストで同じ価値が得られる |

## 2. 短時間のインタビュー（設計のみ）
**参加希望者**：最近参加してみたい地域活動があったか、どこで探したか、条件/申込/費用のどこで迷ったか、どう解決したか、実際に行動したか。一般的な参加意欲だけで需要を判定しない。

**主催希望者**：具体的にどんな単発イベントを開きたいか、準備をどの順番で始めると思うか、最初の1週間で何をするか、公式情報はどこで見つけられるか、何が不安か。許認可・施設利用をアプリが確約しないことも確認。

**中立的な聞き方**：「このアプリがあったら使いますか？」だけでなく「直近の実際の行動」「他の方法」を聞く。相手の個人情報・連絡先を無断記録しない。未成年者対象の調査は学校/保護者/主催者の必要な手続きを確認。

## 3. 既存サイト比較タスク（実行前）
- 参加：同じ実在の個別活動について、既存の公開案内だけを見て「対象・費用・申し込みの必要性・次の一歩」を説明できるか。
- 企画：仮想の「高岡で少人数の交流会を初めて開く」条件で、公式案内+既存チェックリストと今回の画面案を比較。**画面案に正解を先に書かない**。
- 観察指標：本人が次の一歩を自分の言葉で言えたか、根拠のURLを示せたか、未確認を正しく未確認と判断できたか、誤った確信を持った回数。
- 同じタスク、順番の偏りを減らす、参加者の助言なし、比較が公平になるよう情報の鮮度を揃える。実験準備はできても効果の数値は未測定。

## 4. 判断の目安（閾値を採用したわけではない）
- どちらの入口で必要性が高いかは実際の困りごとを根拠に判断。参加側の需要が弱ければ静的情報を公式索引＋確認項目に縮小する案も残す。
- 公式側の更新負担が高い場合、既存ポータルの代替を目指さない。保守可能な情報量を優先。
- 個人情報を取らずに記録する最小限の観察メモ：利用群/タスク/成功した第一歩/誤解/つまずいた画面/改善案。
