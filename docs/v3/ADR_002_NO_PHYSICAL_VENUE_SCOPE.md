# ADR-002｜物理会場なしの一般準備支援（B案・正式採用）

決定日：2026-11-15。**ユーザー採用済みのスコープ決定**。実装・テストは未実施。対象は地域イベント準備支援Webアプリ（旧空き家所有者診断、物件マッチング等を含まない）。

## 決定
1. 基本6問と会場回答 `venueStatus=no_physical_venue` は**維持**し、**オンライン開催だと断定しない**。
2. `no_physical_venue` でも企画（P01-P03）、運営（P04-P06）、募集・開催前（P10-P12）の一般的な準備と優先理由・次の行動を示す。
3. P07〜P09の**施設専用の子チェック項目**（建物の会場選定、室内施設の申込・予約、館内設備の利用）だけを適用外にする。一方で、屋外活動、移動型、オンライン等の形式が未特定であり、**場所の使用条件・届出や安全等が一律不要とは判定しない**。
4. P07（場所・開催形式の確認）、P08（場所の利用条件や手続きが必要かの確認）、P09（必要な環境・備品の確認）の**親タスクを機械的に完了／不要とせず**、該当性は `needs_information` として一般確認を残す。P08の優先区分と説明は施設固有のP1へ自動昇格せず、確認すべきことが不明な一般確認として扱う。形式が確定すれば将来の版で明示的な分岐を追加可能。
5. 屋外施設／公園／道路等の利用申請の要否、配信機材・アカウント・通信・参加者認証等のオンライン固有の条件は**MVPで自動診断しない**。必要なら本人が管理者等へ確認する一般案内に留める。
6. 建物の施設情報を付与するには**地域・会場状態・施設カテゴリの明示選択・公式根拠台帳の適用条件**が必要。`no_physical_venue`時には以前入力した施設カテゴリや施設名メモが残っていても**現在の判定には使わない**。
7. 追加の必須質問は設けない。基本6問は維持する。今後、開催形式の任意追加確認を設けるかは必要性・入力負担を再評価し、別決定とする。

## ルール上の注意

- 上記の `applicable=needs_information` は「何らかの許可が必要」と断定する値ではなく、「今の回答だけでは確認の要否を確定できない」の意味。
- 親タスクの `progress.status=not_applicable` は**本人が手動設定した状態**。一部子項目の非該当と混同しない。
- 明示的な「施設の使用が不要」と、「地域や屋外の使用許可はすべて不要」を混同しない。
- 進捗完了歴がある状態から `no_physical_venue` に変更した場合、以前の前提に依存するP07/P08/P09の完了や本人の対象外判断に再確認を付ける。無関係なP01等は変更しない。
- 元の回答へ戻すときも古い出典を無条件に復活・確定しない。再度、現在の施設条件と出典版で判定する。

## U02の説明文（案）
**Q4 会場の決定状況** の `no_physical_venue` 選択肢に補足：

「建物の会場を使わない場合に選択してください。オンラインや屋外で行う場合も含みますが、開催方法に応じた確認は別途必要になることがあります。」

**U03の説明文（案）**
「建物の会場を使用しないと回答されています。建物の予約・館内設備の確認は対象外として扱います。屋外の使用条件やオンライン開催固有の準備は、このプランだけでは判断できません。開催方法に応じて確認してください。」

実際の文言・配置・アクセシビリティは画面レビューで確定する。

## この決定で変えないもの
- 基本6問→暫定プラン→任意詳細化。
- 保存方式B（IndexedDB/Dexieで生成後保存・後日再開・複数イベント）、初回下書き保存A（生成前は永続保存なし）。
- React + TypeScript + Vite、Vercel。
- 4領域・基本P01〜P12を維持。新しいオンライン専用タスクを作らない。
- 自治体の利用許可・安全性・法的適合を判定しない。施設固有の公式条件を別施設へ流用しない。

## 残件
P05一般安全の基本優先度、同順位代表ルール、親タスクの進捗対象外・再確認操作細則は後続の判定契約審査で正式化。オンライン形式専用機能は現MVPの採用対象ではない。
