# ADR-018｜復元イベントのrevision=1・復元時刻・元日時の由来保持（A案正式採用）

決定日：2026-11-15。**利用者がSTEP7-⑭のA案を明示採用**。現行の地域イベント準備支援Webアプリのみ対象。旧空き家所有者・物件・マッチングのデータを取り込まず、**設計資料のみ（実装・動作試験・Vercel公開なし）**。

## 1. 決定事項

- JSONから**新規追加するすべてのイベント**は、既存eventIdと衝突するか否かにかかわらず、復元先DB上の独立レコードとして **`revision=1`** から開始する。バックアップ元のrevisionを復元先の競合管理に流用しない。
- 新規レコードの **`createdAt` と `updatedAt` は当該復元処理の確定保存時刻**を設定する。ファイルの`exportedAt`を復元日時と混同しない。
- 元の**`eventId`、`createdAt`、`updatedAt`は`importedFrom`由来情報として保持**する。由来情報は本人の入力・進捗とは区別し、**元イベントの履歴との連結・同期を意味しない**。
- 衝突したeventIdは[ADR-016](ADR_016_IMPORT_COLLISION_AS_COPY.md)どおり新しい一意IDを発行、衝突のないものは元IDで新規追加。**既存DBのイベントのrevision・日時・入力・進捗を一切変更しない**。
- 入力、P01〜P12の本人進捗・`needsRecheck`は保存元から継承する。施設固有出典や導出優先度はバックアップから復元せず、復元先の現行カタログ・ルールと利用者条件で再評価。
- 繰返しインポート時も[ADR-017](ADR_017_REPEAT_IMPORT_WITH_CONFIRMATION.md)の**毎回件数プレビュー・コピー増加注意・本人の明示確定**を維持。
- 一括復元は**全件成功か全件失敗**、プレビュー後の衝突分類変更時は再確認。コミット失敗・競合で元DBを変更しない。

## 2. データ契約（フィールド構成を具体化）

新しいEventRecordに付与する由来情報の論理モデル：

```ts
// データ契約の概念を表す擬似型。実装コードではない。
importedFrom?: {
  originalEventId: string;
  originalCreatedAt: string;  // 正規化されたISO 8601日時
  originalUpdatedAt: string;  // 正規化されたISO 8601日時
  importedAt: string;         // 当該復元コミット時刻
};
```

- 保存時、`importedAt = createdAt = updatedAt` とし、一括復元されるイベントは同一の確定時刻を使う設計。
- `originalEventId` は**今回インポートしたJSON上の直接のeventId**。コピーのコピーの場合に履歴配列を伸ばして無限に追跡する仕様はMVPに追加しない。
- `originalCreatedAt` と `originalUpdatedAt` は、インポートしたイベントの直接の保存日時。以前の`importedFrom`を継承して原本の最初の日時を偽装しない。元イベントの日時が不正なら黙って補正しない。
- 元の`revision`を由来欄に残すかは追加の技術検討とし、**復元先レコードのrevision=1は確定**。由来の元時刻・元IDを失わないことは確定。
- 時計のタイムゾーン、日時形式のバリデーション、未来の日時などの異常値に対する許容範囲は実装前の厳密な検証事項。日付を捏造しない。

## 3. U01一覧・詳細表示

- 復元したイベントには**「バックアップから復元」**の補助表示を付ける。既存IDと衝突して別コピーになった場合には**「別コピーとして追加」**も伝える。
- U01の並び替えに`updatedAt`を使う場合は、新しく取り込んだイベントを復元日時として扱う。イベントの**開催予定日（Q3）を復元日時として表示しない**。
- 詳細の由来情報には「復元日時」「バックアップ内での元の作成日時・更新日時」を区別して示す。元IDは一般利用者には必須表示とせず、必要に応じて補助情報へ。
- 同じJSONを再度取り込んでも本人の意思なくスキップしない。プレビューには毎回追加件数・コピー件数とコピー増加の注意を表示する。

## 5. 既決と未決の境界

**正式採用**：revision=1、復元時刻を新createdAt/updatedAtとして設定、`importedFrom`に直接の元ID・元作成日時・元更新日時・復元日時を保持。ADR-015〜017と矛盾しない。

**技術／品質検証事項**：元revisionの由来保持の可否、JSON形式の具体的な版、UTC/JST時刻の正規化、異常日時の許容範囲、ファイルMB・件数の上限、既知旧版のインポート可否、プレビュー中に別タブが更新する場合の実際のDexie動作。これらは実装時に検証して仕様を確定する。ユーザーの追加判断が必要なものは次のSTEPで比較する。
