# ADR-008｜任意メモ100字・イベント説明500字（A案正式採用）

決定日：2026-11-15。**利用者が文字数制限A案を明示採用済み。** 対象は初めて単発・小規模の非営利地域イベントを主催する人向けWebアプリのみ。旧空き家所有者・物件・マッチング・用途診断を混ぜない。**実装・試験・公開は未実施**。

## 1. 正式に確定した上限

| 入力 | 保存フィールド | 入力必須性 | 上限 |
|---|---|---|---|
| 施設名の任意メモ | `venueNameMemo` | 任意 | **100字** |
| イベント内容・説明 | `optionalDescription` | 任意 | **500字** |

- 空欄は有効。上限ちょうどは有効、上限を超えた値はバリデーションエラーで保存しない。
- 施設名メモは本人の自由入力であり、公式出典・施設カテゴリの自動判定には使わない。イベント説明からAIで許可や安全条件を判定しない。
- 入力超過の場合はU04のドラフト値を保持してエラーを明示し、**「変更を反映する」で確定保存しない**。U04のキャンセル、保存失敗、別タブ競合は以前の保存値を維持。
- 施設メモが条件変更で非該当になった場合は[ADR-005](ADR_005_CLEAR_INAPPLICABLE_FACILITY_INPUT.md)に従い、**U04保存成功時だけ**旧施設メモを削除。現在非該当の施設メモは現在の判定に使用しない。
- 画面カウンターと保存前の検証は**同一の文字数定義**を使用する。IME変換中に入力を勝手に切り捨てない。

## 2. Unicode文字数の技術設計案（正式な100/500字の具体化）

**第一候補：Unicode書記素クラスタ（grapheme cluster）を「字」の単位にする。** `Intl.Segmenter("ja", {granularity:"grapheme"})`等で見た目に近い文字のまとまりを数える。日本語、絵文字や結合文字に対してUIの「あと何字」と保存検証が一致しやすい。ブラウザ互換性、Unicode分割結果の端末間差異、長い結合文字の防御を**実装前の技術レビュー対象**として明記し、ユーザーが選んだ上限値と混同しない。

- `String.length`のUTF-16コード単位や`Array.from(text).length`のコードポイント単位を、画面の文字数と無断で混在させない。
- `Intl.Segmenter`がない環境への対応を、Polyfillを採用するか非対応ブラウザを案内するか、**開発前に決定**する。フォールバックで単位を黙って変更しない。
- **別の保護策**：極端に大きな単一書記素（大量の結合記号など）は書記素数だけでは制限できないため、UTF-8の技術的サイズ上限と性能試験を設ける（数値は未採用）。

## 3. IMEとUIの具体方針（推奨設計）

1. フォームは入力・変換中の一時文字列を保持する。ブラウザの`compositionstart/compositionend`等で変換中を識別し、日本語の候補選択や確定を途中で遮らない。
2. 変換中は上限のエラー判定を確定しない（仮のカウント表示は可）。確定後に同じ書記素カウンターで検証。
3. **超過時に自動切断しない**。上限を超えた事実と修正方法をフィールド近くに示す。保存前に改めて全入力を検証。
4. 例：「施設名メモは100字以内で入力してください（現在101字）」／「イベントの説明は500字以内で入力してください（現在501字）」。空欄はエラーにしない。
5. テキストをHTMLとして解釈しない。機微な個人情報、参加者氏名・連絡先・住所の入力を避ける案内を表示。
6. 入力の前後空白・改行の正規化は画面カウンターと保存値の一致を守る方針で調整。**見た目と保存値が異なる暗黙トリミングを避ける**。

## 5. 決定済みと未決の境界

- **正式採用済み**：任意／100字・500字／超過時はバリデーションエラー／IME中に文字を勝手に切断しない／カウンターと保存検証の一致。
- **技術的な推奨（未承認）**：書記素クラスタ採用、Intl.Segmenter非対応環境での処理、UTF-8バイト上限、空白・改行の厳密な正規化。
- **別途判断待ち**：公式情報の更新頻度と担当者、対応ブラウザの範囲。
