# STEP8-②｜P01〜P12判定ルールと中心価値の監査（設計レビュー・推奨仕様）

作成：2026-11-15。**現行プロダクトの判定設計の監査であり、未承認の優先度変更を自動採用しない。** レビュー対象：[RULE_ENGINE_CONTRACT_V1](RULE_ENGINE_CONTRACT_V1.md)、[判定表v1.1](STEP4_RULE_DECISION_TABLE_V11.md)、[ADR-002](ADR_002_NO_PHYSICAL_VENUE_SCOPE.md)、[ADR-003](ADR_003_PRIORITY_RULES_ADOPTED.md)、[ADR-004](ADR_004_EXPLICIT_RECHECK_CLEAR.md)、[ADR-026](ADR_026_U03_PROGRESS_CAS_INDEPENDENT_OF_INVALID_INPUT.md)。現行の単発・小規模地域イベント準備支援Webアプリのみ。旧空き家案・物件・所有者・マッチングとは無関係。**実装・ルール計算の実行・利用者試験・公式原ページの現行確認なし。**

## 1. 守る中心価値

> 初めて小規模の地域イベントを主催する人に、**準備の全体像／今優先して考えること／なぜその順か／最初の具体的な一歩**を示す。アプリは主催者本人に代わって法的な申請要否・会場の許可・安全性・定員を確定しない。

出力契約：4領域・P01〜P12すべてのタスクは常に参照可能。目立たせるのは現在未解決の代表1件と、他の重要なP1全件。既存の進捗を根拠なしに巻き戻さない。本人の`not_applicable`と計算上の`applicable=no`、`needs_information`を区別する。理由を説明できない優先度を与えない。

## 2. 正式決定済みの判定（変更しない）

| 論点 | 確定仕様 |
|---|---|
| 物理会場なし | P07〜P09の建物専用の子項目のみ非該当、親は情報確認を残す。オンラインと断定しない（ADR-002） |
| P05未成年／両方 | **P1**、見守り・安全の一般確認。人数・責任配置・法的義務は入力から断定しない |
| P05成人のみ／参加対象未定 | **P2**、対象未定のまま見守り方を推測しない |
| P08物理会場なし | 親タスクは`applicable=needs_information`、**P2** |
| 同優先度 | タスクIDの数値昇順、P01→P12（ADR-003） |
| U03進捗・再確認 | 本人の記録を保持し、明示解除＋保存成功以外に`needsRecheck`を解除しない（ADR-004/026） |
| 古い出典 | 施設固有の断定情報を表示しない、一般的な準備確認は維持（ADR-009〜012） |

## 3. P01〜P12の詳細監査

表の「P2候補／P3基準」は**判定表v1.1から読み取れる推奨案**であって、ADR-003以外の新しい正式採用ではない。

| タスク | 利用者が理解できる次の一歩（推奨文言） | 根拠になる入力 | 優先度候補と不明情報の扱い | 誤案内禁止 |
|---|---|---|---|---|
| **P01** 目的・内容 | 「誰にどんな体験を届けたいか、一文にしてみましょう」 | eventType・eventDescription | 内容がotherでまだ具体化不足ならP2候補、通常P3 | 説明が空＝失敗と断定しない |
| **P02** 対象・人数 | 「来てもらいたい人と人数の目安を考えましょう」 | audience・attendees | audience=undecidedならP2候補、任意人数空だけで0人とみなさない | 未入力人数から定員・規制を決めない |
| **P03** 日程・費用 | 「開催日／月の目安と使える費用を整理しましょう」 | schedule | 未定・月のみはP2候補、それ以外P3候補 | 法定期限や予算金額を捏造しない |
| **P04** 責任者・役割 | 「当日連絡を受ける人と役割を確認しましょう」 | organizerForm・responsible | 明示未定ならP2候補、空欄だけで不足確定にしない | 個人主催＝責任者確定としない |
| **P05** 安全・見守り | 「参加対象に応じた安全確認を整理しましょう」 | audience | **未成年／両方=P1、成人／未定=P2確定** | 子ども参加だけで法令・保険・必要人数を確定しない |
| **P06** 進行・緊急時 | 「当日の流れと、困った場合の連絡方法を考えましょう」 | eventType・schedule | 現行はP3基準、開催14日前等の昇格は**未採用** | 開催日だけで確定した期限を作らない |
| **P07** 会場の確認 | 「会場候補と開催方法を整理しましょう」 | venueStatus・region | 未定／候補はP2候補。物理会場なしでも親は要情報 | 会場確定＝使用許可済みと断定しない |
| **P08** 利用条件・手続き | 「会場や開催場所の利用条件を公式窓口で確認しましょう」 | region・venueStatus・venueCategory・出典 | **物理会場なし=P2確定**。施設固有のP1昇格は出典のスコープ・有効性に依存し、**大きな確認事項** | 高岡市だけで施設利用条件を決めない。古い出典を根拠にP1昇格させない |
| **P09** 設備・備品 | 「必要な設備と使えるものを照合しましょう」 | equipment・venueStatus | 会場選択に影響する設備入力ありならP2候補、通常P3 | 未回答＝不要としない |
| **P10** 募集・告知 | 「誰にどこで告知するかを決めましょう」 | eventType・schedule | P3基準、日程だけで特定の募集締切を作らない | SNS利用や申込み期限を必須と断定しない |
| **P11** 参加方法・連絡 | 「申込み方法と参加者への連絡を決めましょう」 | audience・venueStatus | P3基準、未成年を含む場合は保護者向けの確認を追記 | 参加者の個人情報のDB収集機能を増やさない |
| **P12** 開催前の最終確認 | 「役割・持ち物・当日の連絡方法を見直しましょう」 | schedule・venueStatus | P3基準、開催日までの固定日数で自動昇格しない | 日付が決まっただけで完了にしない |

**推奨として進められる具体化**：上記の言い回し・無推測ガードをU03カード案とテスト仕様の設計に反映する。現在の正式優先順位の改変・自動P1拡大を勝手に正式採用しない。

## 4. 検証すべきケースと独自性

- **ケースA：未成年対象・会場未決定**。P05=P1を隠さず、会場選定P07等を「他に必要な準備」へ表示する。代表はID順（他にP1がなければP05）。
- **ケースB：成人対象・物理会場なし**。P05=P2／P08=P2、P07〜P09親を残し「オンライン開催」「予約は不要」とは断定しない。
- **ケースC：高岡市、地域交流センター本人選択、古い公式台帳**。施設固有の具体条件は停止し、公式情報の確認先・一般案内に戻す。保存済み進捗は保持。
- **ケースD：会場変更、P08完了済み**。完了履歴は残し、前提が失効するなら`needsRecheck`を付ける。開いただけでは解除しない。
- **ケースE：任意説明が空欄**。入力の空欄をAIが補完したかのように扱わない。基本6問から無理に「最適」と断定しない。
- **ケースF：過去日・月のみ指定**。ADR-006の警告付き入力、期限の自動推定禁止を守る。
- **ケースG：古い入力メモが4 KiBを超える**。閲覧・U03進捗CASを可能な設計、U04は本人修正必須。JSONバックアップは上限違反を無断切捨てない。

## 5. 判定と保存は別レイヤ

```text
U02/U04で確定したEventInput + 検証済みルール/公式出典
    ↓  該当性・priority・理由・nextActionを純関数で評価
U03で全12タスクと代表タスクを表示
    + 本人のprogressByTask / needsRecheckを重ねる
    ↓  本人が進捗を操作
ADR-026のrevision CAS → 本人進捗だけ保存
    × 入力の無断修正・公式出典のコピー保存・自動進捗初期化は禁止
```

判定の`priority`は**準備を考えるための提案**で、法律上の必要書類や義務を確定するものではない。元の情報に根拠のない説明は出さない。テストに落とすには各条件について「入力値→該当性→P1/P2/P3→理由コード→表示文言→再確認への影響」の期待値行を作る。

## 6. 自動で進める設計（利用者の委任範囲）

1. P01〜P12に**理由コードと次の一歩文言の候補**を追加し、入力値が足りない場合は明確に「確認してください」とする。
2. P06/P10/P12などの**根拠のない日数閾値を採用しない**という既決の制限を守る。
3. U03の代表1件＋その他P1・全体12件の情報構造を詰め、理由表示と完了／要再確認の状態区別をレビュー。
4. CASE-A〜Gから手動の受入テスト表を作る。**テストは実行しない**。
5. 施設固有のP08のP1自動昇格は実際の公式出典条件・レビュー期限・対象者への影響が大きいため、**ユーザー確認が必要な変更**として分離。

## 7. 次の大きな判断（承認前）

**地域の公式情報を適用できる場合、P08をP1へ自動昇格させるか**。[STEP8-③ P08公式根拠による優先度](STEP8_03_FACILITY_P08_PRIORITY_GATE.md)に比較を整理する。現状のP08物理会場なし=P2という既決条件を変えず、施設固有のルールで誤認を生まないための判断。選択されるまで施設固有のP1自動昇格を「既決・稼働」と扱わない。

## 8. 監査結果の状態

**監査済み**：GitHub設計書の記述・矛盾候補の整理。**未検証**：実装、ランタイムの判定、実際の利用者理解、公式原ページの適用と最新日時。公式出典の定期運用方針（ADR-009〜012）は決定済みだが、個々の施設情報を2026-11-15時点で現行だと確認したわけではない。
