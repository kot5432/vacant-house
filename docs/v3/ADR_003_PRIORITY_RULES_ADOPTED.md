# ADR-003｜優先順位の細則A案を正式採用（2026-11-15）

**状態：ユーザーの明示承認済み。設計決定のみ。アプリ実装・試験は未実施。**

対象：初めて単発・小規模の非営利地域イベントを主催する人に準備全体像と優先順位を提示するWebアプリ。旧空き家所有者診断・物件マッチング・用途診断・旧困りごと相談文フローのいずれも対象外。

## 採用する3項目

1. **P05（一般安全・見守り）**：参加対象が`adults`（成人のみ）または`undecided`（未定）のときは**P2**。参加対象が`minors`または`both`なら**P1**。これは一般的な確認の順序であり、危険性や法的義務を自動判定するものではない。
2. **同じ優先度の表示・代表選択**：優先区分は**P1→P2→P3**。同一区分なら**タスクID昇順（P01→P12）**。完了・本人対象外・非該当など通常の未解決候補でないものは代表選択から除外し、`needsRecheck=true`は未解決として残す。**P1が複数なら代表以外も省略せず表示**。旧「P08→P05→P07…」の固定特別順は採用しない。
3. **P08（物理会場なしの一般確認）**：`venueStatus=no_physical_venue`のとき**親P08の優先度はP2**、`applicable=needs_information`。建物予約専用の子項目は非該当。屋外・オンラインの利用条件が不要だと断定せず、開催方法に応じた利用条件の要否を確認する案内を表示する。本人がP08を完了にすれば未解決候補から外すが、開催の許可・安全を保証しない。

## 優先度・該当性・進捗は別次元

| 入力・状態 | P05の優先 | P08の優先 | 備考 |
|---|---|---|---|
| Q2=adults | P2 | Q4で別途判定 | 子ども専用の見守り説明を出さず、一般安全確認を残す |
| Q2=undecided | P2 | Q4で別途判定 | 見守り要否がまだ分からないと説明 |
| Q2=minors/both | P1 | Q4で別途判定 | 見守り・連絡体制の確認を優先 |
| Q4=no_physical_venue | Q2で別途判定 | P2 | P07〜P09の親は要情報。オンライン固有の診断はしない |
| P05またはP08が`completed + needsRecheck=false` | 保持 | 保持 | 優先区分の計算値は持っていても通常の代表候補から除外 |
| P05またはP08が`completed + needsRecheck=true` | 保持 | 保持 | 未解決候補に再び含め、以前の完了履歴は保持 |

## 数値と表示の規約

- 優先区分は`P1`（優先して確認）、`P2`（次に確認）、`P3`（後で確認）。タスクIDの`P01`と優先区分`P1`は**別の識別子**であり混同しない。
- 比較キーの例は`(priorityRank, taskNumber)`（優先順位が小さいものから、次にタスク番号昇順）。`P05`と`P08`がどちらもP1なら`P05`が代表、`P08`も重要事項として表示。
- 表示の4領域は維持。優先カードの候補順と全体像の領域順は別表示でよい。
- **「開催14日前」**など根拠のない日数閾値は未採用。公的な申込締切、施設の利用可否、安全性、本人の主催責任を断定しない。
