## 1. 基本方針

**最初からA/B/C/Dが並行**で動き、各自のブランチは小さいPR単位で管理。D担当に全画面の完了待ちを集中させないため、**共有型・関数の呼出形だけ先に固定する**。本番Repository未接続の画面は「仮応答/mock」の状態を明示する。すべてのコード追加は、別途実装開始が許可された後に限る。

- Dが`EventInput`、`EventRecord`、`ParentTaskProgress`、`OrganizerRepository`と結果型を**唯一の所有者**として管理。B/Cは独自の重複型を作らず、[STEP25](STEP25_TYPESCRIPT_DOMAIN_TYPES_AND_REPOSITORY_SIGNATURES_20261119.md)と[ADR-032](ADR_032_TECHNICAL_V1_DATA_RECHECK_EQUIPMENT_AND_API_ADOPTED.md)を参照する。
- Bが`derivePreparationPlan(input, officialContext)`の純粋な判定を所有。CはBの計画表示契約を読み、優先度を独自に再実装しない。
- Aの`ActivityCatalog`は主催側`EventRecord`とは**別**。出典審査前`visible=0`を受け入れ、活動から主催への転記はしない。
- EはA〜DのPR主レビューと出典・利用者評価の受入調整。E本人のPRは他の担当者にレビューを依頼する。
