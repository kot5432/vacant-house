# STEP7-⑩｜JSONバックアップ復元時のイベントID衝突の扱い（未決）

作成：2026-11-15。**選択肢比較、ユーザー承認待ち**。[ADR-015](ADR_015_JSON_BACKUP_EXPORT_IMPORT.md)でエクスポート・インポート両方をMVPに採用。現行地域イベント準備支援Webアプリのみ。旧空き家、物件、所有者、マッチングのデータは取込み対象外。**実装・テスト実行なし**。

## 1. 衝突の種類

- **ファイル内部で同じeventIdが2件以上**：内部整合性がないため、取り込み前のエラーとして拒否する安全設計を推奨。二重に取り込んで片方を黙って失わない。
- **インポートするeventIdが既存IndexedDBにある**：既存データと内容・revision・更新時刻が違う可能性がある。既存イベントを勝手に上書きしないことは決定済みだが、ユーザーがどう復元できるようにするかは未決。
- **同じJSONを何度も取り込む**：既存の同IDと衝突。何もせず成功と表示する、勝手に上書きする、黙って新しい複製を作ることは避ける。
- **プレビュー後、別タブで変更・削除された**：プレビュー結果は古くなるため、**確定保存時に現在のIndexedDB状態を再照合**することを全案の共通条件とする。

## 2. 利用者が決める3案

| 案 | 同じeventIdが既存DBにあるとき | 長所 | 弱点 |
|---|---|---|---|
| **A（推奨）** | **復元するイベントを新しいIDで複製として追加**。元イベントは変更せず、プレビューに「既存イベントとは別に追加」と明示 | 既存データを壊さず復元内容を確認・比較できる。初期MVPとして単純 | 同じ内容の複製が増える。衝突のないイベントは元IDを引き継ぐ等の細則が必要 |
| B | **衝突したイベントだけ復元対象から除外**。衝突なしのイベントは追加 | 既存データを保持し、重複が発生しにくい | バックアップ側の新しい進捗を戻せないことがある |
| C | **イベントごとに「既存を維持／別コピー追加／既存を置換」を本人が選択** | 自由度が高く、バックアップによる復旧がしやすい | 差分プレビュー、既存更新時のrevision・削除・競合、UIの複雑さが大きい |

**A案推奨**：個人で利用する初期MVPでは既存情報の誤消失を避けつつ、ファイル側のデータを復元できる。複製された旨とイベントの元の名称・日時を見せ、本人が不要になったコピーを既存の個別削除機能で整理できるようにする。

## 3. A案採用後に詳細化する契約（まだ未承認）

- ファイル内eventIdが全て一意であることを検証。既存と衝突するレコードは**復元確定時に一意の新eventIdを発行**し、元イベントIDとマッピングする。イベント本文・本人の進捗・再確認状態を保護する。衝突しないIDは元IDを使用することを第一候補とする。
- `revision`は他のイベントのrevisionを流用して同一イベントだと誤認しない。複製イベントのrevision初期化、`createdAt/updatedAt`の保存、元IDの履歴情報を保持するかは別のデータ契約で決める。
- 復元前プレビューで「X件追加／Y件は別IDで追加／既存Z件は維持」と示す。**複製の件数・保存先・追加方式を隠さない**。
- 書き込み直前に衝突を再検査。確定時に新しく衝突したレコードへの処理は本人の再確認を要する案を推奨。勝手に仕様を変えたことにしない。
- バックアップを2回取り込めば複製も2回増え得るため、同じファイルを検出する重複警告や内容要約を設けるかは別のUI細則で検討。
- 複数イベントの一括保存時は、**一部しか保存していないのに「全部復元しました」と表示しない**。Dexie readwriteトランザクションによる原子的な一括追加を第一候補とし、容量不足・schema不一致・別タブ競合で既存DBを保護する。
- 旧ルール版の進捗`completed/not_applicable`は維持。現行公式出典に基づく該当性や`needsRecheck`は要再評価であり、古いファイルを「許可取得済み」と認定しない。

## 4. 全案に共通する安全な読込み

1. ファイルを選択しただけではDBに書き込まない。
2. 事前にサイズ・UTF-8 JSON・形式ID・exportSchemaVersion・イベントschemaVersion・全イベント内容を検証する。
3. ファイル内IDの重複と既存DBとの衝突を**区別して表示**。不正なIDは推測で補正しない。
4. 利用者による明示確定が必要。保存結果が返る前に完了と言わない。
5. 読込エラー・バージョン非対応・容量不足・別タブ競合で、既存イベントを削除・無条件上書きしない。
6. 端末に保存したファイルには本人が書いた任意メモが含まれ得る。外部へ自動送信しない。
