# STEP10-⑥｜主催P01〜P12の子チェックと再確認コード：レビュー用固定候補 v0.1
作成：2026-11-18。**新規の技術案であり採用済みIDではない**。公式ADR-001〜030の既決ルールを変更しない。コード、実行試験、実物JSON Schemaは作成していない。

## 0. 設計原則
- 親P01〜P12の**進捗**が中心。子チェックは任意であり、チェック数だけで親statusを`completed`へ自動変更しない。
- IDはラベルとは別。表示文言の修正で安定IDは変更しない。版を伴う将来の変更時はIDの互換確認を必須とする。
- 以下の`Pxx_Cyy`は提案ID。旧版データからの暗黙移行は認めず、採用後に版1の正式カタログへ固定する。
- `no_physical_venue`でもP07〜P09の親は`needs_information`（ADR-002）、施設・建物固有の**子だけ**非該当。
- 法的義務、行政申請の有無、会場空きや安全認定は本チェックで確定しない。

## 2. 再確認理由コード：保存専用の候補

| 提案コード | 意味 | 影響候補 | 発火の前提 |
|---|---|---|---|
| RECHECK_EVENT_TYPE_CHANGED | 企画内容の種類が変更 | P01,P06,P09,P10 | 以前の本人確認が旧種類に依存していた場合 |
| RECHECK_AUDIENCE_CHANGED | 参加対象が変更 | P02,P05,P11 | 以前の本人確認が旧対象に依存していた場合 |
| RECHECK_DATE_CHANGED | 日付・月・未定の情報が変更 | P03,P06,P10,P11,P12 | 本人の以前の準備確認の前提に影響する場合 |
| RECHECK_ORGANIZER_CHANGED | 主催者形態・担当の状況が変更 | P04,P05,P06 | 本人の以前の運営確認の前提に影響する場合 |
| RECHECK_VENUE_CHANGED | 会場の状況・地域・施設分類が変更 | P07,P08,P09,P11,P12 | 実際に旧会場条件に依存していた場合 |
| RECHECK_EQUIPMENT_CHANGED | 設備必要性・選択カテゴリが変更 | P07,P09 | 旧設備前提と異なる場合 |
| RECHECK_ATTENDEE_COUNT_CHANGED | 参加予定人数が変更 | P02,P05,P07,P09 | 旧人数が準備確認の根拠だった場合 |
| RECHECK_OFFICIAL_SOURCE_CHANGED | 適用対象の公式出典が更新・失効 | 原則P08関連、必要ならP07/P09 | 新旧出典の対象条件が実際に関係する場合 |

**この表は入力変更→無条件の一括再確認を意味しない**。旧値・新値・影響するタスク・旧進捗と確認項目・出典参照範囲を照らし合わせる。根拠が不足する場合は「要再確認の可能性」を人に示す一般案内にとどめ、勝手に`needsRecheck=true`にしない設計を推奨。保存する理由コードと、画面に出す導出priority理由コードは異なるもの。

## 3. 設備カテゴリ：4つの最小技術候補
| 候補enum | 表示名 | 備考 |
|---|---|---|
| `tables_chairs` | 机・椅子 | 必要性の明示入力のみ |
| `audio_visual` | 音響・映像機材 | 「使える」とは断定しない |
| `power_internet` | 電源・通信環境 | 物理会場なしでも環境要件としてあり得る |
| `other` | その他 | メモの推定分類はしない |

**注意**：`equipmentNeed=answered/yes`かつ`equipmentCategories=[]`でもP09=P2（ADR-028）。`none_identified`は「不要」ではない。4カテゴリが不足/過剰なら**カテゴリ配列をUIに出さず、設備必要性のみ利用**する縮小案も成立する。版1のJSON正式enumとするには別人レビューが必要。

## 4. 条件と状態の契約（案）
- `checkedItemIds`は、該当する親タスクIDに所属する既知子IDのみ。重複ID・別親IDは拒否。条件変化で子項目が不適用になっても、本人が以前にチェックした証拠を一律に無断削除しない。非該当の表示を区別し、U04の施設固有入力クリア規約（ADR-005）と**子チェック履歴の扱いを分ける**。
- `recheckReasonCodes`は既知候補集合と`needsRecheck`の整合が必要。本人による明示解除時は空集合（ADR-004）。空配列の意味は未変更・入力変更なしではなく「現在保存されている再確認理由がない」。
- 子チェックの全チェック完了と親`status=completed`は独立。親の完了/対象外は本人による選択のみ。
- JSON v1の未対応キー・重複IDは無断切捨て不可。正式採用後は厳密検証、移行は別の承認。
