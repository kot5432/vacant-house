# STEP 6-②｜入力バリデーション・保存データ検証契約 v0.1（2026-11-15）

> **状態：実装前の推奨仕様。** 現行イベント準備支援Webアプリのみ。旧空き家・物件データと混ぜない。React+TypeScript+Vite／IndexedDB+Dexie／Vercelは正式採用済み。以下は入力制約・正規化の設計案であり未承認の閾値を含む。実装と実行試験なし。
> 参照：[要件定義](REQUIREMENTS_V1_DRAFT.md)、[データ](DATA_DESIGN_V1.md)、[U02](STEP5_02_HOME_SETUP_WIREFRAMES.md)、[U04](STEP5_04_EDIT_SAVE_ERROR_UI.md)、[ADR-002](ADR_002_NO_PHYSICAL_VENUE_SCOPE.md)。

## 1. 基本6問：必須・未定は有効

| フィールド | 入力値 | 無効とみなす例 |
|---|---|---|
| `eventType` | `workshop / lecture / exchange / other` | 未回答、列挙外文字列 |
| `audience` | `minors / adults / both / undecided` | 未回答・列挙外 |
| `schedule` | `{kind:date, value:YYYY-MM-DD}` / `{kind:month, value:YYYY-MM}` / `{kind:undecided}` | 不正形式、存在しない日付、不要なvalue |
| `venueStatus` | `undecided / candidate / confirmed / no_physical_venue` | 未回答、列挙外 |
| `region` | `takaoka / toyama_other / outside_toyama / undecided` | 未回答、列挙外 |
| `organizerForm` | `solo / group / undecided` | 未回答、列挙外 |

- `undecided` は**回答された選択肢**であって未回答ではない。初回プラン生成は6問全て有効入力のときに限る。
- `schedule.kind=month`は日付に補完しない。暫定的な`YYYY-MM-01`を開催日として利用しない。時刻・タイムゾーンによる日時差は型と表示で区別する。
- **過去日の扱い（提案）**：過去の日付・月は入力エラーにせず「過去の希望時期ですが、そのままでよいですか？」と確認し、ユーザーの実際の意図に従って保持する。過去日を行政の違反や法的な問題と表示しない。
- `confirmed`は本人が場所を決めたという申告であり予約・許可取得を意味しない。`no_physical_venue`はオンライン開催と断定しない。

## 2. 条件付き入力

```text
region=takaoka AND venueStatus in {candidate, confirmed}
  => 施設カテゴリの確認が該当することがある（選択肢と表示はSTEP3準拠）
  AND 施設カテゴリ=本人が明示した高岡市地域交流センター
  => 施設利用者の年齢構成（未成年のみ/成人を含む/不明）を確認
それ以外：
  => 現在のルール判定に施設カテゴリと施設利用者構成を使わない
```

- 利用者が施設カテゴリを選択しても、実際の施設利用可否を判定しない。
- 施設名の自由記述・イベント説明からカテゴリや施設条件を推測しない。
- 会場条件変更で入力が非該当になった場合の以前の値の**保存保持か削除かは別設計判断**。ただし、非該当値を現在の判定に使うことは禁止。

## 3. 任意の詳細入力

| フィールド | 値の区別 | 推奨検証 |
|---|---|---|
| `attendeeCount` | 未回答／未定／回答済み整数 | `Number.isSafeInteger(n) && n>=1`を満たす場合だけ値として受理。上限は要承認 |
| `responsible` | 未回答／未定／決定／未決定 | 主催者形態`solo`でも自動的に決定へ変えない |
| `equipmentNeed` | 未回答／未定／必要な設備あり／現時点で思いつかない | 「思いつかない」は設備不要を意味しない |
| `equipmentCategories` | 任意の列挙済み設備カテゴリ | `equipmentNeed=yes`のときのみ意味を持つ。列挙外は検証で扱う |
| `venueCategory` | 未回答／未定／回答済みカテゴリ | 地域・会場条件が該当したときだけ判定使用 |
| `facilityUsersAge` | 未回答／未定／未成年のみ／成人を含む | 本人選択の該当センターの場合のみ判定使用 |
| `venueNameMemo` | 任意文字列 | 長さ制約・改行処理・個人情報の注意。URLとして解釈しない |
| `optionalDescription` | 任意文字列 | 長さ制約・改行処理・HTMLとみなさない。内容からAI判定しない |

**文字数上限の候補（未承認）**：施設名メモ100字、イベント説明500字。UTF-16コード単位ではなく、UIの文字数表示と実際のバリデーションの単位を揃える。日本語入力の確定前に不用意に切り捨てない。

## 4. 3状態の統一

任意質問は`{kind:unanswered} | {kind:undecided} | {kind:answered,value:T}`で扱う。回答済みの値`unknown`をさらに入れ子にしない。単独の未定が存在する基本6問と、未回答の必須状態は別（未回答では生成できない）。`null`、`undefined`、空文字を無造作に`未定`へ変換しない。

## 5. データ保存時・読み込み時

- **U02の初回入力途中はIndexedDBへ保存しない（A案正式採用）**。初回保存が成功するまでU03へ遷移しない。失敗時はU02の画面内値を保持。
- U03進捗は自動保存、U04編集ドラフトは反映ボタンから保存する。どちらも書き込み完了まで保存済みと表示しない。
- IndexedDBから取得したイベントは`schemaVersion`, `eventId`, `revision`, 全列挙値、日時、`TaskId`、配列構造をランタイム検証。TypeScript型での断言`as EventRecord`だけでは認めない。
- `schemaVersion`が新しすぎる／レコード破損／不正なタスクIDの場合は**黙って削除・上書きしない**。安全なエラー表示と修復・移行の判断へ。
- `rulesVersionAtLastReview`とDB schemaVersionを混同しない。ルール更新時には以前の完了履歴を保持し、影響するものだけ再確認を提案。
- `eventId`は作成時だけ生成し、update時に任意生成しない。revision照合と保存は同じDBトランザクションで行う。

## 6. 表示の文言

- 未回答：「選択してください」
- 未定：「まだ決まっていない」など、利用者の意図を尊重する。
- 不正値：「正しい開催日を選択してください」（存在しない日付）
- 施設未入力：「施設の種類が分かる場合は選んでください」（該当時、任意・必要なときのルールを区別）
- 人数不正：「1人以上の整数で入力してください」
- 保存失敗：「今回の入力は保存されていません。内容を保持したまま再試行できます」

## 7. 未決の確認ゲート

1. 日付が過去の場合、確認のみで許容するか／エラーにするか。
2. 人数の上限と自由記述の文字数上限。現時点で仮に決め打ちしない。
3. 条件外になった施設カテゴリなどを保持するか、不要情報として消すか。
4. 公式出典の必須項目と更新時の無効化運用。
5. UIの文字数・入力検証の詳細と、対応するブラウザの試験。

**すべて設計上の検証規則であり、コード・実際の操作・データ移行試験は未実施。**

## 8. 条件外施設回答の保持・削除（正式判断待ち）

地域や会場状態の変更で施設固有入力が現在の条件から外れた場合、**旧入力を現在の判定・公式案内に使わないことは確定済み**。しかし、旧入力の**永続保持と確定保存時の削除**は別判断。[比較と推奨B案](STEP6_03_INACTIVE_FACILITY_DATA_OPTIONS.md)で説明。U04では保存成功前に既存DBを変更しない。旧進捗・再確認を削除と混同しない。
