# STEP7-⑯｜バックアップが100件・2 MiBを超えた場合の書き出し（未決の選択肢）

作成日：2026-11-15。**本書は利用者判断待ち**。[ADR-019](ADR_019_JSON_BACKUP_LIMIT_2MIB_100_EVENTS.md)で「JSON**1ファイル**につき最大2 MiB（2,097,152バイト）・最大100件」を正式採用済み。旧空き家案のデータは対象外。コード実装・動作試験・公開は未実施。

## 課題

保存済みイベントが101件以上ある場合や、100件以内でも完成JSONが2 MiB超になる場合に、「書き出し」を押しても全件を1ファイルに収められない。**黙って先頭100件だけ出す、途中で記録を省く、復元できないサイズのファイルを成功表示することは不採用**。利用者が必要なイベントを安全に保存できる方法を選ぶ。

## 3案

| 案 | 上限超過時の動作 | 良い点 | 課題 |
|---|---|---|---|
| **A（推奨）** | **利用者が対象イベントを選び、1ファイルの100件・2 MiB以内に収めて書き出す**。必要なら残りも別操作で選んで書き出す | 操作を理解しやすく、対象外を本人が把握できる。スマホにも向く | 複数ファイルへの手動分割が必要。選択し忘れを防ぐ案内が必要 |
| B | **全イベントをルールに従って自動的に複数JSONファイルへ分割**（各ファイル100件・2 MiB以内） | まとめてバックアップしやすい | 生成ファイル数、失敗時の一部ダウンロード、モバイルの複数ダウンロード、復元順とファイル管理が複雑 |
| C | **上限超過時は書出しを停止**し、後日分割を提供する | MVPの追加UIが最小 | イベント数が増えると復元可能なバックアップが取得できなくなる |

**推奨A**：本人が対象を選び、毎回どのイベントが出力されたかを明確に把握できる。1回で全件を選びたい場合は段階的な改善を検討。Aでも**「すべてのイベントをバックアップ済み」と言わない**ことが重要。

## A案の設計候補（未承認）

1. U01のバックアップ補助画面で「すべて選ぶ」「個別に選ぶ」「選択解除」を用意。件数・見込みサイズは案内できるが、**最終的なUTF-8 JSON生成後のサイズ**で可否を確定。
2. 100件超なら「100件まで選択できます」と説明。100件以内でも2 MiBを超える場合はサイズ超過エラーを出し、本人が選択を減らす。
3. ダウンロード前に「選択X件／保存済み合計Y件／このファイルに含まれないY-X件」を表示。0件の出力を許可するか・ボタン無効かはUI細則。
4. 書き出し成功後、元DBは不変。複数ファイルで全件を管理するには残りを本人が再選択する。**保存先にファイルが確実に残ったとアプリは断定しない**。
5. 全イベントを選ぶ状態でも、上限超過時に先頭だけ切り捨てない。選択・件数・バイトサイズは本人に見える。
6. インポート側の2 MiB／100件の上限、ADR-016〜018の新規ID／revision／日時の契約は変えない。

## 利用者への次の判断

**A：イベントを本人が選んで複数回に分けて書き出す／B：自動複数ファイル化／C：超過時は書き出し停止**。MVPではAを推奨。確定後にU01画面・データモデル・テストを具体化する。
