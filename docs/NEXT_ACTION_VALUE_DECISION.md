# 決定記録：診断から「次の具体的な行動」へ（2026-11-12）

**状態：中心価値の方向を決定／詳細UIは設計案。実装・利用者検証は未実施。**

## ユーザーの決定
「活用候補の一覧を持ち帰る」と「活用に向けた具体的な行動を持ち帰る」の二択で、**後者**を選択。

中心価値：**空き家の所有者が用途ごとの確認事項を理解し、最初に何を調べ、誰にどんなことを確認すればよいか分かること**。

現行の6用途・希望A分類・基本設備B分類・地域の根拠表示・非ランキング方針は維持。実際のマッチング、自治体への連絡代行、専門家判断は追加しない。

## 出力画面に追加する設計
1. 結果カード：用途名・希望との関係・基本確認状況・**代表的な最初の一歩（1行）**・詳細。
2. 用途詳細：「次に確かめること（最大3件）」の各項目に、**確認したいこと／最初の行動／確認方法・相手の種類／その理由と根拠／注意点**をセットで表示。
3. 2用途比較：設備の状態だけでなく、最初に取る行動の違いを比較。
4. 地域データ未調査時：用途別の一般的な行動例を使い、地域で活動する団体の実在や協力意思を断定しない。
5. 基本条件が「ない」と分かっている場合：整備や代替手段の専門家相談。「不明」の場合：所有者の手元資料などで確認。両者を区別。
6. 次の3件に入らない確認事項も、別の確認事項や専門家確認欄で見られる。

## 6用途に対する行動例（すべて一般的な提案。現地未検証）
| 用途 | 次に取れる具体的行動 |
| --- | --- |
| 住宅・移住 | 賃貸・売却・自己利用のうち希望を整理し、建物や契約の不明点を専門家へ確認する |
| 地域交流 | 活動したい人数と時間を書き出し、既存地域交流施設の利用条件を調べる |
| 学習支援 | 既存の学習支援活動や学生・地域団体の情報を調べ、運営体制の有無を確認する |
| 子ども食堂 | 既存の食事支援活動を調べ、運営主体・調理方法・衛生面の確認事項を整理する |
| コワーキング | 想定利用者・利用時間・通信条件・費用などを整理する |
| 店舗・カフェ | 物販か飲食か、提供内容と運営主体を整理し、必要な手続きや設備を調べる |

## 判定・技術上の変更範囲
- 所有者希望A・建物確認Bの決定規則は変更しない。根拠なきスコアや用途順位も付けない。
- 既存の質問ルールと優先度（最大3件）を維持し、結果の表現へ firstActionText、actionMethod、actionCaveat を追加する設計。
- 同じ入力と同じ版では、質問と行動例が変わらない。出典と未調査/架空状態を保持する。
- 地域調査の内容に応じた行動例は、根拠の対応が確かめられた場合のみ切り替える。

## 受入条件（まだ検証していない）
- 全6用途に、地域未調査でも一つ以上の実行可能な最初の行動を表示する。
- 基本条件が「ない」「不明」で行動例が適切に分かれる。
- 2用途比較で、次の一歩の違いを認識できる。
- 団体の協力・利用許可・利益・建物安全を保証しない。
- 初見ユーザーが結果を見て「次に自分ができること」を一つ説明できるか検証する。

## 引き続きチームで検討
行動案の表示数、特定の相談窓口リンクの確認体制、行動完了チェックの要否（現段階ではMVPに含めない）。
