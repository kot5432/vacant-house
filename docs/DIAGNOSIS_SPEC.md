# 診断・地域の根拠・質問分岐仕様 v1.0
作成：2026-11-12／**仕様でありコードではない**。

## 1. 不変条件
- 同じ入力、同じruleVersion・公開データ版では同じ結果。
- 用途に総合点数や客観的な優劣順位を付けない。
- 所有者の希望の区分（A）と設備基本条件（B）を**独立**して求める。
- 地域調査／施設距離が変わっても、設備状態Bは変えない。所有者の希望Aも勝手に変えない。
- 「基本項目確認済み」は法令・安全・収益・現実の利用可能性の保証でない。

## 2. 入力の正規化
設備値：present（ある）／absent（ない）／unknown（不明）。空欄はunknown。部屋数：正の整数なら条件を満たす、0なら満たさない、未入力なら不明。負数や非整数は**不正入力**として利用者へ修正を求める。数値0と空欄を同一視しない。
所有者希望の方向：住まい→housing、地域→community/study/meal、事業→work/shop。方向からの変換は**具体的希望をユーザーが確定する前の既定**。詳細用途を明示した場合はそれが優先。除外は希望より優先。希望が未設定ならA3。

## 3. 用途別の基本3条件
| usageId | 確認1 | 確認2 | 確認3 |
| --- | --- | --- | --- |
| housing | キッチンあり | トイレあり | 浴室あり |
| community | 部屋数1以上 | トイレあり | 電気あり |
| study | 部屋数1以上 | トイレあり | 電気あり |
| meal | キッチンあり | トイレあり | 電気あり |
| work | 部屋数1以上 | 電気あり | 通信環境あり |
| shop | 部屋数1以上 | トイレあり | 電気あり |

**重要**：この表は検討の入口であり、各用途に必要な設備や許認可を網羅していない。カフェのキッチンなどは専門家確認欄に必ず残す。専門家・所有者の検証がまだないため実務的妥当性は未確定。

## 4. 希望A分類
- A4 excluded：明示的に避けたい用途。主候補から除外し、別枠に置く。
- A3 undecided：希望未定のときの非除外用途。
- A1 preferred：明示的に希望用途。
- A2 alternative：希望が設定されていて、それ以外の非除外用途。
- 表示グループはA1→A2、未定ならA3、A4は展開枠。**同一グループ内の固定順**：housing→community→study→meal→work→shop。ランキングを意味しない。

## 5. 基本確認B分類
各用途の3条件をfulfilled / unmet / unknownに正規化し、次の順で判定：
1. unmetが1件以上 → B2「設備の見直しを検討」。unknownもあれば**同時に項目を列挙**。
2. unmetが0件かつunknownが1件以上 → B3「追加情報が必要」。
3. unmetもunknownも0件 → B1「基本項目が確認できた」。
各条件の明示的な理由を生成する。B1/B2/B3は**作業状況の分類であり適合度の順ではない**。

## 6. 地域・施設の扱い
- Region（行政統計地区）／SurveyArea（調査範囲）／SearchCircle（概略ピンからの直線距離円）は別。名称一致だけで結合しない。
- 施設：500mと1kmの直線距離。座標が検証された対象だけに適用。coverage不明→not_collectedであり、施設なしとは表示しない。
- needs：real_descriptive / real_reference / not_surveyed / demo_synthetic（および観測0件の特記事項）。対象・質問・母数・時期・募集方法を根拠とともに保持。地区全体の需要や利用者数を推計しない。
- アンケートQ4→対象用途が分かる場合のみ当該用途の利用障壁として扱う。Q6/Q7はQ5で選んだ**回答対象の1用途**と結合。Q8の自由記述は個人情報除去・人間による分類確認まで用途別ルールに使用しない。

## 7. 「次に確かめること」の分岐
最大3個の質問を優先表示。以下の優先順で重複を除去：
1. 建物の基本条件で「ない／不明」→その項目を確認する。
2. 用途と結び付いた運営人材不足の有効な根拠→担い手・協力団体・継続可能性。
3. 用途と結び付いた既存施設の利用障壁→時間・距離・費用・手続き等の具体的確認。
4. 用途への希望があるが利用意向不明→頻度・利用条件を確認。
5. 利用意向はあるが利用条件不明→対象者や時間帯・頻度を確認。
6. 根拠なし・未調査→用途固有の標準質問。
同優先度はruleId固定順。専門家への確認事項は別領域で常時表示し、3件制限の対象外。
**sourceRefs、ruleId、ruleVersion、questionId、surveyId、データの版**を保持して、根拠を説明できるようにする。
実調査・架空・参考・未調査を区別し、架空情報を実際の住民の声として扱わない。

## 8. テスト例（すべて架空・実行前）
- 部屋3、台所/トイレ/浴室/電気あり、通信不明、希望住宅：housing=A1/B1、work=A2/B3、ほかA2/B1。
- 部屋2、台所なし、トイレ/電気あり、浴室不明、通信なし、希望地域交流：community=A1/B1、meal=A2/B2、housing=A2/B2＋浴室不明、work=A2/B2、study/shop=A2/B1。
- 部屋1、台所不明、トイレ/電気/通信あり、浴室なし、希望店舗：shop=A1/B1、meal=A2/B3、housing=A2/B2＋台所不明、その他A2/B1。shopでも飲食営業可能とは表示しない。
- 全設備不明、希望未定：6用途A3/B3。所有者が店舗を除外すればshop=A4。
- Q4が用途不明：用途別の利用障壁による質問切替をしない。
- Q8の「担い手不足」が未レビュー：事実として扱わない。
詳細は [VALIDATION_SCENARIOS.md](VALIDATION_SCENARIOS.md)。

## 出力に追加する「具体的な行動」の規則（2026-11-12）
- 現行の質問ルール・A/B分類は変更しない。質問結果の表示属性として firstActionText（最初に取れる行動）・actionMethod（確認方法や相手の種類）・actionCaveat（注意・未確認）を用意する設計。
- absent（なし）とunknown（不明）の行動例は分ける。前者は整備・代替手段の相談、後者は現状確認。
- 地域が未調査でも全6用途に一般的な確認行動を用意。データ由来の場合は根拠の種類・版を保持し、実在する団体や相談先の協力を保証しない。
- 詳細は[NEXT_ACTION_VALUE_DECISION.md](NEXT_ACTION_VALUE_DECISION.md)。
