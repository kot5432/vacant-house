# 活動条件・場所タイプ・次の行動のルール v2.0
更新：2026-11-12／**設計のみ、判定コードは未作成**。旧所有者向けA1〜A4/B1〜B3分類は**現行MVPでは廃止**。履歴はPROJECT_CONCEPT.md第32章などに保存。

## 1. 最重要原則
- これは会場の**空き状況や実際の適合性**を判定するシステムではなく、活動条件に対応する検討事項の整理。
- 3つの**場所タイプ**（existing_public、vacant_house、other_venue）を同列に提示。客観的な適合点・推奨順位を付けない。
- **既存施設で実施できるなら、空き家を使う必要はない**。空き家を無理に促さない。
- 同じ入力、ルール版、公開データ版なら同じ確認事項・行動文を返す定型処理。AIの自由生成・架空施設の創作なし。
- 地域アンケートの実/参考/未調査/架空を区別し、施設の存在と実際の利用可否を分離。

## 2. 入力の定義
activityId：community / study / meal / work / shop / other （1つ、必須）。
participantCount：正の整数またはunknown。0・負値・小数・数値変換失敗は入力エラー（人数未定はunknown）。
recurrence：one_off / recurring / unknown。
desiredTime：daytime / after_school / evening / weekend / unknown（複数選択可能、unknownは他と併用しない）。
equipment：調理設備 / 電源 / 通信 / トイレ / 机椅子 等の複数選択。不明を許容。
operatorStatus：ready / looking / unknown。
regionId：高岡市地区の手動選択/unknown。地区境界の自動判定なし。
budget：任意・不明。初期の処理では費用から会場を自動除外しない。
optionalDescription：任意。LLMによる内容解析はせず、必須の判断ルールに影響させない。
実在個人名、精密住所、緯度経度、自動GPSを入力しない。

## 3. 3場所タイプの定型確認
| 場所タイプ | 常に確認すること | 最初の一歩 |
| --- | --- | --- |
| existing_public | 利用対象・活動内容、空き時間、人数・設備・予約手順 | 希望地区の施設利用条件を公式情報で調べる |
| vacant_house | 所有者の利用意思、実際の建物状況、整備費、契約、利用上の安全・法令 | 活動に必要な設備と使用条件をリストにし、所有者の同意や建物確認が必要と把握する |
| other_venue | 会場利用条件、料金、設備、時間、契約・予約 | 既存団体の拠点や民間貸会場の条件を調べる |

**空き家は物件検索ができない段階で、特定の候補として紹介しない。** 施設リンクは公的なURLと利用条件の更新日を確認済みのものだけ追加する。

## 4. 活動ごとの必須注意（会場ごとに消さない）
| 活動 | 追加確認 |
| --- | --- |
| community | 運営主体、参加人数・時間帯、騒音や安全への配慮 |
| study | 子どもの見守り責任者、対象人数・時間、活動安全 |
| meal | 食品の提供方法、衛生・保健所等の相談、安全・継続スタッフ |
| work | 利用者・通信、利用規約、費用や運営の継続性 |
| shop | 営業形態・提供内容、必要な届出・許認可、建物用途・費用 |
| other | 活動内容に固有の法令・安全・運営上の要件は未判断。専門窓口に確認 |

## 5. 確認事項の優先順位（最大3件の行動カード）
1. **活動安全/運営主体の不足や未定**：子ども関連、食事提供、事業等では必要な専門相談の案内を常時別枠に出す。行動カードでは運営主体/活動条件の明確化を優先。
2. **活動条件が未定**：参加人数、頻度、時間帯、必要設備を具体化。
3. **場所タイプの重要な条件**：既存施設の利用規則、空き家所有者の承諾、民間会場の契約など。
4. **確認済みの地域の障壁**：営業時間が合わない等、活動種類と地区に紐づく有効な根拠がある場合にのみ分岐。
5. **一般的な次の一歩**：調査・地域データがない場合は定型の確認方法を表示。
同優先度はruleId固定順。重複を除き3件を優先表示。**専門家・安全・運営上の注意は別枠で残す**。隠れた確認事項は「ほかに確認すること」で閲覧可能。

## 6. 各行動結果の論理データ
activityId、venueType、ruleVersion、ruleId、questionText（確認事項）、firstActionText（最初の行動）、actionMethod（確認方法/相手の種類）、reasonText、evidenceRefs[]、sourceStatus（verified/reference/not_surveyed/demo）、caveats[]。
活動内容の自由記述があっても、未検証の推測から法令や設備を断定しない。

## 7. 施設・地域情報の判定
Region（行政地区）とSurveyArea（調査範囲）は別。地区が未選択の場合は地域根拠を無理に結び付けない。公開施設は、データの収録範囲・出典・座標・利用案内の更新日を明記。建物・施設の存在だけで活動可能と判定しない。
調査回答があっても、地域全体の需要量・施設の不足・学生団体の協力意思を断定しない。架空デモを実調査と見せない。

## 8. 初期の受入ケース（期待値、未実行）
- 学習支援、5人、放課後、責任者未定→「見守り責任者の確認」と「利用時間」の確認、既存施設・空き家・その他を比較。
- 食事交流、調理要、人数未定→運営主体・調理/衛生の確認。空き家が実際に調理できるとは表示しない。
- イベント、土日、20人→既存施設の土日使用条件や人数上限を確認。空き家を推薦1位にしない。
- 店舗、販売内容のみ→営業形態、運営者、届出・必要設備を確認。開業可能とは出さない。
- その他、全条件未定→3場所タイプの一般的な確認事項は出す。特定施設の推薦や用途の推測なし。
