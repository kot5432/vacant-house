作成：2026-11-12。**まだIssue・ブランチ・コード・デプロイは作成していない。** 役割は仮。正式なチーム人数・稼働時間は未確定。作業の見積もり時間は確約しない。

## 運用方針
- 3人を基本：A UI/アクセシビリティ、B 診断とテスト、C データ・調査/出典。4～5人なら品質/発表を補強。
- 一つのIssueに**目的・対象画面/型・受入条件・テスト・非対象**を記す。
- GitHub feature branch → PR → 少なくとも別担当1名のレビュー → main。AI生成コードは人間が確認し、入力/出力契約と結果を検証。
- チーム全員のVercel Hobby自動デプロイを前提にしない。必要ならCloudflare Pagesへ。
- コンテスト応募は最大5人、実際に動く作品が必要。提出直前に公式要項の最新条件を確認。

## ゲートと縮小ルール
- **Gate 1**：6用途の建物基本確認と希望分類が動く。
- **Gate 2**：UIから入力→6用途→詳細→比較→修正を完了できる。
- **Gate 3**：未調査でも用途別の質問・専門家確認が出る。
- **Gate 4**：実データがある場合だけ、確認済み情報を追加。
- **Gate 5**：テスト・プライバシー・利用条件・公開・紹介動画を確認。
期限が厳しいときはアニメーション・追加データ・地図から削る。**基本分類・説明・安全なデータ扱い・動作する作品は削らない**。
