# 画面・操作仕様 v1.0（ワイヤーフレーム相当・設計のみ）
2026-11-12。**画面の実装やデザイン画像は未作成**。画面を作る人が迷わないように、必須要素・操作・異常状態・言葉を定義する。

## 共通原則
- 主操作は各画面に原則1つ。状態は色だけに依存せず文字で示す。
- 説明可能でない「おすすめ順位」「適合率」「地域に必ず必要」「許可済み」「営業可能」は使わない。
- 一覧→詳細→比較の間は入力を保持。保存やログインを要求しない。
- 不明設備、地区未選択、ピンなし、地図データエラーでも**建物だけの判定は継続**。
- 架空データの表示はアプリ全体と地域の根拠の近くの両方に出す。
- 画面幅320px程度、文字拡大、キーボード、見出し、入力ラベル、エラー説明を想定。詳細UIは実装後に実機確認する。

## U01 Home
- 見出し：「この空き家、どんな活用が考えられる？」
- 説明：「建物の情報と所有者の希望をもとに6用途を整理します。地域情報がある場合は、次に確かめることも提案します。」
- 主操作：「活用候補を調べる」
- 副操作：「架空の例で試す」
- 注意：「建物の安全性や法令上の利用可否、収益性を判定するものではありません。」
- 状態：デモ時は以降の全画面に架空ラベル。

## U02 建物フォーム：ステップ1/3（地区と基本）
- 進捗：1/3。地区は「博労／川原／戸出／そのほか／分からない／選ばない」。正確な場所を求めない。
- 入力：部屋数（数値または不明）、面積・階数（任意/不明）、概略ピン（任意）。
- 注：「地図の位置は概略で構いません。位置情報はサーバー保存しません」ただし外部地図リクエストについては公開時に説明。
- 操作：「次へ」「戻る」。不正な部屋数のときは欄の下に理由を出す。無効な入力は診断開始できない。
- 地区自動推定なし。選択なしで進める。

## U03 建物フォーム：ステップ2/3（設備・状態）
- キッチン、トイレ、浴室、電気、通信環境：各「あり／なし／分からない」。未回答は「分からない」。
- そのほか：段差、駐車、建物状態は任意・不明可。**安全性診断に使ったように表示しない**。
- 文言：「設備の有無が分からなくても進められます」。
- 操作：「戻る」「次へ」。戻っても選択は消えない。

## U04 建物フォーム：ステップ3/3（希望）
- 簡易方向：「住まいとして」「地域の居場所」「事業・仕事」「まだ決めていない」（複数方向可、未定は他と同時選択しない）。
- 詳細で6用途の希望選択・避けたい用途の選択。**方向だけ**なら住まい→housing、地域→community/study/meal、事業→work/shop。**詳細選択を明示確定したら詳細が優先**。
- 希望と除外の同時指定は理由付きで警告。未修正で計算する際は除外が優先。希望なしは全用途A3。
- 入力確認画面では実物件の正確な住所を尋ねない。
- 主操作：「候補を確認する」。戻る操作あり。

## U05 Results（結果一覧）
- 見出し：「この空き家の活用候補」
- サブ：「入力された基本項目を整理した結果です。建物の安全性・用途の実現性・許認可は判定していません。」
- 希望用途を先に表示。希望外は「ほかの可能性（X件）」として折りたたむ。希望なしなら全6用途。除外用途は「除外した用途を表示」で明示展開する。
- **用途カード**：用途名、希望区分、設備の状態（基本項目確認／設備の見直し／追加情報が必要）、不足・不明の項目、地域情報（未調査/架空/調査あり）、操作「詳しく見る」。
- 用途カードをB1/B2/B3や地域回答数で**自動ランキングしない**。
- 操作：「入力を修正する」「2つの用途を比較する」。フィルタや高度なグラフはMVPで不要。
- 例外：全入力不明でも表示するが「多くの情報が不明です」を明記。地域データや地図の読込失敗では結果を隠さない。

## U06 用途詳細・地域との接点
1. 用途名・所有者希望区分・設備確認状態。
2. 基本条件：一致、なし、不明の項目を分けて表示。建物の利用許可を保証しない。
3. **地域との接点**：調査の種類、対象地区、質問、母数、時期、調査方法、限界。未調査なら「地域ニーズはまだ調査していません」。架空なら必ずラベルを表示。
4. 周辺施設：出典、収録年、直線距離500m/1km圏（存在する場合）。施設データ未収録・圏内0件・取得エラーを区別。ピンなしなら「周辺施設は未検索」。
5. **次に確かめること（最大3件）**とそれぞれの「この質問を表示した理由」。一般的な確認か、実/架空の匿名調査が根拠かを示す。
6. **専門家への確認事項**は件数制限外。消防、安全、衛生、契約、事業などの誤認防止。
7. 操作：「結果一覧へ」「比較する」「入力を修正する」。
- B1でもshopには「飲食店の場合、調理設備・衛生面・消防・許認可の確認が必要」を必ず表示。
- 近くに学校があっても学習支援の需要を断定しない。

## U07 Compare（2用途比較）
- 選択した2用途を同じ行で比較：所有者の希望、基本項目確認、満たした/ない/不明、地域ニーズの状態、周辺施設の状態、次の質問、専門家確認。
- 「どちらが最適か」は決めない。両者の必要な確認が違うことを見せる。
- 狭幅では縦並びとし、2用途の見出しを繰り返す。
- 操作：「比較を終了」「別の用途を選ぶ」。

## 中心価値を反映した結果画面の追記（2026-11-12）
- U05の用途カードに、利用者が最初に取れる行動を短く1行表示する（例：「既存交流施設の利用条件を調べる」）。ほかの可能性や除外用途を推奨順位へ変更しない。
- U06の「次に確かめること」各件は、**確認事項→最初の行動→確認方法/相手の種類→理由/根拠→注意**の構成とする。最大3件の質問表示制限と専門家確認の別枠は維持。
- U07では**次の一歩の違い**も比較する。根拠のない具体的な協力先や連絡先、許可を断定しない。
- この方針は[NEXT_ACTION_VALUE_DECISION.md](NEXT_ACTION_VALUE_DECISION.md)に記録。
