# 詳細ワイヤーフレーム・操作規約 v1.0
作成：2026-11-12／**設計のみ。画像・アプリ・画面コードは作っていない**。
この文書は [画面・操作仕様](UI_SPEC.md) の詳細。ボックスの位置・操作・文言の概念設計であり、ピクセル・配色の最終値や実機での評価ではない。

## 共通レイアウト
PC（目安960px以上）：ページ中央に読みやすい最大幅、グローバルヘッダーはブランドと「このアプリについて」。入力画面は本文1カラム。結果画面は候補カード2カラムまで。詳細と比較は情報量が多いため1カラム主体。
スマホ（320〜959px）：1カラム、本文の横スクロールを避ける。入力フォームは縦配置。結果・比較では縦並び、見出しを繰り返し迷わないようにする。**ブレークポイントは実装後に表示検証して決定**。
共通ヘッダーの「戻る」はルートと入力値を保持する。主要操作・戻る・折りたたみはキーボードで操作可能、フォーカスが分かる。

## 画面 U01 Home
```text
[サービス名]                                     [このアプリについて]

この空き家、どんな活用が考えられる？
建物の情報と所有者の希望から、6用途の確認状況を整理します。
地域の根拠があれば、次に確かめることも提案します。

[活用候補を調べる]
[架空の例で試す]

どう進める？ ①建物を入力 → ②6用途を比較 → ③次の確認事項を知る
※安全性・法令適合・採算や最適解を判定するサービスではありません。
```
ユーザーが開始を選ぶまで正確住所、GPS、氏名を要求しない。デモ開始の場合は全画面に架空表示を付ける。

## U02 入力1/3「建物の場所と基本情報」
```text
[戻る]    入力 1/3
どのような建物ですか？
地区   [博労/川原/戸出/そのほか/不明/選ばない]
部屋数 [整数入力]  [分からない]
面積・階数 [任意/分からない]
空き家のおおよその位置（任意） [位置を指定しない / 概略ピン]
※地区境界が未検証のため、ピンから地区を自動特定しません。
[次へ]
```
部屋数空欄はunknown。負数・小数・非数値は欄の下にエラーを出し、修正時に解除。0室は欠損ではなくabsentの判定材料。
ピンなしで進める。地図を使う際は外部への地図通信の有無とプライバシー説明を確認。

## U03 入力2/3「設備の情報」
```text
[戻る]    入力 2/3
分かる範囲で選んでください
キッチン [あり/なし/分からない]
トイレ     [あり/なし/分からない]
浴室       [あり/なし/分からない]
電気       [あり/なし/分からない]
通信環境 [あり/なし/分からない]
その他（任意） [段差/駐車/建物状態]
[次へ]
```
未選択はunknown、勝手にabsentへ変換しない。端末のリロード時に保存されると誤解させず、リロードで内容が消える可能性を別途説明する。

## U04 入力3/3「どう活用したいですか？」
```text
[戻る]     入力 3/3
希望に近いものを選んでください（複数可）
[住まい] [地域の居場所] [事業・仕事] [まだ決めていない]
具体的に考えている用途（任意）
[住宅] [地域交流] [学習支援] [地域食堂] [仕事場] [店舗]
避けたい用途（任意）[6用途から選ぶ]
（希望と除外が重複したら警告。除外を優先）
[入力内容を確認]  →  [活用候補を確認する]
```
「未定」と具体的な希望が同時選択なら入力画面で確認を促す。「地域の居場所」は既定でcommunity/study/meal、「事業・仕事」はwork/shop、明示的な詳細選択で上書き。確認画面でユーザーに「希望として扱う用途」を一覧で見せる。

## U05 Results「この空き家の活用候補」
```text
この空き家の活用候補
※入力した基本項目の確認結果です。適法・安全・収益を判定していません。
建物条件の要約  [入力を修正する]
所有者が希望した用途
[用途カード] [用途カード]
...（希望の数だけ、同じグループ内は固定順）
[ほかの可能性（N件）を表示]
[除外した用途（N件）を表示]
[2用途を比較する]
```
各カード：用途名・希望との関係・「基本項目確認/設備見直し/追加情報」・不足/不明・地域情報状態・「詳しく見る」。
6用途は必ずアクセス可能。希望していない用途を根拠なく劣位扱いせず、**表示グループだけ**区別。希望が未定なら全6用途を最初から表示。

## U06 用途詳細
```text
[結果一覧へ]
地域交流スペース      [所有者希望に合う] [基本項目を確認]
建物の基本情報     ✓部屋数 ✓トイレ ✓電気
※実際に利用できるかは未判定
地域との接点
 [地域の声: 未調査/参考/実調査/架空]
 [地区・調査の範囲・母数・質問・期間・出典・限界]
 [周辺施設: 未検索/データ未収録/収録済0件/収録済あり/エラー]
次に確かめること（最大3件）
 ① 確認質問 [なぜこの質問？ → 一般テンプレ/出典]
 ② 確認質問 [なぜこの質問？]
 ③ 確認質問 [なぜこの質問？]
専門家への確認（質問の3件とは別）
[2用途を比較する] [入力を修正する]
```
架空であれば上部にも「架空のデモ」の表示。どの地区・どの回答が根拠か分からないなら用途固有の「地域の声」として表示しない。B1でも店舗/食堂の衛生・消防等の確認欄は残す。

## U07 Compare「2つの候補を見比べる」
```text
[結果一覧へ]
比較する2用途 [用途1] [用途2]
希望との関係   ...        ...
基本項目       ...        ...
不足・不明     ...        ...
地域の根拠     ...        ...
周辺施設       ...        ...
次の確認事項   ...        ...
専門家確認     ...        ...
[別の用途を選ぶ]
```
PC：左右の内容を比較（長文の高さ差や見出しの対応を確認）。スマホ：用途1と用途2を同じ項目ごとに縦配置。1件選択の間は「比較する用途をもう1つ選ぶ」と促す。**同じ用途を2つ選べない**。除外用途を比較に加える場合は明示的なユーザー操作が必要。

## 状態・文言の受入条件
- **設備がすべて不明**：結果は表示、6用途はB3。「入力が不足しているため、確認項目が多くなっています」。
- **地区なし**：建物分類は表示、地域ニーズ「未調査／地域未選択」を適切に分離。
- **施設なし vs 未収録**：データ収録が確かで検索して0件のときだけ0件。取得失敗や未収録は0件としない。
- **調査参考程度**：母数、調査範囲、募集の偏りを記載。地区全体の需要と書かない。
- **架空デモ**：全画面と各調査カードに明記。実在の施設データと組み合わせる場合でも架空調査は混同しない。
- **詳細で戻る**：入力値・結果・比較中の選択の扱いが一貫し、本人の再入力を不必要に求めない。
- **アクセシビリティ**：320px横はみ出し無し、200%文字拡大・キーボードのみ操作・エラーテキスト、音声読み上げは実装後検証。設計段階では「確認予定」であって「成功」ではない。

## 最終品質ゲート
1. 実装担当がこの文章仕様から主要要素を配置できる。
2. 特殊状態でも主操作・戻る・入力保持・理由説明が通る。
3. 「地域と合う」や「最適」等の定量評価と受け取られる文言を避ける。
4. UIの外観についての最終ピクセル設計・利用者評価は**残る検証事項**。
